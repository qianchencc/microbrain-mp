# 01: 复杂 Company 请求生成可确认计划

**What to build:** 用户提出跨楼层、跨区域、照明与空调混合的夜间收口请求后，Agent 能在不发送控制请求的情况下，解析并核验包含范围和排除范围，读取一次当前状态，并通过现有确认卡展示一份稳定的多阶段计划。

**Blocked by:** None (can start immediately)

**Status:** implemented; real-gateway / native acceptance pending

- [x] Pi 输出结构化批量操作请求，包含范围表达、排除表达和时间；固定设备类型、关机动作及阶段顺序由具名业务入口定义，不逐台生成动作。
- [x] 服务端一次展开当前 Company 授权目录中的真实成员，并阻断范围或排除无法完整核验的计划。
- [x] 计划显示包含范围、排除范围、阶段、设备数量、已满足、不可读和仍需下发摘要。
- [x] 预检和计划生成期间控制请求数为零。
- [x] 计划保存可供确认使用的范围和阶段快照；模型后续回复不能改写成员和数量。
- [x] 使用现有确认卡和已有 Agent 流程完成从用户请求到待确认计划的外部闭环。
- [x] 覆盖跨两层、多区域、照明/空调混合和真实排除项的复杂验收输入。

实施与证据见 [首条提案闭环交接](../../../plan/2026-10-19-company-batch-plan-handoff.md)。当前证据为公开 HTTP 协议夹具、真实模型配合夹具、实际 Vue 组件浏览器走查及微信编译；未部署新 Runtime、未确认真实任务，不宣称真实网关/真机验收完成。
