# 05: 跨楼层多期间用电差异调查与依据追问

**What to build:** 用户比较公司已接入范围的四个完整周后，能继续定位相邻两周差额贡献最大的楼层、位置和电表，查看采样依据；系统按真实覆盖解释结果，不虚构原因。

**Spec:** ../followup-spec.md

**Blocked by:** 04 的协调设计决议、只读路径与版本基线结论；不依赖 04 的现场控制或照明权威回读完成，也不依赖 06。

**Status:** ready-for-agent（阻塞边满足后实施）

- [ ] 先明确统计、对比、调查下钻及原事实解释的职责与用户流程；决定现有工具、结果引用和重复准备路径如何保留/合并/替换。不给每种问题增加专用工具，不把调查固定为必经的单一路径。
- [ ] 固定 Company 当前授权计量集合和四周请求边界；对比可比集合由服务器解析，Pi 不枚举或自行加减全量电表。
- [ ] “最近”按当前上海时间解释，缺近期数据明确给出最新采样；用户选定历史窗口后再分析，不静默退到历史样本或模拟数据。
- [ ] 同一批表多期比较、时间对比及楼层构成分别保留窗口和口径；范围与时间同时变化有实质歧义时先澄清。
- [ ] 复用现有统计/对比与贡献计算；共同有效表、缺失/回退、不等长日均、基期零和全空/单侧有效状态符合现行领域口径。
- [ ] 用户可追问“第一项”“前面排除的表”“只看那一层”；引用带明确窗口和成员，重新校验当前授权；实质改变范围/时间生成新的查询结果。
- [ ] 已有统计事实在解读失败后仍可恢复；解释原卡不重新统计，新对比不改写旧卡。查看重点电表可定位真实起止读数及采样边界。
- [ ] 首个统计结果冻结成员 ID、来源元数据、位置归类依据与读取时刻；多期比较按当次查询的目录位置分组描述，不主张历史物理放置（有历史证据除外）。“第一项/前一名”指原保存结果的排序与成员在当前授权重核后的对象，不按当前改名目录重新计算。仅名称变化不把电表移出已知楼层；真实 areaName/位置变动影响新查询归类，不回写旧排名。
- [ ] 至少覆盖跨两层多表四周成功下钻、表集合不一致、缺边界、基期零、近期无数据、错字/歧义、跨轮选择与撤权等复杂路径；比较数字和排名来自服务器。
- [ ] 位置语义用例：`农旅办公室电表`（areaName=26楼农旅办公室）归入 26 楼；仅 iot-center 侧改名时能耗元数据与归类不变；上游 areaName 真实迁址后新查询产生新分组且原卡不变；位置未知或仅兜底数据时不断言当前位置；不做跨来源模糊 ID 关联。
- [ ] 原小程序现有统计/对比卡及依据抽屉完成阅读、下钻和返回；不新增调查页面、报告产物或收件箱。
- [ ] 真实模型与真实网关只读验证分开留证，保存耗时/查询数；2024 保存样本与后续模拟补数分别标注，不宣称节能成效或设备故障。
- [ ] 交接设计取舍、实际替换和剩余限制；同时证明 Pi 可依据不同贡献结果改变调查方向，且统计数字、集合与证据始终可追溯。

## 范围与成本

复用已核验的统计算法和成熟卡片，按目标业务流程决定协调层是否重写。预计生产新增约 150–300 行，测试数据另计；不预建调查持久化对象。若需要的新协调代码显著超出预算，先重新检查是否可以由更小的业务接口承载完整行为，预算不代替设计判断。

允许 Pi 根据贡献事实选择下一步调查，数值、集合和排名始终由服务端计算。本票只读，不创建周期委托、自动控制或因果结论。
