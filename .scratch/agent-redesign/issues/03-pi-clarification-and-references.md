# 03: Pi 结构化澄清与跨轮引用收口

**What to build:** 当范围、排除项或用户指代不完整时，Agent 能返回最小必要澄清；用户补充后，Pi 基于服务器返回的结构化缺口继续形成同一业务计划，并保持范围、草案和任务引用一致，不重复搜索或扩大用户未确认的范围。

**Blocked by:** 01: 复杂 Company 请求生成可确认计划

**Status:** ready-for-agent

- [ ] 无法解析的地点、排除项或设备类型以结构化缺口返回给 Pi，用户可用自然语言补充。
- [ ] Pi 的补充请求只携带当前来源、授权上下文和仍有效的结构化引用；对话历史不能单独恢复范围或执行事实。
- [ ] 用户补充后只修正明确缺口，不因换地点词或重复提问逐步拼接未确认设备范围。
- [ ] 用户引用“刚才的范围”“排除的会议室”“这个任务”等表达时，只能解析到当前授权且仍有效的结构化对象。
- [ ] 服务器校验错误可以返回可解释的修正信息，但不会触发无边界的重复检索。
- [ ] 澄清完成后仍进入现有确认卡，不新增独立的澄清面板或新的 UI 组件体系。
- [ ] 覆盖多候选地点、未解析排除、补充后成功、引用失效和授权变化等复杂多轮验收输入。
