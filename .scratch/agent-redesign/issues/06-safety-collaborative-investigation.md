# 06: 多类型告警协同排查与选定监控查证

**What to build:** 用户指定一个告警窗口后，得到按设备整理的燃气/烟感/水浸核查清单，能选择具体记录、核对当前位置并打开选定摄像头直播或回放；未确认恢复的事实保持未知。

**Spec:** ../followup-spec.md

**Blocked by:** 04 的只读协调路径与版本基线结论；不依赖照明现场控制，不依赖 05。顺序安排在 05 后，避免并行改动同一协调模块。

**Status:** ready-for-agent（阻塞边满足后实施）

- [ ] 当前 Company 目录限制三类台账，服务端按指定窗口分页、稳定记录键去重、按设备聚合次数与最近时间；读取未完成不宣称全量排名。
- [ ] 空记录、无权限、读取失败和部分覆盖分别收口；单类失败保留其它已取得事实并指出缺口，不伪造完整公司结论。
- [ ] 排查清单保留记录引用、历史名称、当前核验资料和读取时间；当前位置失败不沿用旧地点参与监控匹配。
- [ ] 根据明确的记录时间、重复次数和缺失事实说明核查顺序；缺少风险规则不宣称事故等级或已恢复。
- [ ] 支持“看反复出现最多的那个”“看它当时附近的监控”等多轮请求；以稳定事件/设备引用重新核验，历史地点未核验时明确说明当前匹配依据。
- [ ] 多摄像头先询问，选择后只生成对应一张观看卡并保留事件关联；范围外候选拒绝，零候选不扩大来源。
- [ ] 复用现有列表、详情、观看卡和播放器导航；回放窗口、实际录像可用性及直播当前画面分别表达，不声称视频理解。
- [ ] 覆盖三类多页重复、设备搬迁、资料失败、无恢复证据、多摄像头选择、跨轮引用与撤权；实际模型和客户网关只读验收及小程序点击分开记录。
- [ ] 汇总接口/模型耗时与调用数，避免逐条重复拉全台账；最终建议只基于已保存证据，不标记处置、不控制设备、不发外部通知。

## 范围与成本

复用现有台账分页与单事件监控联查，先查清聚合/多轮引用的实际缺口。预计生产新增约 150–300 行，夹具另计；不新建告警处置平台、通用调查引擎或另一套事件日志。

本票只输出核查清单与只读查证入口。接口 503 时保留明确失败及已有证据，不能以协议夹具结果替代真实台账验收。
