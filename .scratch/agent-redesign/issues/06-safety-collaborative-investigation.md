# 06: 多类型告警协同排查与选定监控查证

**What to build:** 用户指定一个告警窗口后，得到按设备整理的燃气/烟感/水浸核查清单，能选择具体记录、核对当前位置并打开选定摄像头直播或回放；未确认恢复的事实保持未知。

**Spec:** ../followup-spec.md

**Blocked by:** 04 的协调设计决议、只读路径与版本基线结论；不依赖照明现场控制，不依赖 05。顺序安排在 05 后，避免并行改动同一协调模块。

**Status:** ready-for-agent（阻塞边满足后实施）

- [ ] 先消化[工具体系设计盘点](../../../docs/research/2026-10-20-agent-tool-system-design-audit.md)，实施前记录本域接口/生命周期/旧入口取舍：服务端完整聚合、当前元数据与选择引用如何表达、可选调查证据与必经准备的分界；不固定为单一路径脚本。
- [ ] 先设计记录、设备级聚合、当前资料、建议、监控候选及用户选择之间的关系；明确各结果归属、引用有效性和继续/结束流程，决定旧查询与联查接口的保留/合并/替换，不只串接现有按钮。
- [ ] 当前 Company 目录限制三类台账，服务端按指定窗口分页、稳定记录键去重、按设备聚合次数与最近时间；读取未完成不宣称全量排名。
- [ ] 空记录、无权限、读取失败和部分覆盖分别收口；单类失败保留其它已取得事实并指出缺口，不伪造完整公司结论。
- [ ] 排查清单保留记录引用、历史名称、当前核验资料和读取时间；当前位置失败不沿用旧地点参与监控匹配。事件保存的名称/位置/时间与当前核验设备元数据及读取时刻分别保存，当前摄像头匹配不证明事发时同址。
- [ ] 根据明确的记录时间、重复次数和缺失事实说明核查顺序；缺少风险规则不宣称事故等级或已恢复。
- [ ] 支持“看反复出现最多的那个”“看它当时附近的监控”等多轮请求；以稳定事件/设备引用重新核验，历史地点未核验时明确说明当前匹配依据。
- [ ] 多摄像头先询问，选择后只生成对应一张观看卡并保留事件关联；范围外候选拒绝，零候选不扩大来源。
- [ ] 复用现有列表、详情、观看卡和播放器导航；回放窗口、实际录像可用性及直播当前画面分别表达，不声称视频理解。
- [ ] 覆盖三类多页重复、设备搬迁、资料失败、无恢复证据、多摄像头选择、跨轮引用与撤权；实际模型和客户网关只读验收及小程序点击分开记录。
- [ ] 位置语义用例：名称无楼层的摄像头按区域树路径归属；自身写明 27 楼的设备不被粗粒度 26 楼树节点误配到 26 楼；自身字段冲突或元数据读取失败时不以历史名称充当当前位置；事件后搬迁的设备标注当前配对为“当前”，不改写旧事件/录像证据；改名后历史证据不变；只有当前授权且用户选定的摄像头生成观看卡；恢复未知保持未知。
- [ ] 汇总接口/模型耗时与调用数，避免逐条重复拉全台账；最终建议只基于已保存证据，不标记处置、不控制设备、不发外部通知。
- [ ] 交接结构设计与替换取舍，验证用户可更换记录、调整时间窗或从监控返回排查；新查询和原事实查阅各有清晰语义，不能只让固定演示路径走通。

## 范围与成本

复用台账读取和已核验的监控能力，允许按核查业务重新设计协调接口与结果投影。预计生产新增约 150–300 行，夹具另计；不新建告警处置平台、通用调查引擎或另一套事件日志，预算不替代必要的设计取舍。

本票只输出核查清单与只读查证入口。接口 503 时保留明确失败及已有证据，不能以协议夹具结果替代真实台账验收。
