# 02: 确认后执行两阶段收口并形成结果

**What to build:** 用户确认复杂 Company 夜间收口计划后，系统按固定快照创建一个多阶段 Task，依次执行照明和空调目标，按安全并发策略下发并进行新鲜回读，在现有 Task 详情和报告路径中呈现每阶段的真实结果。

**Blocked by:** 01: 复杂 Company 请求生成可确认计划

**Status:** implemented-pending-gateway-acceptance

- [x] 确认只接受仍有效的计划快照，快照失效、授权失效或能力变化时不下发新动作。
- [x] 同一 Task 保存照明和空调两个阶段，各阶段拥有独立设备执行快照。
- [x] 同控制器串行，不同控制器最多三组并发；执行中不自动重试，也不重复发送未知结果。
- [x] 一个阶段的局部失败不会自动取消独立的后续阶段；授权、服务或快照失效时停止认领排队动作，在途动作继续收口。
- [ ] 下发后按同一批次进行权威回读，分别记录已满足、已受理、已核验、拒绝、回读失败和未知。
- [x] 所有阶段进入终态后 Task 收口；只有全部目标已满足或已核验才显示成功，其余结果保留为部分、失败或未知。
- [x] 现有 Task 详情、阶段结果和报告入口可以查看按阶段、区域和设备整理的结果。
- [ ] 记录 Pi、范围、预检、下发、回读和报告阶段耗时，证明效率提升没有牺牲回读和结果真实性。
