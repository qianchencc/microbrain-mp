# 03: 普通提案多步修正后仍能生成正确卡片

**What to build:** 智能体先后遇到不同字段问题时继续修正，最终生成符合原目标的任务或即时草案；不再把任意两次提案失败直接当成本轮结束。

**Blocked by:** 02 — 工具恢复与重复调用判据。

**Status:** ready-for-agent

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md)。覆盖普通任务、即时混合草案及照明草案入口；专用收口/分阶段由 04 承担。复用 02 的预算与无进展判据，不再并建提案专属循环系统。

## 实现约束

- 工具返回模型可修正字段、约束和已有事实，不把所有校验压成“原因未确认”。内部错误仍脱敏。
- 两次不同问题的实际修正不自动截断；完全相同确定性失败且无进展、不可恢复分类或预算耗尽才终止。
- 提案成功仍依据服务端事实收口；模型修正期间的过程文字不声称已经有卡或已执行。保留原请求全部设备、排除项和参数，不用部分提案逃避失败。

## 验收

- [ ] A05：真实模型依次收到两个不同问题并修正，最终出正确待确认卡；没有强制要求第三条用户消息。
- [ ] 相同错误持续重复会有界结束，最终明确未建提案/未执行，不虚构稍后发卡。
- [ ] 缺参、非法枚举、未知引用分别返回足够安全信息；不会暴露凭据/内部堆栈。
- [ ] 即时混合目标与排除项保持完整，确认前零控制；恢复后读取与直播卡片一致。
- [ ] 保存真实模型的原请求、每次错误/修正及最终卡片，增加至少一个名称/顺序变体验证未写原句特例。

## 验证与交付

沿公开对话测试及既有混合草案/最终答复用例验证；更新旧“两次失败必须终止”的行为预期时仍保留预算耗尽和诚实收尾反例。前端使用既有卡片，必要视觉修正随票交付。
