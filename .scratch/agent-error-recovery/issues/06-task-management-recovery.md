# 06: 任务修改取消和周期启停失败后核实原意图

**What to build:** 用户在对话卡片或任务详情执行修改、取消本次/全部、暂停/恢复时遇到冲突或回包丢失，系统自行核实并继续合法处理，不要求用户猜作用域或反复点击。

**Blocked by:** 01 — 卡片操作的同会话恢复与操作关联。

**Status:** ready-for-agent

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md)。覆盖已有管理提案确认、直接取消、周期状态操作，以及相关查看/结果入口；不重做任务编辑器，不增加权限角色。非对话页的管理失败通过原任务引用承接，不捏造新的用户指令。

## 实现约束

- 沿 01 读取原操作状态。已成功变更回放原结果；版本改变先读差异，保持原本次/全部/未来作用域，实质变化重新确认。
- 并发用户修改不被恢复覆盖；已执行/在途阶段及历史报告不回滚。暂停只影响未来，恢复沿最新窗口规则而不补过去安排。
- 撤权终止相关操作并清旧敏感状态；页面返回、重开及列表/详情一致，不仅更新 toast。

## 验收

- [ ] A08：修改确认丢回包后读回同一变更；冲突后按最新事实重建必要确认，无重复或覆盖并发修改。
- [ ] 取消本次、取消全部分别验证：作用域不串，已执行/执行中不回滚，结果重开仍一致。
- [ ] 暂停及恢复的首次读取失败/丢回包能恢复；恢复仍需现有确认且不补过去点。
- [ ] A11：身份/source 切换、非创建者和撤权不能借恢复获得管理权。
- [ ] 代理在真实前端操作临时只读 Plan 完成修改→暂停→恢复→取消；真实模型承接一次冲突，保留列表、详情与对象证据并清理。

## 验证与交付

沿公开管理接口、卡片和详情操作验证 CAS、状态与效果，不断言内部版本递增实现。真实数据只使用本次创建的临时只读安排，不能修改用户的已有日常计划。
