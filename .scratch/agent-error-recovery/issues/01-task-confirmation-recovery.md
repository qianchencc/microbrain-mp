# 01: 确认创建失败后自动核实并承接原任务

**What to build:** 用户点击创建只读任务/周期计划后，系统处理可恢复失败；回包丢失时找到原结果，提案过期时承接原意图生成必要的新确认，用户无需把报错重新发给智能体。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md) 和 [验收方案](../acceptance.md)。两仓绝对路径与源码导航在执行地图；本票是最小恢复通路，不建立通用编排框架。业务仅限任务/周期计划创建，采用只读测试委托，修改/取消和设备控制交给后续票。

## 实现约束

- 同一次确认保留可核实的操作标识、对象版本与确认内容；确认失败先读权威对象，辨认已成功、未创建、过期/冲突、已有等价计划。
- 服务端基于原主体/source/会话及对象事实启动恢复；重复请求合并，同会话最多一个活动 run。前端异常字符串不作为模型事实或新的用户指令。
- 未产生副作用且目标/时间/成员不变的瞬时失败可安全重试；过期和实质变化生成新待确认卡，时间已过不能静默移动。等价计划返回已有对象，不复制创建。
- 最小恢复关联沿现有持久事件保存，页面重开可恢复；停止、新消息和身份切换作废旧恢复。必要的错误进度与卡片沿现有 UI 展示。

## 验收

- [ ] A01：一次性只读任务确认时首次读取失败后自行恢复，只创建一次，没有额外补救消息。
- [ ] A02：成功但丢回包后，再次触发和页面重开均取得同一 Task/Plan，无新对象。
- [ ] A03：过期可重建；已过时刻请求必要的新决定；等价周期返回已有计划；变化后必须新确认。
- [ ] A11：撤权、跨来源、旧版本、重复并发、停止/新消息都不会造成越权或重复创建。
- [ ] 前端真实点击能看到核实进度及正确结果，失败不立即要求用户复制错误；恢复历史可重新加载。
- [ ] 隔离 staging 用真实模型/网关跑一次“过期提案→重建确认”及一次“确认丢回包→原结果”；保留事件、对象与截图。生产真实创建由 09 汇总闭环。

## 验证与交付

从公开确认/读取/恢复接口验证；沿既有任务创建和对话事件测试，不断言私有状态。需要新增内部 seam 时先确认现有接口无法覆盖。前后端、相关行为测试与编译同批交付；本票证据、commit 与残余生产未验项写入 plan，再推进后续票。
