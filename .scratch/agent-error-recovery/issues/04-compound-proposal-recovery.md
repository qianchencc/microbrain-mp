# 04: 公司复杂收口与分阶段提案失败后继续修正

**What to build:** 公司夜间收口、分阶段控制计划的一次可修正错误不会立即结束规划，智能体能承接同一设备/排除范围与阶段顺序，完成合法待确认方案。

**Blocked by:** 03 — 提案错误反馈与有界修正。

**Status:** implemented-and-verified

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md)。只覆盖当前专用夜间收口及分阶段入口；不更改复杂计划领域模型、全量设备能力、空调窗口排程或确认边界。

## 实现约束

- 区分提案准备中的可恢复异常、真实需要澄清、已有合法提案和不可继续终态；异常不能在 finally 中无条件标记整个规划完成。
- 复用 03 的错误与预算语义；保持服务端固定成员/引用及排除证据，不重搜导致遗漏或扩张。
- 成功卡片由实际阶段事实生成；需要用户决定的位置/时间歧义仍给具体可选项，禁止模型自行猜定。

## 验收

- [ ] A06：夜间收口首次执行校验失败后真实模型修正并出卡，照明/空调顺序和保留区域不变。
- [ ] 分阶段提案对应场景通过，确认前零控制；同一目标不会生成多个并行待确认提案。
- [ ] 确实缺少用户意图时返回必要澄清，持久化后下一轮能承接原范围。
- [ ] 无进展/预算耗尽真实收尾，无未来卡片或后台工作的虚假承诺。
- [ ] 隔离 staging 真实模型/目录跑两类入口，各保留一条修正轨迹和卡片；不确认真实设备动作。
