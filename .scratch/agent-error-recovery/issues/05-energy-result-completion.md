# 05: 能耗准备中自动承接并保留已有成果

**What to build:** 数据准备中时，系统在有限等待内继续取得统计/对比结果；统计已有而解读失败时保留事实和附件，并安全补齐解释或说明剩余缺口。

**Blocked by:** 02 — 只读重试、刷新和预算语义。

**Status:** implemented-awaiting-integration-evidence

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md)。限现有能耗统计、对比与报告交付；不增加跨天聊天后台投递、改变计量口径或重建采样同步服务。

## 实现约束

- preparing/unavailable/真实无采样区分处理。准备状态可在本轮截止时间内查询，未准备好不反复重新启动同步；持续不可用和真实缺数不能当 preparing 无限等待。
- 同一查询范围/时间/口径沿稳定请求关联，已保存报告可重读，不重复生成附件；解读重试不能重算已完成的全部统计。
- 已有事实/采样时刻/覆盖及部分成功始终保留，最终模型解释不能覆盖结构化事实。预算耗尽明确当前成果和缺口，不承诺未实现的自动补发。

## 验收

- [ ] A07：preparing→ready 在本轮恢复后给出真实结果，无需用户重发。
- [ ] preparing 持续到截止时间、无采样、上游不可用三种情况均有准确不同结论。
- [ ] 统计完成后解读失败，事实卡/报告附件可读且不重复创建；重开页面仍一致。
- [ ] 查询参数和计量成员保持一致，缺数不算零，历史模拟补数按当前领域事实标记。
- [ ] 真实模型/网关以有实际采样的期间验证统计及对比；对准备中使用单次受控状态，明确证据环境。前端能打开结果/附件并返回原对话。

## 验证与交付

沿公开查询/报告/对话 API 和现有能耗行为测试进入，不断言缓存内部结构。保存实际数据覆盖、请求关联及最终 UI 证据；不把 H5 或静态图当微信操作验收。
