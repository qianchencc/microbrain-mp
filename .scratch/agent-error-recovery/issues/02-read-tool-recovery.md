# 02: 只读工具瞬时失败后自行取得结果

**What to build:** 用户查询设备、状态或台账时，首次只读请求暂时失败后由系统安全重试，智能体继续原目标；持续失败则在有限预算内给出有依据的结果或原因。

**Blocked by:** None (can start immediately).

**Status:** implemented-awaiting-integration-evidence

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md)。先选一个现有只读查询闭环实现并证明，再把相同语义应用于已有只读工具；不修改控制重试策略，不新增独立重试库。与 01 避免同时修改共享 runner。

## 实现约束

- 按错误性质选择单层有限重试及退避；同参数第一次瞬时失败不计作已经成功的重复调用。
- 只读/副作用类别由代码声明并验证，不能让模型用自报 retryable 绕过。401/403、确定性参数错误不按网络瞬时错误自动重放。
- 保留模型可行动的错误反馈；修正参数、新证据与纯重复分别判断。总回合/调用/截止时间沿现有预算，停止取消等待及后续请求。
- 处理记录关联失败与恢复，主结论基于最终读取；持久历史与直播一致，持续错误不能伪装无设备或空结果。

## 验收

- [ ] A04：同参第一次超时、第二次实际成功，结果正确且运行不因第二次调用被拦截。
- [ ] 持续 5xx/超时有限结束，保留已取得部分、具体失败与下一步；无多层次数相乘。
- [ ] 同一确定性错误无进展会停止；合法的状态刷新/新增证据不会因参数相同被误杀。
- [ ] A11：停止、授权拒绝、来源隔离通过；零设备控制下发。
- [ ] 在隔离 staging 对一个指定只读请求注入单次失败，真实模型/网关随后完成原查询；记录实际调用、错误反馈、事件和 UI。

## 验证与交付

沿公开对话 HTTP/NDJSON 和窄网关协议夹具观察结果、请求数、停止；不直接断言守卫 Map。保存一条真实模型恢复轨迹及持续失败轨迹；文档与语义提交跟本票完成。
