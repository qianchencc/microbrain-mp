# 09: 真实定时报表遇读失败仍交付报告通知并完成生产闭环

**What to build:** 用户实际确认一项未来只读报告任务，到期读取短暂失败时在同一检查点内恢复，最终得到唯一报告和收件箱通知；发布整组修复并由代理完成连续真实业务验收。

**Blocked by:** 01, 02, 03, 04, 05, 06, 07, 08 — 全部用户路径达到各票要求，缺少证据不得视为已完成。

**Status:** ready-for-agent

## 开工与范围

读 [规格](../spec.md)、[执行地图](../execution.md)、[验收方案](../acceptance.md) 全文。此票交付“已确认定时委托→实际到期→报告通知”业务，发布/验收随业务收口，不另建验收设施主线。仅恢复同一检查点的瞬时只读，不补历史漏跑，不重放控制阶段。

## 实现约束

- 如现有 scanner 尚未复用 02 的安全只读恢复，将其接入同一阶段执行截止时间；保持固定成员、统计期间、原创建者身份与一次认领。
- 已完成事实与报告不因解释失败丢失；一阶段仅生成一次产物与结束通知。创建、修改、暂停、恢复之后的真实计划时间沿当前排程语义。
- 只对本票临时只读对象做真实业务操作；staging 复制库的计划/阶段启动前全部隔离。遵循现行生产规范、构建哈希、备份与回滚点。

## 验收

- [ ] A12 staging：真实模型/网关完成新建确认，指定读取一次受控失败后同阶段恢复；一份报告、一条通知，成员/口径固定。
- [ ] 公开行为覆盖持续失败有限收口、撤权、不重认领、不重复报告/通知；保持现行漏跑和阶段独立规则。
- [ ] A12 生产：代理创建未来数分钟实际到期的临时只读 Task，等待实际墙钟执行，从收件箱打开真实报告；不修改库/时钟模拟成功。
- [ ] A13：代理在真实前端连续完成查询→提案→确认→管理→到期报告→通知打开→重开追问，保存两仓版本、实际采样覆盖及全过程关联。
- [ ] A01–A11 必需证据逐项复核，真实模型修正、微信操作、真机及即时控制各按证据等级记录；未验项不以健康检查或测试通过替代。
- [ ] 相关全量测试、类型/构建、MP 微信编译、候选 staging、产物哈希与生产发布验证通过；记录实际版本，不沿用历史测试计数。
- [ ] 临时 Task/Plan、staging、端口、容器、私密副本清理完成；只操作本票创建对象，保留必要业务审计。

## 最终交付

在 plan 写最终交接，逐条链接 A01–A13 的证据、两仓 commits/release/哈希、备份回滚、真实墙钟到期时间、通知/报告关联及清理。任何外部阻碍保留明确未验项与继续方式，代理继续解决可自行处理部分，不能将“请用户验收”作为交付。只有规格要求的业务证据全部具备，才能把本功能整体标记完成。
