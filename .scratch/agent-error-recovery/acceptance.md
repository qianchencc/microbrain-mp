# 真实验收与证据要求

Status: ready-for-agent
执行人：后续实施代理。用户已要求代理自行完成真实业务验收；登录、点击、确认、检查结果、清理测试对象均由代理操作。本文是后续执行要求，不是已完成记录。

## 三类证据分别记账

1. **工程行为**：进程内网关协议夹具 + 公开 HTTP/NDJSON，证明次数、幂等、状态、权限和停止等确定性行为。
2. **隔离真实集成**：发布候选产物 + 真实模型 + 真实客户网关 + 独立业务库。允许对指定一次读取受控注入故障；原始模型轨迹和之后真实读取都保留。模拟时间、丢包和伪造的超时不称为自然生产故障。
3. **生产业务与前端**：发布后通过真实身份、当前来源和可见入口操作，核对生产对象及最终结果。至少一次只读临时任务按真实墙钟到期并生成报告/收件箱；不能修改 phase 时间、数据库记录或注入 now 来宣称生产到期通过。

每条记录环境、提交/release、模型标识、来源、操作时间/时区、输入、原操作/对象/恢复关联 ID、错误码与阶段、恢复动作、实际终态、是否有控制下发、截图/事件/脱敏日志路径。证据只保留必要事实，禁止 Token、密钥、全量私人库或内部思考泄漏。

## staging 隔离

- 优先空业务库配真实配置；确需生产只读快照时，在启动服务/scanner 前对副本停用所有复制计划，确认无复制的 pending/executing 阶段。主库与 `.sessions` 路径必须独立，不能误指 shared 主库。
- 普通验收只读客户网关，测试出口拦截所有非测试对象及设备控制；不能让复制的生产凭据/计划产生真实控制。测试拦截只在隔离 harness，不能留生产故障开关。
- 故障仅注入一个明确测试请求，不重启生产、不阻断整个网关、不污染生产数据库。实际下发路径依照下方“即时控制”证据边界。
- 成本与截止时间沿生产有限预算；为等真实到期可短时安排测试，不能用长 sleep 阻塞进度沟通。

## 必需场景矩阵

| ID / 票 | 用户可观察场景 | 必须证明 |
|---|---|---|
| A01 / 01 | 确认创建一次性只读任务时首次目录读取超时 | 系统自行重读，原目标不变，创建一次；前端无需发送第二条补救消息 |
| A02 / 01 | 确认成功但客户端丢失回包，随后重开页面/再次触发恢复 | 取得原 Task/Plan，无第二次创建；持久化恢复显示同一结果 |
| A03 / 01 | 卡片过期、时间已过、已有等价周期计划 | 分别重建必要的新确认、澄清新时间、返回已有计划；不静默顺延 |
| A04 / 02 | 同参只读第一次失败、第二次成功；持续失败 | 前者得到真实结果，后者预算内停止并给出已取得部分与原因；无无限轮询 |
| A05 / 03 | 两个不同参数问题依次修正 | 真实模型读取每次错误并生成正确提案；相同确定性错误无进展能停止 |
| A06 / 04 | 夜间收口/分阶段提案首次执行校验错误 | 真实模型继续修正，设备、排除项、先后阶段完整；确认前零控制 |
| A07 / 05 | 能耗 preparing 后 ready，以及统计已成但解读失败 | 预算内取得同一请求结果；已存事实/附件不丢、不重复建，缺数不当零 |
| A08 / 06 | 修改、取消本次/全部、暂停/恢复出现版本冲突或丢回包 | 核实原操作结果，精确保留管理作用域；变化需新确认，历史/在途不回滚 |
| A09 / 07 | 即时确认返回前断流、拒绝、下发中断、结果未知 | 查询原回执并分别显示；不重复下发，不把 unknown 或后来现态改写为历史成功 |
| A09a / 07 | 即时草案勾选保存、还原、重核和放弃遇读失败/冲突 | 选择不丢、版本一致，必要差异清楚；恢复不能自动确认设备控制 |
| A10 / 08 | 模型启动前目录故障、首次连接失败、工具后模型失败、租约过期 | 对可恢复情况继续同一委托；续接不重跑工具，成果及历史持久；不可恢复给真实结果 |
| A11 / 全票 | 恢复时停止、新消息、返回重开、换身份/source、401/403 | 停止不再触发调用，旧恢复不覆盖新意图；来源与身份不串，权限拒绝不绕过 |
| A12 / 09 | 新建真实只读报告委托，真实到期前后经历一次受控只读失败 | 同一检查点内恢复；固定对象/口径，一份报告和一条结束通知，可从收件箱进入查看 |
| A13 / 09 | 生产发布后的连续业务操作 | 发起查询→出卡→确认→管理→实际到期→报告通知→重开追问，目标、时间和结果一致 |

A01–A11 的故障注入在隔离集成完成；生产侧核对相同行为的正常业务路径与可安全重现的丢回包/重开，不为了制造故障破坏生产。A12 同时保留“staging 故障恢复”和“生产真实墙钟到期”两条证据，不混写为生产自然故障恢复。

## 前端与即时控制的完成边界

- MP：相关行为测试、微信编译及微信开发者工具实际点击/截图；网页仅辅助。移动网络/前后台断流验收另由可连接的真机完成并记录机型与网络。代理自行操作可用设备，不能写“用户自行验证”；缺少设备接口时明确未验，不把模拟器当真机。
- 自动发起恢复显示正在核实/重试，只有需要实际决策才请求用户输入；处理记录保留失败到恢复的关联。成功后主结论为业务结果，预算耗尽保留部分成果、具体原因和下一步。视觉按当票选择的设计技能核对字号、点击区和返回路径。
- 即时控制 A09 的幂等/未知用协议夹具完整覆盖，真实模型/网关可验证提案和只读核实；生产可重读已终态操作，证明无新增下发。
- 若要声称“新的真实设备下发后的恢复已验”，必须使用已有明确批准的测试设备、目标值、时间窗及原状记录，代理在产品内确认并核对真实回执/可用现场证据。准备方案或概括性的验收要求不等于对任意办公灯/空调/门禁的控制授权。当前材料没有指定这样的测试对象，执行代理先查现有有效授权；若确实没有，具体下发验收记未验，提交最小明确测试方案取得缺少的授权后由代理执行。该项不可伪造完成或永久交给用户代验。
- 真实设备暂不具备物理验证能力时分别记录平台受理、权威回读和物理效果的证据等级；门禁历史动作不能由当前状态证明。

## 生产发布与收口

1. 遵循现行云端发布规范：确认源码、构建、产物哈希、备份、无在途受影响任务、安全窗口和回滚点。不要使用历史 release 名或另一会话尚未验收的源码。
2. 用实际可用的真实历史采样选择报告时间，不把上游模拟补数当真实采集。短时只读 Task 在未来数分钟实际到期；验证创建/确认/执行/报告/通知的全部对象关联。周期行为用临时只读 Plan 验证未来发生和暂停恢复，再停用取消，避免留日常任务。
3. 验收对象加可识别测试标签，记录创建 ID；结束后只通过公开业务接口清理自己创建的未到期任务/计划、恢复测试设备原状。保留已发生报告的必要审计，不误删用户业务。
4. 停止本票 staging、端口、拦截代理和临时容器，删除私密库/密钥副本；清理仅限已记录的测试路径与对象。
5. 完成记录写 `plan/`：逐项 A01–A13 的结果、证据链接、两仓 commit/release、哈希、UI环境、真实到期时间、控制次数、清理、残余未验。没有证据的复选框保持未勾选；自动化通过不替代真实业务验收。
