Mode: 按用户授权自主设计；新增风险取舍另列

## Question

依据已核对的现状和已确认的完整交付，哪些行为交给 Pi 的语言/调查判断，哪些必须由确定性业务模块承接，业务之间通过什么事实与引用组合？哪些现有输入、恢复和结果职责应保留、深化、替换或退出？

## Context

首条控制候选已暴露改时重抄/重绑、核验政策分支和整集/子集问题；报告候选则已有声明式要求与事实准备。两者不能只因都返回提案或 completed 就套同一输入/终态；也不能为了减少工具数建万能入口。原始证据见[现状对照](../../../docs/research/2026-10-20-agent-delegation-current-state.md)。

## Resolution needed

明确业务模块 interface 与 seam、可选证据与必经准备、事实/意图/提案/Task/报告/引用生命周期及恢复；对每个保留/替换决定说明收益和退出旧复杂度的方式。先判断完整能力是否成立，再冻结最小接口；不编写生产代码，不预建工作流或通用注册表。

## Comments

- 2026-10-20：建图阶段开放；依赖事实基线与交付界限，不能直接把旧局部修订草案当 resolution。

## Resolution — 2026-10-20

采用深化现有业务模块的方案。Pi 理解请求、澄清非唯一选择、选择与问题相关的只读调查、组织有依据的解释；模块负责完整成员、权限、计算、准备、确认版本与执行结果。不把开放调查固定成报告脚本，也不让模型管理设备绑定或宣告业务成功。

### 最小职责与复用

| 现有模块 | 对 Pi 暴露的业务能力 | 留在服务器的工作 |
| --- | --- | --- |
| 目录/状态与来源适配器 | 查位置/设备、读状态与能力，取得可读事实及明确选择引用 | 来源与授权、完整成员、位置出处、状态时间/可信度 |
| 能耗统计与报告 | 指定范围/期间统计、比较、按贡献继续查；按明确要求生成附件 | 期间/基期、单位、覆盖、计算、要求满足性、保存事实 |
| 安全台账与视频 | 按窗口查记录/设备汇总、读记录详情/当前资料、选择摄像头/录像窗口 | 分页去重、记录身份、历史与当前位置、候选依据、短时效取流 |
| 动作与 Task 准备 | 即时目标或各阶段独立目标、排除和时间；补充未决缺口 | 完整展开、能力、预检、固定成员/绑定与确认快照 |
| Task/Plan 管理 | 读取真实引用、提出未来变更/停止、解释保存结果 | 对象/版本/权限、可编辑阶段、调度与报告、不重发未知 |

这些是现有代码的职责归属，不是五个新包、五个远程服务或五个万能工具。只在真实重复调用点共享校验，保留具体业务的小接口和错误原因。

### 引用和事实

- 位置表达、完整集合引用、精确成员子集是不同选择语义；完整集合取服务器保存的完整成员，精确子集不扩大。明细展示限额不得变成业务数量上限；集合不存在/过期不能根据历史名称猜回。
- 已选择集合后固定成员；重新授权校验可拒绝，不能静默吸收新设备或缩成有权部分。未选择的目录探索仍可正常刷新，不把查询结果误当长期控制授权。
- 澄清只变更本次明确缺口，保留已确定部分。确认前引用和已登记 Task/Plan 分开；登记后管理真实 ID/版本，不用过期准备引用重建同一任务。
- 时间修改由现有管理模块读取原 Task/Phase/模板，只提交时间差异；完整设备、动作、绑定、核验政策及 `read.agent.spec` 留在服务器。已执行/在途事实保留；明确变设备才重新准备。现存重绑/50 项反例列入迁移必修项。
- 事实/报告/结果保存后不可变；跟随设备 ID 核验当前访问权限，解释不重算。新的范围/期间另得新事实；任务名称/设备显示名不是身份键。复用现有会话、候选引用和报告存储，不新建长期 Investigation、OperationPlan 或引用注册表。
- 电表按能耗目录 ID 与 areaName；智慧设备位置路径与设备自身楼层按[位置权威记录](../../../plan/2026-10-19-device-location-authority-handoff.md)核对。不能按模糊名称把两张主数据自动关联；名字变化本身不重绑控制，历史名称不回写。

### 旧入口的去向（设计决定，尚未实施）

| 入口/行为 | 去向与理由 |
| --- | --- |
| 即时草案与照明便捷入口 | 保留即时业务语义；照明便捷入口内部适配到同一混合动作准备，避免不同成功口径；不强改成未来 Task |
| Company 分阶段控制新输入 | 修正候选生命周期后作为新建阶段目标入口；服务器处理各阶段独立范围，不限定成“先灯后空调” |
| 夜间收口专用新建/续接 | 新建路径在等价能力接通后退出 Company 模型可选列表；已有未确认卡按原期限保留受限续接或明确失效，已登记任务走真实 Task 管理。保留原收口政策作为验收样本 |
| `propose_task` 兼容控制输入 | 变成同一控制准备的适配入口，不再暴露给 Company 模型竞争选择；Office 行为保持。旧周期/区间时间规则继续复用，不抄一套扫描器 |
| 只读任务及 `read.agent.spec` | 保留独立只读输入与处理；不能为了收敛控制把它删掉或套控制回读口径 |
| `summarize_energy` / `compare_energy` 与 `create_energy_report` | 分别保留开放调查和明确附件产出；只共享已存在的统计事实准备，不把每次查询强制保存附件 |
| 设备发现/能力读取、记录详情/录像准备 | 作为可选取证入口保留；动作准备不要求模型先逐台查。G1–G4 位置工具重构仍是待确认独立设计，不以本票批准其 schema 或大面积替换 |
| prompt、工具描述/返回 note、恢复摘要 | 和实际入口同步替换；不能隐藏工具后仍引导旧调用。旧观察/报告/任务历史保留读取 |

业务完成政策随模块事实确定，模型不能通过兼容输入选择较弱标准。Company 新控制的已满足/已核验与报告的要求/覆盖分别判定；历史 ACCEPTED 不回写为 verified，Office 不在本轮隐性迁移。照明无权威新鲜反馈时始终保留未核验。

独立目标的普通设备失败可分别收口；原夜间收口的授权/快照失效阻断本次后续下发已经确定。该规则在周期计划未来发生上的暂停/恢复范围另列重要风险决定，不通过 module 命名或兼容代码偷偷决定。
