# 03 — 大范围计划的效率与执行政策

Status: decided
Wayfinder: grilling
Blocked by: 01

## Question

冻结大范围操作的阶段预算与执行政策：范围展开、批量状态预检、提案生成、控制下发、回读和报告各自如何计时和收口；服务器是否使用范围加动作模板；同控制器串行、跨控制器并发、已满足项、部分失败、未知结果和是否重试如何表达。

## Boundary

基于现有真实基准和客户网关约束做取舍，不先增加并发平台、缓存系统或通用调度器。

## Resolution — 2026-10-19

### Efficiency stages

大范围任务按以下阶段记录耗时和结果：

1. Pi 理解/澄清；
2. 服务器范围展开与排除校验；
3. 批量状态预检；
4. Task 提案生成与确认；
5. 到时控制下发；
6. 权威回读；
7. 报告收口。

不能只报告整轮平均耗时，也不能把模型等待归因于设备网关。当前真实基准（97 台状态读取约 15.2 秒、整轮约 63 秒）作为对照，不先承诺脱离现场网关的固定总秒数。

### Planning and preflight

- Pi 生成范围表达、排除表达、阶段和动作模板；服务器一次展开完整成员。
- 计划范围或排除无法完整核验时，不生成待确认计划。
- 当前状态一次批量预检；已满足、可读但需下发、不可读分别展示。
- 低风险照明/空调的单设备状态不可读时，可以生成计划，但不能把它当作已满足或成功；范围覆盖、授权和能力不可读时必须阻断。
- 预检结果不让模型重新搜索；修正只能来自用户补充或服务器明确返回的缺口。

### Execution and readback

- 确认后使用同一计划快照；到时不重新让 Pi 解释目标。
- 同一控制器串行，不同控制器最多三组并发；三路是当前真实网关安全基线，是否提高必须用真实对照数据决定。
- 独立控制组继续收口；失败不自动重试，不重复发送未知结果。
- 授权失效、服务中止或计划快照失效时停止认领排队动作，已经在途的动作继续收口。
- 下发结束后按同一批次做新鲜回读；回读失败、受理未确认和物理状态未知分别保留。

### Acceptance evidence

首条闭环至少记录范围展开、预检、下发、回读、报告和模型阶段的耗时与调用数量，并验证跨两层、多区域、照明/空调混合、排除项和两阶段任务。性能优化不能通过缩小范围、跳过回读、把未知视为成功或增加自动重试取得。

本票不引入缓存平台、全局并发调度器或新的执行服务；只规定首条业务使用现有适配器、Task/Phase、执行器和报告事实如何高效收口。
