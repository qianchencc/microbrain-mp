# 客户告警消息卡片跳转公司 Agent（启动生命周期收口）

上游证据与契约探索：`plan/2026-10-28-message-card-jump-exploration.md`。本规格只覆盖**前端启动生命周期与参数接收**；发送端配置与正式版本发布是外部闸门（见 Further Notes）。

## 2026-11-05 固定路径实验（当前契约）

`App.onShow` 分发、登录后恢复与 30 秒重放保护已在 `e415019` 实现；下文旧问题陈述保留为 2026-10-28 的历史背景，不代表当前代码仍缺失这些逻辑。

- 客户只需配置固定路径，例如 `/pages/agent/dashboard?source=company&entry=latest-alert&type=gas&deviceId=53b5b346404f47c8a438ec6d16124931`。`type` 仅支持 `gas/smoke/water`；`deviceId` 是授权设备目录的 ID，不是订阅配置中的 sn。
- 有设备 ID 时，只引用该设备、该类型的最新历史告警；未配置设备时，只在同类型的授权设备内查找。无权限、类型不匹配、读取失败或分页未完成均不扩大范围、不换成其他告警。
- 前端调用 `GET /api/agent/safety-events/latest`，传公司来源、类型、可选设备 ID 及本次读取的带时区 `to`。准备态重试沿用同一查询时刻；后端复用身份隔离的读取快照，完整扫描最多 20 页并按发生时间及事件标识选最新记录。未扫描完整不返回猜测结果。
- 返回真实 `safety_event` 引用和预置问题，只填入输入区，不发送、不创建任务、不确认、不下发。已有草稿时，引用与问题成对确认替换；取消、旧确认迟到、身份切换或用户继续编辑均不得形成“旧问题＋新引用”。
- 固定路径无法标识被点击的那条历史消息：用户点击旧消息时仍取该设备当前最新台账记录。历史记录不等于设备当前仍在报警。

### 本轮证据与未验收边界

证据目录：`evidence/LATEST-ALERT-01/`。开发者工具中，同一真实账号分别打开燃气、水浸、烟感路径，均出现对应设备的台账引用及对应问题，未自动发送。燃气设备最新记录为 `aa122d376ec44d0db54a7236e0866920`（2026-10-16），水浸为 `c321e1afdca8455c8970df5e04084413`（2026-10-28），烟感为 `c5fd4c856451457f9b652de7657233dd`（2026-10-16）；它们是已有历史记录，不是本轮触发的新告警。

- 真实接口：把水浸设备 ID 用于燃气查询返回 403；缺类型返回 400，均未落到其他告警。
- 真实界面：已有草稿时确实展示“已有未发送内容”成对替换弹窗，见 `replace-confirm.png`。
- 工程验证：前端 306 项通过；后端 599 项中 574 项通过、25 项跳过；边界检查和 HBuilderX 小程序编译通过。隔离回归覆盖乱序分页、同类型其他设备更新、跨类型、未来记录、无权限、空台账、上游失败、扫描不完整，以及成对确认和迟到结果。
- **未验收**：原生弹窗自动化未得到可观察的取消／确认回调，不能把按钮分支记为前端通过；热启动模拟未产生可核验的页面切换；真实未登录后恢复未执行。对应纯逻辑测试不替代上述界面证据。
- **未验收**：没有修改客户发送端配置、发送订阅消息、触发物理告警或点击真实微信卡片。真实卡片冷／热启动、登录恢复及正式版本发布仍需联调，不能据此宣称正式链路已验收。


## Problem Statement

客户在微信里收到设备订阅消息（烟感/燃气/水浸告警）后点击卡片，期望直接落到小程序的公司概览，并且 Agent 已经知道"我在说这条告警"，可以一键继续处置。当前四种进入方式只有一种成立：

- 已登录、冷启动落到仪表盘：可用（浮层展开，带「客户告警引用」与预置问题）。
- 未登录冷启动：`thirdLogin` 成功后 `reLaunch('/pages/index/index')`，原始路径与参数丢失，用户落回首页，卡片上下文全丢。
- 小程序在后台时点卡片：`App.onShow` 不解析也不分发新的启动参数，页面停在原状态，新告警被静默忽略。
- 已有未发送草稿时点新卡片：实测保留旧草稿，未出现"是否替换"确认，用户以为 Agent 已经换成了新告警，实际发出去的是旧草稿 + 旧引用。

另外，页面打开期间不会自动发送，这是既有且正确的约束；缺口只在"参数能否可靠到达输入区"。

## Solution

把"卡片启动参数"当成一条有明确生命周期的输入，而不是页面上的一段 `onLoad` 逻辑：

1. 发送方按冻结契约拼 `page`（`source=company` + 可选 `alertPrompt` + 可选 `prompt`）。
2. App 层在每次前后台切换时统一解析启动参数，按"有无登录态 / 当前顶页是不是仪表盘"做出唯一决策：走登录恢复、重开仪表盘、还是交给当前页面消费。
3. 仪表盘是**唯一消费点**：在 `onShow` 原子取出一次待处理参数，打开公司 Agent 浮层，把 `alertPrompt` 变成客户告警引用、`prompt` 变成预置问题。
4. 输入区已有内容时用既有"已有未发送内容"确认弹窗，绝不静默覆盖；同一告警重复点击不重复插引用。
5. 任何路径都不自动发送、不触发设备控制。

## User Stories

1. As a 收到烟感告警的客户员工, I want 点击告警卡片直接落到公司概览, so that 我不用先找入口再翻告警。
2. As a 收到告警的客户员工, I want 打开时 Agent 已经带上这条告警的原文引用, so that 我提问时不用复述设备和时间。
3. As a 收到告警的客户员工, I want 预置一个"帮我核实这条告警"的问题, so that 我只需点发送。
4. As a 收到告警的客户员工, I want 预置问题只填入输入框、不自动发送, so that 我能先改措辞或取消。
5. As a 未登录的客户员工, I want 点卡片后自动登录并仍落在这条告警上, so that 首次进入也不丢上下文。
6. As a 已登录但小程序在后台的客户员工, I want 点新卡片后前台页面立刻切到新告警, so that 我不会看到旧告警以为是新的。
7. As a 正在打字的客户员工, I want 新卡片到达时明确问我是否替换草稿, so that 我不会误发上一轮的提问。
8. As a 连续点同一张卡片的客户员工, I want 不重复出现两条相同引用, so that 输入区不被污染。
9. As a 客户员工, I want 卡片参数过长或损坏时仍能正常进入仪表盘并被提示, so that 跳转本身不失败。
10. As a 客户员工, I want 从仪表盘返回时不被重复的跳转打断, so that 我已消费过的卡片不会再次弹浮层。
11. As a 客户员工, I want 卡片只带预置问题（静态路径）时界面不显示空引用, so that 不会出现没有内容的引用条。
12. As a 客户员工, I want 引用内容被当作"客户告警原文"而不是"平台已核验事实", so that Agent 不会谎称已核对台账。
13. As a 客户员工, I want 点击卡片后不经过首页、不闪跳, so that 体验像原生入口。
14. As a 客户员工, I want 切到其他页面再回仪表盘时，已消费的卡片不再重放, so that 返回行为可预期。
15. As a 客户员工, I want 卡片页在弱网/登录失败时给出可理解的错误而不是空白, so that 我知道该重试。
16. As a 我方工程师, I want 启动参数只认公司 Agent 的键, so that scene/referrerInfo 等系统参数不会渗进业务页。
17. As a 我方工程师, I want 解析与决策逻辑是可单测的纯函数, so that 生命周期分支不靠真机试错。
18. As a 我方工程师, I want 主包不引用分包模块, so that 不再出现 `module ... is not defined` 灰屏。
19. As a 我方工程师, I want 每条进入路径有明确的验收层级, so that 单元测试、开发者工具、真机、trial/formal 各自证明什么一目了然。
20. As a 我方工程师, I want 不引入仅开发环境可用的模拟入口, so that 产品代码不背实验开关。
21. As a 客户对接人, I want 一次真实卡片点击就能验证到位, so that 不用反复改发送端配置试错。
22. As a 客户对接人, I want 正式版 `page` 只在含该页面的版本发布后切换, so that 不会出现 `41030`。

## Implementation Decisions

**参数契约（冻结，发送方据此实现）**

- 目标页固定 `pages/agent/dashboard`；`source=company` 固定。
- 可选 `alertPrompt`：发送方 `encodeURIComponent` 一次；客户端解码一次并 trim，解码失败按原文保留；空或超过 2000 字拒收并 toast，不阻断进入仪表盘。建议发送方压到 300 字以内（路径长度无官方上限）。
- 可选 `prompt`：同上解码一次，≤200 字，拒绝控制字符；只预填，不自动发送。
- 既有 `taskReference` / `safetyReference` / `environmentWindow` / `energyWindow` 语义不变；`alertPrompt` 与它们的优先级以现有解析顺序为准（后者覆盖前者）。
- 不传 `alertId`：本期不建告警详情接口，引用内容即事实边界，Agent 不得声称已核验平台记录。

**模块边界**

- 启动参数白名单、目标页判定、暂存/取回、URL 生成集中在**主包**工具模块；App 与页面共用同一实现。
- 主包任何文件不得引用 `pages/agent` 分包内模块——已发生过运行时 `module 'pages/agent/launch-link.js' is not defined` 导致灰屏。
- App 层分支收敛为一个纯函数：输入 `{ hasToken, currentPath, launch }`，输出 `ignore | login-restore | reopen | deliver`：
  - 无可用启动参数 → `ignore`；
  - 无 token → `login-restore`（暂存参数，登录成功后取回并回到目标 URL）；
  - 有 token 且当前顶页是仪表盘 → `deliver`（暂存，由页面 `onShow` 消费）；
  - 有 token 且顶页不是仪表盘 → `reopen`（`reLaunch` 到目标 URL；卡片点击视为新入口意图，不压栈）。
- 重放保护：微信每次回到前台都会把当前进入参数再交给 `onShow`，同一内容键 30 秒内不重复接管（内容键 = 白名单键值串），否则已消费的卡片会把用户从别的页面拽回仪表盘。
- `reopen` 的 `reLaunch` 延后一拍执行：在 `onShow` 里同步导航会被丢弃（实测页面栈不变），放到 `setTimeout(…, 0)` 后可靠生效。

**消费模型**

- 仪表盘 `onShow` 是唯一消费点：原子取出待处理参数（取出即删除）并打开浮层；`onLoad` 只负责把本次参数交给暂存，不再并行打开，避免双开与重复消费。
- 暂存为单槽 + 10 分钟 TTL；过期、时钟倒退、存储不可用一律视为无参数。后到的卡片覆盖未消费的旧参数（最新意图优先）。
- 已 `onShow` 消费过的参数不再重放：页面被 `navigateTo` 压栈返回、后台/前台切换都不重复弹浮层。
- 未登录冷启动的恢复只保留一条路径（登录回调取回 → `reLaunch` 目标 URL → 页面 `onShow` 消费），不允许"登录回调恢复"和"页面 onLoad 恢复"两条同时存在。

**交付与冲突**

- 浮层打开时若会话组件尚未挂载，引用/预填进入既有暂存队列，挂载后交付（已实现，保持不变）。
- 输入区已有草稿时复用既有「已有未发送内容」弹窗，取消保留草稿；本期需查明实测"未出现替换确认"的原因并修正，不允许静默覆盖。
- 当前待发送引用与到达的 `alertPrompt` 内容相同时不重复插入（浮层仍照常打开）。
- 任何路径不自动发送、不自动确认、不触发设备控制；发送仍走用户点击 + Runtime 权限/确认。

## Testing Decisions

好测试：只测外部可观察的决策与参数语义，不读 Vue 源码断言 CSS、标签或动画参数（`test/AGENTS.md` 既有约定）。组件级交付（浮层展开、引用条、输入框预填、草稿确认）不写单测，走开发者工具与真机验收。

测试缝（按优先级，复用现有实现）：

1. **参数解析（已有）** `parseAgentContext`：解码一次、长度边界、控制字符、非法参数只 toast 不中断；`alertPrompt` → `customer_alert`；`prompt` 只预填。现有 `test/agent-card-link.test.mjs`。
2. **启动链接（已有）** 白名单、URL 只编码一次、暂存/取回/TTL/原子性。现有 `test/agent-launch-link.test.mjs`。
3. **新增** App 层分支纯函数：`hasToken × currentPath × launch` 全组合 → 四种决策，含 `currentPath` 带前导 `/`、无 query、非目标页。与 2 同文件或新增 `test/agent-launch-lifecycle.test.mjs`。

不新建页面级测试框架；回归命令保持 `npm run test:agent`。

## Out of Scope

- 客户告警发送端改造（`page` 拼装、`miniprogram_state`、模板字段）与客户后端。
- 告警详情接口、`alertId` 引用、卡片内容与平台台账的自动对账。
- Runtime 侧改动（`customer_alert` 校验、`query_alerts` 行为）。
- 首次"只有预置问题（静态路径 A）"的 Agent 回答质量验收。
- 设备控制链路与二次确认语义（保持不变）。
- 正式版提审、发布与 `formal` 切换。
- 多条未消费卡片的排队/合并（本期只保留最新一条）。
- 仅开发环境可用的模拟卡片入口（**不新增**；用开发者工具「启动参数」与真机 developer 版卡片）。

### 验收分层（每层能证明什么）

| 层 | 手段 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| L1 | `npm run test:agent` | 参数语义、分支决策、暂存 TTL/原子性 | 小程序生命周期顺序 |
| L2 | 开发者工具启动参数（冷启动，已登录/未登录各一次） | `onLaunch/onShow` 分支、单一消费点、登录恢复 | 真实卡片参数编码、真实网络 |
