# 04 — 即时操作进入区域时间轴

**Spec:** `.scratch/region-workbench/spec.md`（“Runtime：任务存储”“即时草案补写任务记录”“查询接口”“区域工作台视图模型”）
**领域:** ADR 0004 第 9 条；`CONTEXT.md` 任务区域归属
**仓库:** iot-agent-runtime + mp

**What to build:** 第一条真实数据的端到端路径。用户在 Agent 中确认一次即时设备操作后，打开区域工作台，就能在今天的 B6 时间轴上看到这次操作：一个时间点上的细卡片，显示任务名、最多 3 个设备头像加 “+N”、创建者，并按状态着色（完成变淡、部分完成黄铜点、失败标记）。涉及两个区域设备的操作出现在两个区域的时间轴上。

**Blocked by:** 01, 02, 03

**Status:** implemented — 微信端到端验收待开发者工具登录

- [x] 新增任务、任务阶段、阶段设备三张表（以独立模块与 Fastify 插件组织，不向现有入口文件追加路由）
- [x] 即时草案执行进入终态后补写一条来源 `immediate_draft`、单阶段、已结束的任务记录，阶段设备结果由 01 的结果词汇映射；补写失败只记审计，不影响草案结果
- [x] 任务区域集合由设备区域归属推出
- [x] `GET /api/agent/regions/:regionId/timeline?date=` 按 Asia/Shanghai 日界返回任务摘要；按请求身份过滤可见性，非本人区域 404
- [x] 创建者展示名本票统一为“成员”（真实姓名见 13）
- [ ] 小程序视图模型产出卡片点/区间、状态样式与头像组；在微信操作流程中验收，不为简单展示映射单独建测试
- [ ] 工作台页面用 02 的渲染组件显示当天时间轴与卡片，默认定位到当前时刻
- [x] Runtime 测试：faux 模型提出草案 → 确认 → 时间轴接口返回对应任务；跨区域、跨用户可见性
