# 06 — Agent 创建定时任务

**Spec:** `.scratch/region-workbench/spec.md`（“创建者凭据托管”“Agent 工具与任务富面”）
**领域:** ADR 0004 第 5、6、7、8 条；`CONTEXT.md` 执行身份、任务
**仓库:** iot-agent-runtime + mp

**What to build:** 用户在 Agent 中说“下午两点到三点在会议室B 开会，开始时空调 26 度灯全开，结束时全关”，对话中出现一张任务卡：任务名、时间、阶段、每阶段设备与目标。点“创建任务”后任务被保存为已安排，卡片转为持续显示任务最新状态并提供“在区域面板查看”，区域时间轴上出现对应的点或区间缎带。本票不执行任务（见 07）。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] Pi 工具 `propose_task`：名称 ≤12 字、1–2 个阶段、`candidateSetIds` 引用候选集，校验与草案一致（能力已检查、名称位置由目录回填）；拒绝 >2 阶段、首阶段晚于 7 天、未来阶段含门禁、首阶段早于“现在 − 10 分钟”，并给模型可读原因
- [ ] 流事件 `task.proposed` 与 `task.resolved` 随 events_json 持久化、恢复重放；零滞留：下一条消息退役待确认任务提案；TTL 与草案一致
- [ ] `POST /api/agent/tasks/:id/confirm`（带版本）：置 `scheduled`；首阶段已过去超过 10 分钟返回 409“时间已过，请重新创建”（窗口内立即执行的部分见 07）
- [ ] 确认时以 AES-256-GCM 加密托管请求的授权信息与租户；密钥为新运行配置项，缺失时 Runtime 拒绝启动；凭据不出现在任何响应、事件、日志或观测轨迹
- [ ] 小程序统一任务卡富面：提案态（创建任务/放弃）、已确认态（按任务 id 轮询详情直到终态，链接到工作台并带日期）
- [ ] 对话事件归约支持 `task.*` 事件并可恢复重放，`node --test` 覆盖
- [ ] 即时“关灯”仍走原草案链路，既有测试不回归
- [ ] Runtime 测试覆盖：提案校验拒绝项、零滞留退役、确认、超窗 409、版本冲突、缺密钥拒绝启动、响应中不含凭据
