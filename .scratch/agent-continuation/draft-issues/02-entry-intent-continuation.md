# 02: 启动或引用读取失败后保留并续接原委托

**What to build:** 目录/引用在模型启动前失败时，原请求仍可被后续推理理解；短暂故障恢复后自动继续，已经结束为阻塞的请求在用户说“继续”时也不丢目标。

**Blocked by:** None (can start immediately)

**Status:** draft（待新拆分粒度与阻塞边确认；尚未发布为 ready-for-agent）

**规格与追踪：** [业务规格](../spec.md)故事 5–7、30–34；[验收矩阵](../acceptance.md) C04–C05、C23–C24；[执行地图](../execution.md)。

## 冻结范围

仅入口失败的意图保存、引用事实和合法接续。无可信主体时不新增服务端用户会话；不重做认证系统、不缓存原始凭据。

预估产品代码变更 60–120 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

发送一条带明确地点和时间范围的只读查询，在模型启动前使目录读取失败；恢复服务后分别验证同次自动恢复及阻塞后“继续”，真实模型都按原地点和窗口完成查询。

## 继续、等待与退出

- **继续：** 可信身份已确定且只读故障可恢复，在原预算内继续；阻塞后新的已鉴权“继续”带入原目标及失败阶段，重新核实当前引用权限。
- **等待必要决定：** 身份需重登、引用权限不足或原业务信息确实缺失时等待对应必要决定；本地草稿只供同用户确认后恢复，不跨账号自动提交。
- **退出：** 无可信主体拒绝进入模型；新意图、换账号/来源或停止使旧恢复失效；预算耗尽明确阻塞并保留可恢复的合法事实。

## Acceptance criteria

- [ ] 原请求既出现在恢复页面，也在后续模型可用上下文中；不依赖模型猜测“继续”指什么。
- [ ] 目录恢复后自动推进原只读查询；达到阻塞后“继续”仅恢复原未完成内容，不重复已完成查询。
- [ ] 引用读取错误后仍关联原授权对象；引用不可访问时不伪造内容，也不挂接别人的会话。
- [ ] 未验证身份不调用模型、不落他人会话；重新鉴权、换账号、跨来源、停止和迟到结果覆盖。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

将入口红灯探针提升为 HTTP 行为回归，真实模型核对地点/时间/引用均来自原请求。认证失败与可信身份后的目录失败分别测试，不混成一个入口。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
