# 06: 即时草案编辑、重核或放弃遇错后保留选择并继续

**What to build:** 即时草案的选择、参数编辑、还原和重核遇错后仍保留原选择与合法修订；需要协调时智能体承接，放弃则真正停止。

**Blocked by:** 01

**Status:** draft（待新拆分粒度与阻塞边确认；尚未发布为 ready-for-agent）

**规格与追踪：** [业务规格](../spec.md)故事 15–17、30–34；[验收矩阵](../acceptance.md) C12–C13、C23；[执行地图](../execution.md)。

## 冻结范围

仅草案准备/编辑到待确认或放弃，不执行即时控制；不每次勾选叫模型，不新做编辑器或基础组件。

预估产品代码变更 80–140 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

在待确认即时草案中排除一个设备并修改一个参数，提交时读取失败/版本冲突；恢复后展示同一草案的实际版本和用户意图，最后放弃，确认无控制发生。

## 继续、等待与退出

- **继续：** 核实原草案版本与已生效选择，确定性补齐未完成编辑；策略冲突才回流模型，模型获得用户明确选择与当前授权差异。
- **等待必要决定：** 目标集合/参数实质改变或重核发现执行内容改变时保留差异等待确认；不能把旧版本自动升级为已同意控制。
- **退出：** 放弃、停止、换意图或撤权终止相关恢复；迟到重核结果不能重新激活草案或重置用户选择。

## Acceptance criteria

- [ ] 勾选/参数/还原/重核失败不丢编辑意图，原草案/版本可核实，无新建无关草案。
- [ ] 冲突需协调时真实模型解释最新差异并返回必要确认；正常确定性编辑不引入无用模型调用。
- [ ] 恢复期间无实际控制请求；旧版本和失效授权不能进入执行。
- [ ] 微信实际编辑→错误→核实→恢复选择→放弃闭环，通过双端并发、停止及迟到结果检查。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

受控协议覆盖版本冲突和读失败，真实模型承接一处实质差异，微信实际编辑/放弃；客户控制适配器阻断写入。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
