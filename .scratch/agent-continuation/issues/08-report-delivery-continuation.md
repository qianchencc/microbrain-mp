# 08: 能耗准备、部分成功或解读失败后交付原报告

**What to build:** 能耗统计在准备、有部分成果或解读失败时继续交付原范围/期间的报告；有进展且有预算时不把“请重试”交给用户。

**Blocked by:** 03

**Status:** ready-for-agent

**规格与追踪：** [业务规格](../spec.md)故事 21–23、30–34；[验收矩阵](../acceptance.md) C16–C18、C23；[执行地图](../execution.md)。

## 冻结范围

仅现有统计准备和报告交付闭环；复用现有等待/快照/附件，不新增数据补造、计算平台或永久后台任务。

预估产品代码变更 60–120 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

请求一份已明确期间/范围的能耗报告，准备阶段先返回处理中后就绪；再注入部分子结果成功和解读失败，最终只交付同一份权威报告并完成解释。

## 继续、等待与退出

- **继续：** 真实准备进度推进且预算未尽可继续读；已经成功的统计/附件保留，只补未完成部分或解释。
- **等待必要决定：** 仅缺业务窗口/统计范围决定或授权时提问，已经确定的信息不要求重填；不能自动更换期间掩盖缺数。
- **退出：** 准备无变化且无替代或截止到期时交付已有成果与具体阻塞；没有实际持久安排不承诺稍后自动交付。

## Acceptance criteria

- [ ] 既有冷统计同轮恢复保持；超过单次工具等待但仍有真实进展/总预算时合法继续，真实模型得到可行动状态。
- [ ] 部分成功只推进缺项，保存报告后解读失败不重建报告/附件，不重复通知。
- [ ] 原范围、期间、采样与缺数口径保持，不能造数或移窗来制造成功。
- [ ] 无进展/停止/预算到期明确部分或阻塞，保存成果仍可查看；微信实际打开原报告并追问可用。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

公开统计/对话接口控制准备进度和部分故障，真实模型配合真实可读网关完成报告；记录缺数实际边界，不以夹具数据冒称客户报表。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
