# 03: 调查有新进展时继续，真实无进展时正确退出

**What to build:** 明确多个地点的调查能利用每次有效新事实完成提案；参数可纠正时继续修正，真实打转或预算到期才如实结束。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**规格与追踪：** [业务规格](../spec.md)故事 8–10、30–34；[验收矩阵](../acceptance.md) C06–C08、C23；[执行地图](../execution.md)。

## 冻结范围

仅现有工具循环的进展/收尾判据和对外终态；不提高阈值掩盖反例，不新增昂贵的独立完成评审模型，不建设全局规划器。

预估产品代码变更 50–100 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

用户明确五个地点的同一任务，五次检索分别获得新设备事实，随后生成完整待确认提案；并列验证重复同一失败与存在合法替代查询。

## 继续、等待与退出

- **继续：** 新事实确实缩小待完成问题，或可从已有事实纠正参数/尝试合法替代且未超总预算时继续。对重复无效动作的抑制不得无理由撤销所有有用工具。
- **等待必要决定：** 用户未给定的真实地点/时间选择或新的确认才暂停；已有上下文足够时不能再要求用户填写工具参数。
- **退出：** 无新进展且无合法替代、总工具/模型/时间预算耗尽或用户停止时退出；公开恢复状态包含原因及已得事实，不用普通 completed 文本伪装提案已完成。

## Acceptance criteria

- [ ] 五地点全部有新事实的反例转绿，四地点对照保持；最终卡包含原明确范围，不漏第五处。
- [ ] 保留不同参数连续修正、成功读后重置无进展、停止取消退避等已有行为；不锁定某一内部调用顺序。
- [ ] 重复相同无效动作能终止，存在可用替代时仍可完成；日志刷新和模型新文本本身不算进展。
- [ ] 预算边界仍生效，未出卡/未交付时终态明确未完成或等待必要决定；通过恢复接口可见原因。
- [ ] 真实模型完成同类多地点提案，并证明可行动工具错误促成纠正，不仅增加调用次数。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

从公开 runner/provider 复现五/四地点对照，再经公共 run/恢复接口验证终态。保留现有正确回归；真实模型只生成待确认提案，不执行客户控制。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
