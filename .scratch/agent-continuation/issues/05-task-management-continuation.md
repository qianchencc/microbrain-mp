# 05: 取消本次或全部、周期启停遇错后完成原管理意图

**What to build:** 用户已明确的取消范围与周期启停，在故障后仍针对同一任务/计划生效并可核实，不要求重新描述或误扩大操作。

**Blocked by:** 01

**Status:** ready-for-agent

**规格与追踪：** [业务规格](../spec.md)故事 13–14、30–34；[验收矩阵](../acceptance.md) C10–C11、C23；[执行地图](../execution.md)。

## 冻结范围

仅已有取消本次/全部、暂停/恢复业务的恢复；不新增调度能力，不补跑历史，不把所有操作改为模型驱动。

预估产品代码变更 80–140 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

只读周期报表中跳过本次，再暂停并恢复同一计划；分别让响应丢失和目录暂时失败，恢复后核对本次/未来发生及下一合法检查点。

## 继续、等待与退出

- **继续：** 按原管理操作核实结果；确定性成功直接交付，合法未完成动作在预算内继续，需要判断最新状态时传递原操作范围和当前事实。
- **等待必要决定：** 原请求本来不明确本次还是全部，或目标/范围已有实质变化时只问必要决定；已明确且未变内容不重复确认。
- **退出：** 用户放弃、权限/来源变化、目标不再可操作或无进展到期时阻塞；晚到恢复不能重新启用被后来暂停的计划。

## Acceptance criteria

- [ ] 取消本次不取消全部，明确取消全部才影响未来；重复请求和未知回包不扩大范围。
- [ ] 暂停/恢复只作用同一 Plan，最新状态核实后准确显示，不重复切换或另建计划。
- [ ] 恢复从现有规则下一个合法未来点执行，没有历史补跑，原模板不丢失。
- [ ] 真实模型在必要冲突中处理原管理意图，微信同对象管理闭环通过；停止/新意图/撤权不复活旧动作。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

公共 HTTP 检查原操作范围/发生数与时间；真实模型处理故障后的管理决定；微信对只读计划实际操作并清理验收计划。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
