# 10: 真实周期报表跨故障完成管理、持续到期和报告追问

**What to build:** 代理自行完成一条真实只读周期报表委托，从创建/修改/暂停恢复到关闭客户端后的两次真实到期、报告通知与同结果追问，并发布可核验版本。

**Blocked by:** 01, 02, 03, 04, 05, 08, 09

**Status:** ready-for-agent

**规格与追踪：** [业务规格](../spec.md)故事 27–34；[验收矩阵](../acceptance.md) C21–C22，并复核本链路C23；[执行地图](../execution.md)。

## 冻结范围

仅这一条持续报表业务的最终交付与发布，构建/部署/观察都是闭环步骤。不是新建测试平台或性能治理；票06/07另行独立验收，不作为本报表链路的伪语义依赖。整体完成仍须十票均达到各自关闭标准。

预估产品代码变更 0–60 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

用真实授权身份在微信提出一份当前数据可读的周期能耗报表；隔离环境先证明创建/管理/查看故障均自动承接，然后发布，在生产建立明确验收用只读计划，按真实墙钟完成两个合法未来发生，回到通知和报告追问后清理。

## 继续、等待与退出

- **继续：** 沿已确认计划的现有调度推进，模型只在准备/解释/必要恢复时运行；不要求客户端在线，不靠模型空转维持下一检查点。
- **等待必要决定：** 真实数据/窗口决定欠缺时由代理核实并仅请求必要选择；合法未来时间不能为演示被偷偷修改，生产不可注入客户级故障。
- **退出：** 真实阻塞明确记录，不以构建成功或模拟到期宣告通过；取消验收计划后不得新增发生，保留已发生报告与通知事实。

## Acceptance criteria

- [ ] 发布前记录两仓实际基线、必要测试/类型/构建、MP有改动的开发及发行编译；按现有发布规范备份、核对产物哈希、健康与回滚点，无微信上传/提审要求。
- [ ] 隔离实例以真实模型证明原创建/修改/启停/查看的故障承接；生产不人为打断客户服务，不把隔离证据写成生产故障恢复。
- [ ] 生产微信实际创建唯一只读计划、修改一个业务字段、暂停并恢复；核对原对象、下一合法未来点和无历史补跑。
- [ ] 关闭客户端后至少两个合法未来发生按真实墙钟到期，各交付一份权威报告和一条相应站内通知，无重复统计/通知；记录计划点、实际起止与持续跨度。
- [ ] 重开从站内通知进入原报告并用真实模型追问；原期间/范围/数据依据一致，不能仅凭完成事件或截图认定交付。
- [ ] 停止/取消验收计划，清理自建进程/数据库副本/隧道等资源；提交两仓业务变更与脱敏证据及plan交接。
- [ ] 逐项核对其余九票的独立验收才宣布整组完成；报告两次到期不证明物理控制或长停根因已解决。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

优先合法现有频率缩短等待，但不改调度语义或伪造时钟。若只能跨日才有第二合法点，就实际跨日完成。记录实际通过/阻塞，由代理继续跟进，不把用户当测试执行者。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
