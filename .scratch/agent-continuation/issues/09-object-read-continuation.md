# 09: 任务或报告查看失败后沿原对象核实与对话

**What to build:** 列表、详情、收件箱和报告入口遇到503等读取问题后，系统沿原对象核实并让智能体承接必要追问，不把已创建说成未创建。

**Blocked by:** 01

**Status:** ready-for-agent

**规格与追踪：** [业务规格](../spec.md)故事 24–26、30–34；[验收矩阵](../acceptance.md) C19–C20、C23；[执行地图](../execution.md)。

## 冻结范围

仅查看失败与原对象引用的连续性；不根治旧控制详情503上游原因，不做全站性能/通用请求层重写，不新建第二报告入口。

预估产品代码变更 60–120 行；测试/证据按必要行为单列，不以行数为通过标准。开始实现前核实当前基线和最窄切片；超出上界约50%时先说明原因并重新收窄/拆票，禁止借机扩成通用平台。阻断外发现记后续，不扩本票。

## 可独立演示的闭环

从任务列表打开已存在任务时详情短暂503，恢复后进入同一详情和报告；点击引用追问，真实模型知道当前对象与恢复事实，无需复制编号或报错。

## 继续、等待与退出

- **继续：** 先只读核实原授权对象；服务恢复后恢复原页面/引用，必要解释把安全对象事实交给当前会话，不擅自挂接原私密会话。
- **等待必要决定：** 身份需重验或确实缺授权时等待对应操作；用户没选对象时才请求选择，不能让用户重新创建已存在任务。
- **退出：** 真实不存在、撤权、来源不符、用户停止或预算无进展时明确原因；暂时503不能等价为404或任务未创建。

## Acceptance criteria

- [ ] 任务详情503与报告读取失败恢复到同一对象；加载/核实有反馈，成功后旧错误不再主导界面。
- [ ] 只读恢复不触发任务创建、确认、控制、报告重生成或通知；不存在与暂不可用区分。
- [ ] 真实模型在引用追问中获得当前授权原对象事实，不丢对象、不读取他人私密上下文。
- [ ] 微信列表→详情→报告→追问路径与重开可用；跨主体/来源引用、撤权、停止和晚到结果覆盖。
- [ ] 从最窄稳定公共接口完成相关红灯→绿灯与必要回归，不测试实现字符串；证据区分受控协议、真实模型、真实网关、微信与生产。
- [ ] 执行变更相关检查及必要窄审，语义提交业务代码/测试/文档，记录实际版本、验收证据、未验边界和清理结果；代理自行完成验收，不以“待用户测试”关闭。

## 验证入口与关闭条件

隔离协议故障经公共读取/引用接口验证，微信实际打开与引用；真实模型完成同对象问题，不把上游503根治当本票完成门槛。

源码和既有探针导航统一在执行地图，不把当前行号/私有实现固化为验收。做到相应可观察业务结果、必要权限/取消边界和本票证据后才能 done；待发布或待真实验收如实标记，不能只凭编译、一次重入或错误文案改善关闭。
