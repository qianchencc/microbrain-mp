# 完整业务委托实施规格

## Problem Statement

用户可以委托查询、调查、操作、未来安排与成果交付，但这些能力分散在主线和候选中：提案成功不保证后续可改可停，附件保存不保证期间/比较齐全，授权失效也未覆盖周期计划未来执行。用户难以确信真正安排了什么、取得了什么、为何没有完成，以及停止是否已经生效。

## Solution

保留 Pi、已有业务模块和 UI。Pi 理解/澄清与选择有依据的调查方向；服务器保证范围、事实、计算、快照、确认、执行和真实结果。查询/即时报告轻量完成；控制和未来安排明确确认；周期计划可直接用开关启用/不启用，自动因可信基础失效停用后进入原站内收件箱，重新确认才恢复。

## User Stories

1. 作为查询用户，我希望对已有明确范围直接取得现场/历史事实，以便不为每次只读取证重复确认。
2. 作为调查用户，我希望系统沿真实贡献与记录继续查证，以便得到针对问题的结论而非固定模板。
3. 作为用户，我希望仅在对象、排除、期间或修改作用域真的有歧义时澄清，以便保留已确定信息。
4. 作为报告用户，我希望指定本期、环比、同比和范围后逐项得到事实或具体缺口，以便错期/漏项不被称为完整完成。
5. 作为报告用户，我希望普通问答仍轻量，明确要报告才形成附件，以便即时报告不必先建任务。
6. 作为报告用户，我希望预览、依据、引用、PDF/XLSX使用同一保存事实，以便打开或导出不会改写结果。
7. 作为用户，我希望缺数保留有效部分、真实零仍显示，以便失败不被零或空白掩盖。
8. 作为定时委托用户，我希望确认后立即看到首次/下次安排，以便区分待确认提案和已登记计划。
9. 作为报表委托用户，我希望日报、周报、自然月报区分发送时间和统计期间，以便每次报告归属正确。
10. 作为控制用户，我希望各阶段有独立范围/排除与目标，一次确认后按原快照执行，以便不由模型到点重规划。
11. 作为任务用户，我希望只改时间不改成员、动作、绑定或统计要求，以便大任务也不必重抄设备。
12. 作为周期计划用户，我希望列表/详情有启用开关，以便简单管理未来执行，复杂编辑继续交给 Agent。
13. 作为周期计划用户，我希望手动关闭开关后未来不再发生，本次若仍在进行能明确看见，以便不误以为开关撤回了物理动作。
14. 作为控制计划创建者，我希望撤权、身份明确被拒绝或绑定变化后计划自动进入未启用并收到站内结果通知，以便不会无声恢复控制。
15. 作为创建者，我希望重新启用时核验完整范围并确认下一次时间，以便恢复网络/权限不会自动恢复未来副作用。
16. 作为安全台账用户，我希望每天按明确窗口看到三类记录数、涉及设备数及有效明细，以便失败不冒充零告警，记录不冒充已恢复。
17. 作为巡检用户，我希望先只读检查固定空调范围，再显式确认有限时段内的条件调温，以便不开机、不切模式、不反复争抢或重发未知命令。
18. 作为用户，我希望任务结果/通知/报告从原入口进入和返回，以便没有额外报告收件箱或复杂导航。

## Implementation Decisions

### 复用与最小组合

- 沿用现有目录/来源适配器、统计/比较、安全/视频、动作准备、Task/Phase/Plan、管理及报告模块；不加通用委托对象、注册表、工作流、多 Agent 或第二调度器。
- 目录与状态读取是可选调查能力；控制准备内的授权/完整展开/能力/预检是必经业务校验，不要求模型逐台搬运名单。位置表达、完整集合与精确子集分开，展示上限不是业务上限。
- 新 Company 控制输入与兼容控制输入归到同一准备/核验政策；旧收口专用新建入口在等价接通后退出模型选择，旧未确认卡受限续接/失效，已登记 Task 用真实引用管理。只读任务输入和 Office 来源行为保留，不用新输入形状偷换完成标准。
- 已选成员/控制绑定固定；改时以真实对象和版本提交差异，不重新绑定，已执行/在途部分保留。变目标需重新准备并确认；已存报告不可重算或回写。仅显示名变化不自动重绑设备。
- 能耗由当前能耗计量目录取得范围/位置；摄像头当前位置与历史告警名称分别保留。名称不作为两套主数据的关联键，来源隔离与当前访问权限始终保留。

### 报告与调查

- 自然语言必须准确形成范围、期间与要求声明；服务器校验声明执行，不把“声明合法”当作“理解正确”。开放调查可按贡献选证据，正式附件保存实际采用的事实及要求，不能退化成生成固定模板。
- 必需项区分已取得、缺数/不可比、失败、不支持和未取得。缺项是部分交付；全无有效本期事实不造空附件，真实零有效，空区块隐藏但缺口保留。解释失败不丢保存事实，不因导出重新查询/计算。
- 调度与统计期间分开；日/周/月按上海时区和本次发生解释，不固定为建计划当天，不以每30天冒充自然月，不用旧时期替换请求。
- 安全首期统计按明确窗口、稳定记录身份分页去重；记录数与设备数分开，某类失败保留其它类事实并说明。摄像头只是核查线索，不宣称看过录像或恢复。

### 周期启用开关与失效通知

- 共用已有启用/停用状态，界面显示已启用/未启用；删除和自然结束独立处理。列表开关不触发进入详情，详情展示同一状态；只允许现有管理权限，两个来源各自校验。
- 手动关闭：只阻止未来发生，服务器成功后开关变关，保留本次和历史；仍有执行中本次时给出明确状态和原停止本次入口。普通切换成功现场反馈，不额外刷通知。
- 手动启用：先读完整范围、原快照/绑定、期限和版本，显示规则和下一次时刻，经用户确认后生效；取消、拒绝或请求失败保持关闭。提交中防重复，冲突后重新读取，不静默重试。
- 系统自动关闭：明确授权拒绝、固定目标撤权或控制绑定变化，令受影响控制计划未启用；本次后续点/排队动作停止，在途如实收口。普通超时不冒充撤权，设备局部拒绝/回读失败不自动停计划；只读报告不套控制停用政策。
- 自动停用与本次结果完成后保存一条原站内任务结果通知，包含计划已停用、通用原因及本次结果关联，按同一停用转换幂等。重启/重扫不重复，未启用计划不再产生未来发生，不日复一日重报相同失效。
- 允许已认证创建者读取自己计划停用的最小通知，即使全部目标已撤权；只含自己的计划标识/名称、未启用状态、通用原因和关联入口。设备资料、明细、附件仍按现行授权拒绝；身份失效须先重新认证，通知先保存，不绕过身份检查。
- 恢复网络/权限不自动开回去，不补旧发生，不重发未知。绑定/目标已变化时明确展示差异重新准备/确认，不能把新绑定当成原确认。
- 原夜间收口本次失效即停止后续下发的决定继续有效，当前阶段级失败偏离需修正；周期计划不因一次结果完成而删除。前台开关是用户新批准的简单管理例外，其余编辑仍由 Agent 提案确认。

### 有限空调条件任务

先只读巡检；随后只对已确认范围内开机、制冷且有效设定温度低于26℃的空调上调到26℃。不开机、不切模式/风速，不用站点温度当全房间室温；固定有限时段/检查点，状态未知不下发，未知命令不重发；参数再次改变时让行/暂停，停止覆盖后续点及排队，不自动反向调温。

## Testing Decisions

- 使用现有公开消息/恢复/引用/确认/Task/Plan/报告 HTTP 与可控扫描接口，断言用户结果、保存事实及实际写入；不测试 prompt 字符串、私有表形状或预设工具顺序。
- 首条能耗闭环复用已冻结漏项/错期反例，再看正常可比与同比缺数关键分支；控制复用改时重绑/88台限制反例；周期开关补关闭/恢复/失效通知和重扫幂等的窄回归。
- 稳定切片完成时做一次必要集成检查与审查；新变化/失败才加验，不每改字段/文档就双审全量。历史测试仅引用，不充当合流或当前服务证据。
- 新开关先最小原型，验证普通关闭、本次继续、系统停用通知、确认恢复/取消/失败。保留现有样式，不设计新控制台。
- 真实模型、网关只读、微信/Excel打开、实际服务版本、发布与物理效果分别留证；活动版本未知保留为验收项。

## Out of Scope

更换 Pi，通用工作流/助手平台、完整位置工具重构、个人记忆、新报告收件箱、外部推送、消防处置、视频理解、正式异常检测、停机补执行/追赶、自动无限期调温、自动合并/部署候选或未经具体授权的真实控制。
