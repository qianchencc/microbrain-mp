# 01：连续只读能耗调查与即时报告

Status: in-progress
Parent: [Company Agent 业务闭环实施规格](../spec.md)
Blocked by: None（报告附件/导出源码已接回主线，当前继续补真实交互证据和必要阻断修复）

**Lane:** 主线；Runtime `5293311`、MP `43062da` 是实现基线，不重复实现 S1/S2。

**What to build:**

用户可以从一条能耗问题开始，得到报告，解释报告中的变化，继续下钻贡献区域或电表，修改期间后生成新的结果，并在恢复会话后继续查看或导出。原报告和保存事实保持不变，新的范围/期间形成新的查询或附件。

**Acceptance criteria**

- [ ] 自然语言中的范围、期间和明确比较要求被正确承接；存在真实歧义时只澄清必要缺口。
- [ ] 报告包含实际取得的统计/比较事实、覆盖或缺口说明；漏项、错期、缺基期和部分数据不能被称为完整成功，真实零保留。
- [ ] 报告可在现有预览中查看依据，可引用原报告解释，也可对改变范围/期间的请求开展新的只读调查；不把新结果写回旧报告。
- [ ] PDF/XLSX 和预览使用同一保存成果，不因导出重新查询或重算；即时报告不强制创建 Task。
- [ ] 至少验证一条连续对话：报告 → 解释 → 下钻 → 改期间 → 新结果 → 恢复/导出；真实模型轨迹、活动服务和微信/手机边界分别记录，不能用预设模型脚本或手写页面代替。

**Delivery boundary:** 本票完成不代表已部署、真实网关可用或现场控制可用；只读数据和真实控制分开验收。
