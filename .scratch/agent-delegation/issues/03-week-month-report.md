# 03：周报与自然月报

Status: in-progress
Parent: [Company Agent 业务闭环实施规格](../spec.md)
Blocked by: 02：定时能耗日报与原任务收件箱结果

**Lane:** 主线；在日报闭环上扩展周期与统计期间，不另建报表平台。

**What to build:**

用户可以在已有任务管理中创建每周或每月能耗报告计划。计划的发送周期与报告统计期间清楚分开，周报使用正确周窗口，月报使用自然月窗口；结果沿日报相同的任务、附件和收件箱链路交付。

**Acceptance criteria**

- [ ] 每周和自然月规则可确认、可见并显示首次/下一次发生；自然月不以固定 30 天代替，跨年和短月边界正确。
- [ ] 每次报告按本次发生解析统计期间和比较基期；缺基期或覆盖不足时保留有效部分并说明，不改用其他期间。
- [ ] 预览、依据和 PDF/XLSX 使用保存成果；修改未来计划不改写已经交付的报告或任务结果。
- [ ] 重复扫描、恢复和计划时间变化保持幂等；结果继续进入唯一任务收件箱。
- [ ] 仅在真实模型、服务版本和微信/手机边界实际核验后，才报告对应环节完成。

**Delivery boundary:** 本票不增加独立报告入口、不建设异常检测，也不等待告警或空调业务完成。

## 2026-10-20 实施起点

- 复用日报的 `read.agent.spec`、报告保存、PDF/XLSX 和原任务收件箱。
- 周期规则扩展为每周和每月；每月按明确 `dayOfMonth` 发生，短月不存在该日时跳过，不把自然月简化成固定 30 天。
- 统计期间继续使用 `previous/week` 与 `previous/month`，由每次实际发生时间解析。
