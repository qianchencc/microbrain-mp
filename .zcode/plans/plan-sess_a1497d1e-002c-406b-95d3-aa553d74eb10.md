## 实现步骤（runtime 仓库，单业务闭环）
1. `npm i langfuse`（装时锁定最新 v3.x 版本记录在案）→ 新建 `src/observability/langfuse.ts`：环境三变量齐备才创建客户端，否则导出同接口 no-op recorder；recorder 可经 `BuildAppOptions` 注入以便测试。
2. 四个接线点（全部经 recorder 接口，默认 no-op）：
   - `app.ts` 消息运行：run.started 开 trace（name=`agent-run`，sessionId=conversationId，tags=[tenantCode]，input=用户消息），tool.started/completed 映射子 span（含摘要/成败），run 终态收口 output。
   - `server.ts` streamFn 包裹：每个模型轮一个 generation（modelId、输入上下文、输出文本、usage——pi 流事件含 usage 则记，缺失则如实留空并在记录中注明）。
   - `app.ts` confirm 端点：独立 trace `draft-confirm`（同 sessionId），每条指令一个 span（kind/outcome/耗时）——正是上一bug想要的执行段可见性。
   - onClose：`await flush()`。
3. `.env` 追加 LANGFUSE 三变量（不打印值）；`.env.example` 补占位符。
4. 测试（tsx --test 既有风格）：无 env 时全流程不触 langfuse；注入 fake recorder 断言一轮对话产生 trace+工具 span+generation、confirm 产生 draft-confirm trace。跑全量回归。
5. `npm run build` → 按 AGENTS.md 配方重启 3200 与 3201（`lsof -tiTCP:<port> -sTCP:LISTEN | xargs kill` 后 nohup node dist/server.js）。
6. 冒烟+自审闭环（skill 要求）：curl 3200 发一条消息（local-development 身份）→ `npx langfuse-cli api trace list` 取回 trace → 对照官方 best-practices 页逐项审计（命名/层级/usage/input-output/脱敏），有缺口修复后重跑。
7. 记录 `plan/027-langfuse-tracing.md`（含 SDK 版本、trace 结构、审计结论）、runtime AGENTS.md 补一行备忘；runtime 仓单独提交。**mp 仓库不动**（并行会话 4 个未提交文件保持原样）。
