# 双 Agent 来源、历史留存与任务查询边界

日期：2026-10-02。状态：用户认可。

物联助手仪表盘展开公司 Agent，另设办公室 Agent 二级入口。公司来源为微脑，办公室来源为 Office 用户授权设备；客户负责各自上游权限，我方不把两份目录合并，不通过入口或 prompt 授予权限。两端复用任务与执行规则，但会话、引用、任务、确认、后台调用和结果保留原业务来源。

旧办公室会话曾包含账号级环境/消防/能耗观察。用户认可保留这些历史卡片与审计供回看，同时从后续 Office 规划中隔离相关历史工具结果、观察事实及其摘要；历史显示不是当前查询授权，也不能成为现态证据。迁移不删除历史，不只靠 UI 隐藏，恢复或重启后仍遵守该边界。

两个入口默认查询本端任务，暂不开放跨端共享；同一物理设备出现在两份上游目录不构成跨端查看或管理任务的授权。未来若接共享，须另有明确客户查询契约，不能静默转移管理或执行来源。

此决定取代早期“账号级只读观察范围可以自动加入 Office”的裁定。提供方读取模块和前端观察组件保留，Company 按自己来源接入，Office 的预留入口不默认开放。当前 Office 视频及已有受支持即时控制能力继续按办公室范围校验。

具体实现和验收沿批准规格与 tracker 逐票推进；不能由本 ADR 宣称 Company、历史迁移或周期自动化已经实现。

## 2026-10-08 页面业务分层细化（用户明确）

员工 Agent 消费“我的办公室”业务接口；公司大 Agent 消费“智慧xx”各页面的业务接口；仪表盘复用公司来源。以客户传达的页面业务分层为接入边界，不继续要求客户解释背后的区域角色、设备对人分配或模板机制，也不新增我方授权系统。

服务前缀不是该分层：“我的办公室”与当前 owner“智慧空调/照明/门禁/监控”的目录都在 office 服务，前者先取办公室成员再按 elementId 取设备，后者先取智慧区域树再按 areaFullCode 取设备。具体接口及控制引用维护在 [10-08 接口盘点](../research/2026-10-08-interface-source-boundary-audit.md)。环境、能源和安全台账按对应业务的实际接口接入，不机械套用四类设备的区域路径。

Company 空调曾直读 iot-center 型号目录，与上述页面来源不一致；2026-10-08 票 17 已改为智慧区域/房间设备页确定成员，见[来源对齐交接](../../plan/2026-10-08-company-smart-ac-source-handoff.md)，不再记为客户权限模型待确认。底层状态/动作接口可用于页面业务目录内已确定设备的绑定与读取/执行。来源修正必须保留 Task/Plan、历史收据与引用的同源身份，不能因上游关联 ID 不同静默重建或删除业务记录。

## 2026-11-10 任务可见范围与创建人展示（用户认可）

- 公司任务不是公司全员无条件共享：同租户、同业务来源后，再按当前用户的授权设备裁剪；周期预览没有符合条件的目标时不展示该计划。办公室授权不自动成为公司来源的授权，也不按用户名设置特例。
- 控制型周期的可见目标还须类型匹配且不属于仅观察设备。可见不等于可管理：周期启停和整周期管理要求创建者身份、全部目标及相关未来例外均在授权范围内；不据此收紧一次性共享任务原有的取消规则。
- 任务和周期详情展示任务事实中保存的创建人；“公司 Agent／办公室 Agent”只表达业务入口，不代替创建人。历史姓名缺失显示“未记录”，不代入当前用户，也不为补名字查询上游。周期执行记录标注周期来源，已持有父计划时显示其名称。
- 页面仅消费后端持有的授权事实。空列表只能说明当前可见交集为空，不能直接推断客户未授权；需要另核对后台授权同步是否正确，不由前端补拉或放开全公司任务兜底。
