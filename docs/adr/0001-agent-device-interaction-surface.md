# ADR 0001：物联 Agent 设备卡片与配置面板的交互边界

- 日期：2026-09-15
- 状态：已采纳
- 范围：`apps/agent-miniapp/pages/agent`

## 决策

设备卡片只承担两种直接语义：

1. 短按切换待确认草案中的选择状态；
2. 对可配置的待确认设备长按，经过短暂延迟和环形进度反馈后，从底部拉起统一配置面板。

配置面板是页面级的 modal surface，层级必须高于输入栏和会话内容；它不是卡片内部的浮层。面板关闭、草案过期、草案取消或草案执行后，编辑器都必须同步卸载，不能继续显示一个已经失效的操作入口。

## 修订（2026-09-16 深夜）

长按不再用自制 touch 状态机（touchstart 定时器 + 位移阈值 + suppress 标记 + 环形进度）。该实现有两个结构性缺陷：卡片上的 `catchtouchmove` 会吞掉 scroll-view 的滚动（从卡片上拖动无法滚动手轨/网格）；suppress 标记会把滚动结束后的那次 tap 一并吞掉，造成"卡片点不动"。现改为平台原生手势：`@tap` 选中（与滚动天然互斥）、`@longpress`（约 350ms，触发后框架保证不再派发 tap）唤出配置面板，环形进度反馈随之移除，按压反馈改为 hover-class 缩放。卡片高度统一 180px（不再因空调类型加高）。

## 理想效果

- 短按立即有明确的选中反馈，但不会打开配置面板。
- 长按在约 420ms 后开始给出反馈，约 560ms 后完成并只打开一次面板；移动、取消、多指和抬手都不会误触发配置。
- 配置面板使用 44px 以上的触控目标；遮罩独立负责外部点击关闭，只有横杆区域负责拖拽，标题和面板内控件不会被拖拽手势抢占。
- 面板底座统一使用官方 `uni-popup`；自研代码只负责横杆的下拉跟随与收起判定，禁止再次自绘遮罩、层级和整套进退场。
- 全部设备面板中的全选只操作当前草案，不改变已执行或历史卡片。
- 历史、过期、取消和执行结果卡片只读；门禁卡片不显示虚假的设备状态标签。
- Agent 头像使用固定 seed 的 Blobatar 生成结果，跨会话稳定，但保留原有的微动效。

## 验收

1. 选中与取消选中各有一次清晰、可见的状态变化，勾选图标可见。
2. 单设备配置中不出现“应用到全部同类设备”；存在同类设备时才显示并可切换。
3. 打开配置面板时，面板和遮罩完整覆盖输入栏；关闭时不闪烁、不残留遮罩。
4. 重新构建微信小程序后，开发者工具无运行时错误，发送按钮、确认草案、重新核验、面板关闭均可触达。
5. 不在本次验收中执行真实设备控制。
