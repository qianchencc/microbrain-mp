# 周期计划与独立任务区间

日期：2026-09-30；2026-10-02 更新交互边界。状态：核心方向与 Q7–Q11 业务边界已认可；前台管理流程已收窄，原型待调整，功能尚未实施。

2026-10-02 用户确认转向：复杂任务操作统一委托 Agent，前台只保留查看、删除与快速引用，不提供任务创建/编辑表单、检查点编辑器或仅本次/整个周期的手动管理流程。创建、修改、启停等基础能力仍供 Agent 调用，权限、版本、未来时间与设备目标校验不因此取消；变更仍经提案和用户确认。仅本次与整个周期仍是领域语义，由 Agent 根据用户表达解析，含糊时澄清。

任务可通过按钮引用到输入框，由用户补充意图后发送；引用本身不发送消息、不修改任务、不构成授权。计划、虚拟发生与实际 Task 的对象身份必须可区分，不能仅靠名称定位。引用交互建议与原型调整入口见[Agent 管理与任务引用交接](../../plan/2026-10-02-agent-task-management-handoff.md)。本段取代旧原型的前台编辑、启停导航建议，保留已有执行与历史规则。

2026-10-04 用户明确首期范围：区间至少一个检查点，零检查点拒绝/澄清；不考虑服务停机，按最小可行闭环完成——停机补执行、漏跑窗口与恢复追赶后置，本决定不是选择新的恢复策略，也不设固定迟延阈值。正常运行的终点动作沿用已认可语义：正常扫描先处理已确认到期检查点（含 at=endsAt），在途调用收口后汇总报告。现有幂等、中断结果未知不自动重放与不重复下发约束保持不变；未确认零下发、来源与授权重核不变。功能仍未实施；下文“正常调度迟延与停机补执行的判定阈值属规格与实现验收事项”的旧表述以本段为准，前台原型旧记录由现有已认可场景覆盖，不新增 UI 批准。

周期计划长期保存重复规则和任务模板，未来发生由规则推导，到执行时生成标准 Task，复用已有设备执行、回读和审计。没有选择提前生成未来多天 Task 的做法：停用和修改计划不应需要清理一批尚未发生的执行记录，已经发生的历史也不能随规则编辑变化。一次性 Task 保留，不强制迁移成计划。

区间任务独立保存起止边界，检查点在其中自由安排，不设阶段数业务上限。首末检查点不能决定区间，也不能因为最后检查点提前完成而提前结束任务。检查点确认时安排，用户可编辑未来检查点；本期不引入执行中的自主规划或阶段间持续监控。

用户“基本认可”上一轮五项建议：一期重复规则为每天、工作日、指定周几，设备为照明/空调，可跨日；创建者编辑与启用计划，拥有全部目标设备操作权限的区域成员可停用并留下操作者记录；成功与异常结束通知都发给创建者。门禁不进入本切片，Token 生命周期不作为前置调查。

这是对 [ADR 0004](0004-unified-task-model-and-phase-execution.md)的一次性范围扩展，保留其直接接口执行、执行前授权重核和结果证据原则。旧实现的两阶段上限、首末阶段区间投影和全部阶段终态即结束的行为不是新领域规则。模型、存储、查询、日历、时间轴、详情和通知需要引用同一组独立区间与检查点事实，不能只放宽校验而保留旧聚合语义。

用户在具体场景解释后再次“基本认可”Q7–Q11：本次与整个周期均可完整编辑未来检查点及目标，目标重核并确认；区间结束后不补旧检查点，终点动作允许正常调度，已开始调用收口后报告与通知；停用周期不取消当前发生，实际 Task 取消发通知、跳过虚拟发生不推送；订阅不足不阻断执行，详情记录投递结果；跨日按开始日期归属，截止日不截断已开始区间，创建时已错过开始则顺延下一次。

正常调度迟延与停机补执行的具体判定阈值、并发认领边界属于规格与实现验收事项，不能用本段替代。删除全部检查点、修改区间导致检查点越界等操作仍需原型验证。决定与 Matt 进度统一回填[任务总表](../../plan/2026-09-30-agent-task-register.md)，UI 补充与协调见[周期原型交接](../../plan/2026-09-30-recurring-prototype-handoff.md)。本 ADR 不代替冻结规格或实现票据。
