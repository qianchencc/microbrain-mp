## 结论速览

| 层 | 完备性 | 依据 |
| --- | --- | --- |
| 接口层（范围聚合） | **完备** | 三源直采与 adapter 目录交叉一致；40 条重复关联被正确吸收；20 台平台未分配设备按授权边界正确不可见 |
| 状态层（readStates） | **不完备（关键缺口）** | 关联来源设备状态全盲：superadmin 可见 219 台中仅本人办公室 7 台有状态 |

抽查方式：脚本直采（登录 → 三源分页）+ 引入 runtime dist 的 `createIotAdapter` 做目录/状态层核对，**模型不参与**。账号 superadmin（系统管理员，accountType=1，XSJ）；凭据经环境变量传入、token 仅内存，未落盘。登录一次成功；两次 207 为脚本 client_secret 手误，非账号问题。

## 账号范围画像

- scoped 办公室仅 1 个（数智工程研究院院长室：2 空调 + 3 照明 + 2 门禁）；「更多区域」体现在账号级关联目录：空调 53 / 照明 159 / 门禁 47，覆盖 26/27 楼各办公室、农旅公共区、杭州、始版桥等。
- adapter 最终目录（去重后）：照明 125 + 空调 49 + 门禁 45 = 219 台；诊断 conflicts=7（同名同址异名等字段冲突，已按既有机制入诊断）。

## 接口层明细（完备 ✓）

1. **合并损失为假阳性**：照明 33 组 / 空调 4 组 / 门禁 2 组「同 hubDeviceId 多记录」，逐组核对名称——全部是**同名重复登记**（同一物理设备的重复关联记录），不是不同回路。adapter 按物理设备去重吸收 40 条是正确行为；不同回路各自有独立 hub（26楼过道 4 回路均有独立 hub 已在 023 验证）。
2. **范围外 20 台**（物联中心三类 239 台 - 范围内 219 台）：6 台空调总控（26/27 楼 N 路总控）、11 台 27 楼照明（执行总裁/副总裁/经营部/总经济师/茶水间/男卫等）、开发测试门禁、杭州门禁×2。全部既不在任何 scoped 办公室也不在关联目录中——属平台侧未分配或归属他账号，Agent 不可见是**授权边界正确工作**，非缺陷。客户若希望管理员可见 27 楼照明，属上游分配业务决策。

## 状态层明细（不完备 ✗，本轮核心发现）

- scoped 办公室设备：双路径正常（2 空调权威读全量、2 照明粗状态、1 门禁 null 属设计语义）。
- **关联来源（assoc-only）设备：6 台抽样全部 null**，包括在刘志龙 scoped 下曾有权威读的「空调-26办公区（机房前）」。原因链：
  1. 账号级关联记录**全部不带 `code` 字段**（0/53）→ 空调权威读（路径 B：按 code 查物联中心 acDetail 动作）前提缺失；
  2. 粗状态（路径 A）只按本人 scoped 办公室拉取 → 关联设备不在其中。
- 产品影响（对 admin 这类以关联为主要范围的账号）：草案无法预剔除已满足项、ALREADY_SATISFIED 判定不可用、控制后回读恒为「暂未取得最终状态」。诚实但降级。024 的首次控制之所以能权威证实，正因刘志龙的设备走 scoped。
- 修复方向（登记票，勿顺手实现）：关联记录均带 hubDeviceId（= 物联中心设备 id），可在目录加载时用物联中心目录反查补齐 `code`（或直接按 id 取 acDetail 动作），使权威读对关联设备同样可用。

## 操作层明细（完备 ✓）

- scoped 7/7 台 controlRef 反查成功（hub join 正确）；空调 scoped 台 actionList 均含 acDetail+airCondition。
- 关联记录自身即控制 id 载体（office-association 来源 controlRef=self），219 台全部可下发；40 条重复合并后仍保留一条有效控制 id。

## 方法与工具

- 脚本（/tmp，无凭据落盘）：`superadmin-login-probe.mjs`（登录）、`superadmin-layer-audit.mjs`（三源矩阵+操作层+完备性反查+状态抽样）、`superadmin-merge-deepdive.mjs`（合并损失量化+关联状态抽样）。
- 登录契约：`POST /sso-api/login/word/v2`，AES-128-CBC（key/iv 见 mp `utils/cryptojs.js`）加密用户名密码 + client 凭证；响应 content.access_token，`Authorization: bearer <uuid>`。
