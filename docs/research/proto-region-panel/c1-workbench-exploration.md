## 二、C1 原型覆盖了什么

主变体（`?variant=`，←/→ 切换）是**页面结构**，三者对“设备在哪里、设备时间轴怎么出现”的回答不同：

| 变体 | 结构 | 设备时间轴出现方式 |
| --- | --- | --- |
| P1 双页签 | 时间轴 / 设备两个页签（沿用 B 系列） | 设备列表点击 → 小程序页面栈推入独立设备页 |
| P2 时间轴主页 + 设备抽屉 | 时间轴独占页面；底部浮条“设备 15 / ＋ 新建任务” | 高抽屉内页栈：设备列表 → 设备时间轴 → 任务详情（同 `DraftSheetLayer` 三页导航） |
| P3 设备货架 + 同轴过滤 | 顶部横向拟物货架，下方时间轴 | 点货架设备 = **同一条时间轴**原位过滤为该设备，“只看 K-26-05 ✕”退出 |

次级旋钮（原型栏）：抽屉 D1 阶段 / D2 设备×阶段矩阵；设备列表 L1 陈列格 / L2 铭牌行；设备轴 DT1 同轴（B6 组件）/ DT2 履历（等距列表）；区域提示 无 / 仅异常 / 全部；日历 属于时间轴 / 属于页面（仅 P1）；会话 跨区域连续 / 按区域隔离；演示时刻滑杆。

入口：默认从“物联 Agent”页进入。头部第二行是共享的区域芯片与“区域面板 ›”入口；对话中的任务卡“在区域面板查看”会推入面板并打开该任务抽屉；抽屉里“来源对话 / 再建一次”反向回到对话；面板底部“让 Agent 在某区域新建任务”回到对话并预填区域。

## 三、逐项分析与建议

### 1. 区域切换：单选，推荐会话跨区域连续

- **单选成立，且比多选多一个优点**：区域面板一次只能诚实地展示一个区域的时间轴；多选会迫使面板合并多条时间轴并给每张卡加区域标签，复杂度落在最常用的页面上。Agent 侧的多区域需求可以由对话点名解决（范围选择本来就不是权限边界）。
- **会话不建议按区域隔离**：任务已经由服务端固定 `regionIds`，区域面板就是按区域的长期记录；再把会话按区域切开，等于用会话重复承担区域归属，还会让“把会议室和办公室都关了”这类跨区域意图无处安放，并在切换后丢失上下文。原型中“跨区域连续”模式在切换时插入一条“关注区域切换为 X”分隔，此后默认按新区域解释；“按区域隔离”模式可以对照体验切换带来的断裂。
- 区域芯片是同一个组件：Agent 页与面板页任一处切换都同步；设备详情页不放区域芯片（设备属于固定区域，在此切换没有意义），标题下只显示所属区域。

### 2. 时间轴卡片：细卡 + 设备头像组 + 创建者

- 细卡高 32px：任务名、设备头像组（最多 3 个，其余 `+N`，悬停抬升并显示名称，参照 animate-ui Avatar Group）、分隔线、创建者头像（本人显示“我”）。
- 状态不再占文字位，但不能完全消失（B6 契约：状态由内容承担，不由节点表达）：已结束的卡片淡化；执行中卡片有玉绿左缘与描边；部分完成/失败在任务名前加一粒黄铜点；取消为删除线并更淡。完整状态在抽屉头部。
- 抽屉（D1 推荐）：标题 → 时间与区域 → 创建者与状态 → 一句结构化摘要（部分完成时整块转黄铜底）→ 阶段列表（节点沿用 B6 起点实心、终点圆环、单点空心/实心；区间任务的阶段连线使用同一深浅材质并按当前时间切分）→ 每阶段的设备头像组，点开是逐设备“目标 / 结果”→ 记录。动作按 ADR 0004：未开始“删除 / 编辑”；执行中“取消剩余阶段 / 编辑未来阶段”；已结束“来源对话 / 再建一次”。
- D2 矩阵适合多阶段、多设备的会议类任务（一眼看出每台设备在每个阶段的目标与结果），但单阶段任务里只剩一列，信息密度反而更低。可考虑“阶段数 ≥ 2 时提供矩阵切换”。

### 3. 设备列表与设备时间轴

- L1 陈列格复用 `DeviceActionCard` 的纸材底座与设备插画，右上角黄铜指示灯（亮 = 运行、灰 = 关闭、空心黄铜环 = 离线），底部一行“下一次计划动作”。L2 铭牌行复用 `DeviceRoster` 的纸卡分组，更密。设备多时 L2 更实用，陈列感弱。
- 设备时间轴复用 B6 组件，**区别在内容而非几何**：卡片从“任务”变为“这台设备经历的操作”——左侧来源标签 `定时`（定时任务）/ `即时`（对话确认后立即执行的单阶段任务）/ `人工`（设备审计），正文是本设备的目标（区间任务显示“开启 → 关闭”），其后弱化显示任务名，再是结果（✓ / 已满足 / 失败 / 进行中）和执行发起人。区间缎带在设备轴上的含义是“这台设备处于该任务区间内”，与区域轴一致。头部是设备插画、实时状态和“下一次”。
- DT2 履历（倒序等距列表）作为对照：设备记录稀疏且跨天时更紧凑，但失去了时间比例和“现在”的空间感。建议设备轴保持 DT1，与区域轴同一语言。
- 人工操作只出现在设备时间轴，不进入区域时间轴卡片层；区域轴只展示任务。

### 4. 接管与冲突

本轮用户决定：接管与冲突定义是多余的，不进入设计。C1 已移除待办条、“接管”计数与冲突文案。需要对齐的文档见第四节。

### 5. 设备筛选

照搬操作草案“查看更多”（`DraftSheetLayer`）的交互：分组标签（类型 / 位置 / 状态）+ 圆形搜索按钮，点按后标签左滑淡出，返回键与搜索框自右展开；搜索匹配名称、位置、类型、状态并高亮；返回即清空。标签是“分组方式”而不是“过滤条件”，列表始终是全量。

### 6. 状态、更新与通知钩子

建议分三层，只让真正需要人的事情越级：

| 层 | 内容 | 建议 |
| --- | --- | --- |
| 原位（面板内） | 阶段开始/完成、进度 | 时间轴与卡片实时更新即可，不产生任何提示。 |
| 区域列表 / 入口红点 | 当日部分完成或失败、且本人尚未查看 | **只显示异常**（原型默认“仅异常”）。“执行中 / 下一项”在“全部”模式下可以体验，信息正确但噪声大：多数区域大部分时间都有计划任务，徽标会失去含义。 |
| 推送（订阅消息等） | 我创建的任务失败/部分完成 | 仅失败，且深链到对应任务抽屉；渠道尚未接入，见专题研究。 |

“已读”只是个人状态：打开该区域面板即清除红点，但任务仍然是部分完成，不代表已处置。建议的事件钩子（服务端 → 投影）：`task.created / task.updated / task.deleted`、`task.phase.started`、`task.phase.finished{verified|satisfied|partial|failed}`、`task.finished{done|partial|failed}`；红点只订阅最后两类中的 partial/failed。
你感觉“好像没必要”的那部分（完成、进行中）确实没必要进入区域列表；异常是唯一值得越级的信息。

### 7. 日历归属：属于时间轴

- 日历是时间轴的**导航器**，不是页面属性。证据就在 P1“属于页面”模式：切到设备页签时，页面级日历仍然占据顶部却没有任何作用（原型中会变灰并提示）。
- 因此每个时间轴实例各带自己的日历：区域轴用完整周条（可展开为月）；设备轴用更轻的形态——右上角日期胶囊即日历入口，点开是只标记本设备有记录日期的周条。
- 两个日历不共享状态，但**下钻时继承聚焦日期**：在区域轴看到 9/25 再进入设备，设备轴从 9/25 打开。P3 因为是同一条时间轴，自然共享同一个日历。

## 四、补充问题（原型暴露，尚未决定）

1. **区域层级**：会议室B属于 26F 办公区。父区域面板是否汇总子区域任务？若汇总，区域芯片是否需要层级选择？C1 暂按扁平区域处理。
2. **入口形态**：Agent 页头部是“区域芯片 + 区域面板入口”两个控件；另一种做法是区域芯片本身即入口（点芯片进面板，长按/下拉切换区域）。前者清晰，后者省空间。
3. **对话任务卡的生命周期**：任务完成后对话里的卡片是否转为只读收据（Orca“卡片即状态机，回答即收据”）？C1 中对话卡实时反映任务状态。
4. **即时任务是否上区域时间轴**：ADR 0004 下对话确认的“帮我关灯”也是 Task。C1 只把它放在设备时间轴（`即时`），区域轴只放定时/区间任务，避免被高频即时操作淹没。需要确认。
5. **空区域**：会议中心没有设备和任务时，面板只剩空状态与新建入口。是否在区域列表中隐藏无设备区域？

## 六、验证

- 浏览器逐一核对 P1/P2/P3、D1/D2、L1/L2、DT1/DT2、三档区域提示、两种日历归属和两种会话模式，控制台无错误。
- 区间浅/深两层使用完全相同的 `d`，深色层按当前时间裁切；每个午夜只有一个 `00:00`，没有 `24:00`；“现在 / 时刻”文字碰撞时整组隐藏，黄铜节点保留。
- 已知简化：数据是静态投影，按演示时刻推导任务状态；编辑/删除/取消只提示语义，不改数据；小程序真机特性（安全区、`scroll-view enhanced`、宿主全局样式屏蔽）不在本原型验证范围。
