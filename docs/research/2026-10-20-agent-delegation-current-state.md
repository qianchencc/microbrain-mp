# 完整业务委托：目标、现状与证据缺口

日期：2026-10-20（续接复核）。本文件是本轮只读核对快照，不是全链路验收、完整规格或排期。决策索引沿用[物联 Agent 重设计地图](../../.scratch/agent-redesign-wayfinder/map.md)。用户已认可从“完整业务委托”校准终点；未因此批准旧修订草案、具体工具形状或新执行政策。

## 目标锚点

用户以自然语言委托有实际价值的物联业务；系统能够按需要查询、调查、澄清、准备操作或安排任务，交付有依据的结果，并承接追问、调整与停止。Pi 保留语言与有证据的调查判断，服务器掌握确定性业务和副作用事实。夜间收口是一个检验样本，不是全部终局。

本轮重点为 Company，Office 的既有来源、权限与成熟功能作为不可混用/不可回退边界；不把历史个人记忆、通用助手或新平台探索自动恢复为当前范围。下表是待校准的业务族，不是承诺同时实现七个功能。

## 如何读证据

- 源码核对：仅证明对应版本存在该路径，不证明模型自然调用正确、现场数据可用或用户界面已验收。
- 冻结实测：仅证明已记录版本、输入、环境和结果，不重新派生成功率；夹具、真实模型、客户网关、微信、物理设备各自区分。
- 历史记录：说明过去有相应交接，未在本轮重新验证，不能充当当前活动服务事实。
- 待核验：证据不足，不写“已支持/已完成”，也不把未知当零或失败。

## 跨业务必须一起看的继续路径

这不是固定工具脚本：同一委托可能需要若干轮证据与澄清。观察/调查不强制创建 Task；即时报告不强制先建定时任务；控制及未来执行必须有相应显式确认。确认前后、原事实解释与改变范围/期间、放弃目标与补缺口不能混为同一种“继续”。

每条业务都要检查：意图到范围/要求声明、可选证据、必要澄清、待确认（适用时）、实际结果/成果、追问与调整/停止、恢复与权限变化。前端卡片、详情、附件和收件箱也是链路的一部分，接口存在不是用户能完成委托。

交付与自主推进已按用户授权收口，见[完整业务委托的交付与自主推进界限](../../.scratch/agent-redesign-wayfinder/issues/05-complete-delegation-outcomes.md)；周期控制的未来发生如何受失效影响仍需单独决定。首条收口的[原决议](../../.scratch/agent-redesign-wayfinder/issues/01-company-night-closure-contract.md)已经明确授权/计划快照失效后不得继续下发后续阶段；这是已定约束，不能因实现或测试偏离而改称用户尚未决定。开放的是跨业务推广、周期影响与恢复细节，不重新要求用户批准原契约。

## 已知约束与不应外推的结论

- Pi 固定，Company/Office 来源隔离，未确认零控制，未知不自动重试，没有证据不声称完成。
- 动作受理、设备目标核验、报告要求齐全、任务所有阶段终态是不同事实；不能因为都有 completed 字样就共用成功定义。各业务迁移范围和历史兼容仍待决策。
- 目标是完整委托，不意味着“一个万能工具”或“一种 Task 结构承载全部业务”；保留现有成熟业务并不等于保留每个旧接口。
- 旧重设计地图闭合的是首条业务样本；旧 04–06 与客户报告/巡检需求不是同一批已完成承诺，不能互相替代或因本图自动放行。
- 对模型误解、上游缺数、接口能力缺失和交互未接通分别取证，不把一份提示词或成功样例作为通用修复。
