# 周期计划稳定主体与执行凭据只读核验

日期：2026-09-30。任务：总表 S01，服务 T01 周期计划与 T02 结束通知。

状态：真实只读核验完成；发现可复用账户 ID；跨 Token 稳定性和后台运行政策仍未实证。未修改业务代码、身份文件或登录状态。

## 新证据

复用 Runtime 的现有开发凭据，对真实网关 `GET /sso-api/account/me` 连续请求两次。两次均 HTTP 200、业务 `code=200`，`content.id` 为非空字符串且相同。仅输出字段类型与不可逆 ID 摘要，未保存响应原文或个人字段值。

该响应没有 `principalId`、`openid` 或 `wxOpenId` 字段。它包含账户 ID 与姓名等账户属性，不能据此取得微信接收地址。

客户前端已经用 `account/me` 的 `userInfo.id` 调用用户关联业务。因此稳定主体并非完全缺少数据来源；`content.id` 是当前可以由服务端从已认证上游接口取得的主体候选。这个判断是基于接口实测与现有业务用法的推断，不是跨 Token 稳定性保证。

## 可采用的处理方向，待规格确认

1. 服务端用请求凭据读取 `account/me.id`，将账户 ID 与上游身份域、园区归属明确组合。Token 作为独立执行凭据加密托管；客户端提交的用户 ID 或 openid 不替代主体验证。
2. 周期计划、其管理操作与通知接收人引用稳定主体。用户重新登录后，服务端重读身份，只有主体一致且当前权限覆盖目标设备时才允许更新凭据与恢复计划。
3. 暂无刷新契约时，用明确登录失效后的停用与人工恢复闭环。网络超时、设备拒绝、权限收缩和凭据失效分别记账；不能把所有 403 或准备失败都等同于 Token 过期。
4. 现有 Token owner 的会话与历史 Task 有迁移问题。规格中先声明兼容范围与回退点，不能为了新主体键无证明地合并旧用户数据。

## 仍未实证的最小项

- 同一账户在不同有效 Token 下是否恒定返回同一 `id`，以及 `id` 的身份域唯一性。现有专属开发账号禁止为调查重新登录，因此本次不旋转 Token。
- 账户停用、Token 撤销、退出、跨端登录和授权撤销的正式后台执行政策。
- 是否提供可用且可用于后台的刷新接口；无契约时按显式恢复设计。
- 稳定账户 ID 到客户 AppID 下 openid 的可信查询/绑定路径；`account/me` 这次未提供。
