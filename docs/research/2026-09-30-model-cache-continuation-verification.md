日期：2026-09-30。任务：T03 模型缓存。状态：连续纯文本暖请求 2/2、任务查询工具链路暖请求 3/3 命中；整体缓存任务未关闭。

## 方法

复用当前 Runtime 的 `createPiAgentRunner`、`createChatModel` 和已安装 SDK，经现有模型配置分别运行三轮纯文本、两轮工具查询。模型为 `GLM-5.3-Flash`；每轮使用上一轮返回的真实 `newMessages`，当前时间随轮次变化，纯文本组的用户尾部文本也变化。系统提示词、工具定义不改，未额外注入缓存键。

纯文本组每轮仅要求回复 OK，所有物联网和任务回调均绑定为拒绝执行的探针函数，没有触发任何工具回调。工具组要求调用 `list_tasks` 查询一个本地诊断区域，只有该回调返回本地空列表，其余回调拒绝执行。两组均没有读取真实物联网/任务库、创建任务、重启 Runtime 或修改登录状态。读取模型配置时不输出密钥。

同时捕获 SDK 提交的请求结构摘要和响应原始 `usage`。只保留摘要及用量，不保存完整请求、模型密钥或客户身份。

## 结论与下一步

此前 [Runtime 前缀修复](../../../iot-agent-runtime/plan/2026-09-30-model-cache-prefix-handoff.md)在连续纯文本及任务查询工具链路获得暖请求命中证据。两组首请求均为零缓存，后续五次全部命中；这些场景没有复现暖请求零命中，不能据此继续猜测一个新原因或宣称所有请求已恢复稳定。
