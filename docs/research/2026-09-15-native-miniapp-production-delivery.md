# 原生物联 Agent：嵌入、生产环境与交付研究

日期：2026-09-15

## 结论先行

当前 `apps/agent-miniapp` 已经是可运行的独立原生页面，但它的定位应当是：

1. 独立 UI、消息流和设备操作闭环的测试/验收壳；
2. 后续合入客户小程序的页面与接口实现来源；
3. 不是可以直接切换 URL 后发布的生产小程序。

生产交付推荐走“合入客户小程序”的路径。客户小程序已经拥有生产 AppID、登录态、租户/园区上下文、菜单入口和网关配置，Agent 页面应复用这些能力。独立项目继续保留，用于不依赖客户页面的回归和模拟器验收。

## 1. 微信开发者工具的“当前用户不是开发者”

这个提示针对的是 **AppID 项目操作权限**，不是物联 Agent 的业务用户权限。

需要区分三种身份：

| 身份 | 作用 | 是否必须是客户小程序开发者 |
| --- | --- | --- |
| 微信开发者工具当前登录账号 | 打开、编译、预览、上传某个 AppID 项目 | 是；需要管理员/开发者等项目成员权限 |
| 体验版测试人员 | 使用客户 AppID 的体验版进行验收 | 不一定是开发者，但必须被加入体验成员 |
| 线上最终用户 | 使用已发布的小程序 | 不需要开发者身份 |

因此：

- 对独立测试项目，使用测试 AppID 可以规避“不是客户 AppID 开发者”的工具提示，但只能验证独立项目和固定测试身份；
- 对客户 AppID 的开发者工具验收，必须让当前微信号加入客户小程序的开发者/体验成员范围，或者由客户提供已授权的开发者工具账号；
- 对最终生产用户，这个提示不会出现，也不要求用户属于开发者名单；
- 但是测试 AppID 不能验证客户 AppID 下的真实登录链路。微信登录凭证与 AppID 绑定，测试号里的登录身份不能等价于客户小程序里的登录身份。

## 2. 当前独立项目实际做了什么

证据：

- [`apps/agent-miniapp/config/index.js`](../../apps/agent-miniapp/config/index.js)
- [`apps/agent-miniapp/manifest.json`](../../apps/agent-miniapp/manifest.json)
- [`apps/agent-miniapp/README.md`](../../apps/agent-miniapp/README.md)

当前独立项目：

- `agentUrl` 固定为 `http://127.0.0.1:3200/api`；
- 请求头固定为 `Authorization: Bearer local-development`、`Tenantcode: LOCAL`；
- 当小程序环境不是 `develop` 时，直接抛出“独立开发版尚未配置正式登录和服务地址”；
- 没有 `wx.login`、客户 SSO 换 token、刷新 token 或生产用户会话接管逻辑；
- 当前测试 AppID 是 `wx2fe182d3f1ca6e68`，不是客户小程序 AppID；
- 当前工程的成功标准是独立页面启动、消息流、草案、执行回执和模拟器闭环，不是客户 AppID 下的生产登录闭环。

所以“改一行 URL”只会改变请求目的地，不能同时解决：

- 生产身份从固定 token 切换为客户当前登录用户；
- 生产租户/园区上下文传递；
- 客户 AppID 的合法请求域名；
- HTTPS、代理超时、流式响应不缓冲；
- 生产版构建不再被开发环境保护逻辑阻断。

## 3. 客户小程序已经具备的可复用能力

客户仓库已经存在生产配置和登录态：

- `config/settings.js`：按微信环境区分 `develop/trial/release`；
- `config/index.js`：开发版指向本地 Agent，非开发版指向客户网关 `/micro-api/api/ai`；
- `utils/auth.js`：保存和读取客户登录后的授权 token；
- `store/modules/user`：提供当前用户和园区/租户上下文；
- `pages/webView/index.vue`：现有模块会在登录后读取当前 token，并向远程模块传递 `token` 与 `tenantCode`；
- `pages/index/coms/index-con.vue`：已有原生 Agent 页面入口。

这意味着生产嵌入不应另起一套微信登录。Agent 原生页面只需要复用客户仓库的：

```text
客户小程序登录
  → 客户 token / 用户上下文
  → Agent 请求封装
  → Runtime
  → 当前用户 Authorized Device Scope
```

这也符合已经冻结的领域边界：Runtime 接收当前用户身份，设备授权过滤由客户上游完成，Agent 不复制用户模板、区域人员或设备注册流程。

## 4. 推荐的两种运行形态

### A. 推荐：合入客户小程序，生产使用

适用于正式交付。

- 将 `apps/agent-miniapp/pages/agent` 的页面和组件合入客户仓库；
- 将 `apps/agent-miniapp/apis/agent` 的请求逻辑接入客户现有 `config/index.js`、`utils/auth.js` 和用户 store；
- 保留客户小程序 AppID、登录和菜单入口；
- `develop` 使用本地 Iotfake/Runtime；
- `trial` 使用客户测试网关/沙箱 Runtime；
- `release` 使用客户生产网关/Runtime；
- 通过客户 AppID 的体验版和正式版完成验收。

这个路径不要求最终用户成为开发者，也不需要独立小程序再处理一次登录。

### B. 保留：独立 Agent 小程序，测试与演示使用

适用于研发回归、视觉验收、脱离客户首页的快速测试。

- 继续使用测试 AppID；
- 继续允许固定本地身份，但仅限 `develop`；
- 如果未来需要独立项目进入生产，必须新增一套 `wx.login → 客户后端换取 Agent token` 的正式身份方案；
- 不能把当前固定 Bearer token 和测试 AppID 直接用于生产。

## 5. 环境切换不是一行 URL

应该把环境切换拆成四个明确维度：

| 维度 | develop | trial | release |
| --- | --- | --- | --- |
| 小程序 AppID | 测试 AppID或客户开发 AppID | 客户生产 AppID | 客户生产 AppID |
| Agent URL | 本地 Runtime/Iotfake | 测试网关或验收 Runtime | 客户生产网关/Runtime |
| 身份 | 固定测试身份 | 客户真实登录态 | 客户真实登录态 |
| 设备动作 | 全部模拟或沙箱 | 受控测试设备 | 客户批准的生产设备 |
| 允许操作 | 测试闭环 | 验收清单 | 正式授权范围 |

建议建立一个唯一的环境配置模块，而不是散落的 `isDev` 分支：

- `develop`：允许固定测试身份；
- `trial`：禁止固定测试身份，必须有客户登录态；
- `release`：禁止本地地址、禁止固定身份、禁止缺失 HTTPS；
- 构建时输出当前环境和后端版本标识，方便验收截图与故障定位；
- 未配置生产地址或生产身份时 fail closed，不允许静默回退到本地地址。

## 6. 必须完成的生产验证

### 阶段 0：独立项目回归

已经完成：

- 31 项源码测试；
- 微信编译产物启动兼容测试；
- 测试号模拟器页面启动；
- 消息流、处理记录、草案、控制回执和恢复逻辑的 UI 验收。

### 阶段 1：客户 AppID + 测试/验收 Runtime

必须由客户提供：

- 客户小程序 AppID 的开发者或体验成员权限；
- 一个可登录的普通测试用户；
- 测试网关地址或客户允许的验收环境；
- 允许操作的非生产设备或明确的安全测试窗口。

验收：

1. 客户登录；
2. Agent 页面打开；
3. 请求带当前用户 token 和 tenantCode；
4. 恢复/清空六小时会话；
5. 查询设备候选；
6. 生成、编辑、取消草案；
7. 确认一条安全动作；
8. 获取受理/执行/回读结果；
9. Agent 自然收尾；
10. 更换普通用户，确认设备范围随用户变化。

### 阶段 2：体验版生产链路

- 构建客户 AppID 体验版；
- 使用体验成员账号测试，不依赖开发者工具当前账号继续模拟线上用户；
- 测试真实 HTTPS 域名、网关路由、流式响应、超时、断线重连和 token 过期；
- 只允许客户批准的测试设备；
- 记录每条动作的设备、用户、时间、上游请求受理结果和状态回读结果。

### 阶段 3：正式版小范围发布

- 客户确认生产 AppID、服务器域名和发布主体；
- 发布前锁定 Runtime 版本、数据库迁移和回滚版本；
- 先以白名单或小范围用户验证；
- 验收通过后再扩大用户范围；
- 小程序版本和 Runtime 版本必须可以独立回滚。

## 7. 交付物应该是什么

后续不要只交一个编译目录或一个生产 URL，应交付一套可复现的发布包：

1. **客户端源码交付**：客户仓库中的 Agent 页面、组件、API 适配和入口 commit；
2. **Runtime 交付**：Runtime commit、环境变量清单、数据库迁移、启动方式和健康检查；
3. **环境矩阵**：develop/trial/release 的 AppID、URL、身份来源、设备范围和禁止事项；不写入 token、密钥和个人信息；
4. **接口契约**：请求头、流式 NDJSON、错误码、草案/执行/回读结果语义；
5. **验收报告**：按阶段记录账号类型、版本、时间、测试用例、设备和结果；
6. **运维与回滚手册**：如何发布、如何查看日志、如何切回上一个 Runtime/小程序版本；
7. **客户操作清单**：客户需要完成的 AppID 成员授权、合法域名配置、体验成员添加、发布审核和设备测试窗口。

## 8. 当前阻塞与下一步

当前不是“页面能否运行”的阻塞，而是“客户生产集成方式尚未走通”的交付准备问题：

1. 先冻结生产形态：推荐 A，独立项目保留为测试壳；
2. 为客户仓库建立 Agent 原生页的集成分支，不再把独立项目当生产入口；
3. 把客户已有 token/tenantCode 适配到 Agent API，并保留 develop/trial/release 三态；
4. 由客户提供 AppID 开发/体验成员权限和测试用户；
5. 部署一个 HTTPS 验收 Runtime，验证流式请求不被网关缓冲；
6. 完成阶段 1 的真实客户登录端到端验收；
7. 再进入体验版和正式版交付。

在第 4 步之前，不能声称“生产环境已验证”；在第 6 步之前，不能声称“已完成客户小程序集成”。
