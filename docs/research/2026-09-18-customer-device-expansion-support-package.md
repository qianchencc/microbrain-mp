# 客户新增设备接入支持包调查

日期：2026-09-18  
状态：支持包已形成；客户接口、权限和测试材料待补齐；未进入设备实现

## 目的

这份清单用于判断一个设备类型是否能够进入 Runtime 的真实业务闭环。判断标准不是“Swagger 中存在路径”、Provider 目录中有设备，或模型能够描述该设备，而是能否在当前用户授权范围内完成：

```text
发现 -> 稳定身份映射 -> 读取事实 -> 生成业务动作/事件 -> 权限校验
-> 执行或处置 -> 获得真实回执/恢复状态 -> 审计与前端呈现
```

设备目录、控制对象、状态对象、告警事件和业务责任人可能来自不同系统。客户需要为每个设备类型明确它们之间的映射，不能要求 Runtime 通过名称、地址或底层 ID 猜测。

## 证据等级

| 等级 | 含义 | 能否进入 Runtime |
|---|---|---|
| E0 | 合同、菜单或口头描述中提到 | 不能，只能登记候选 |
| E1 | 公网 Swagger/源码存在路径或模型 | 不能，仍无用户范围和真实响应证据 |
| E2 | 认证账号可以读取真实目录或样本响应 | 只能进入 provider 调查/只读探针 |
| E3 | 已证明按当前用户/园区过滤，并有稳定设备或计量点映射 | 可进入用户范围只读能力评估 |
| E4 | 读数/事件/控制契约、错误语义、权限和测试环境齐备 | 可进入 Runtime 适配开发 |
| E5 | 至少一条真实业务闭环通过：含回执、异常、审计和前端验收 | 可对外声明该切片已接入 |

E2/E3 不能直接对外称为“已接入”。只读、控制、告警和自动化是不同成熟度，必须分别标记。

## 所有设备类型的客户必填项

### 1. 业务与范围

- 设备类型、业务名称、服务负责人和验收负责人；
- 期望能力：查询、统计、控制、告警、自动化、报表或工单；
- 当前用户能看到的范围规则：用户、部门、园区、楼栋、楼层、区域、项目或角色；
- 设备是否允许 Agent 使用，哪些动作必须人工审批，哪些动作永久禁止；
- 测试设备与生产设备清单，包含不得操作的设备。

### 2. 身份与统一映射

- 用户范围接口及完整分页规则；
- 设备稳定主键、业务关联记录 ID、Provider 设备 ID、控制器/回路/计量点 ID；
- 父子关系：园区、建筑、楼层、区域、空间、设备、回路或传感器；
- 设备迁移、重命名、删除、替换和合并规则；
- 客户台账与 Provider 台账的映射表或查询接口；
- 不允许仅按名称、安装地址、图片或模糊文本做唯一映射。

### 3. 认证与权限

- 调用所需 Token、租户、组织和角色字段；
- 用户范围是否由上游过滤，还是需要 Runtime 传入区域/角色参数；
- 设备权限变化、离职、撤权和禁用的生效时间；
- 后台服务调用与用户实时调用是否使用不同凭据；
- Token 过期、刷新、401/403 和限流语义；
- 是否有测试租户、测试账号和可安全重复操作的测试设备。

### 4. 状态与读数

- 当前状态接口、字段字典、单位、枚举和空值含义；
- `observedAt`/采集时间、服务响应时间、数据质量和时区；
- 在线、离线、故障、未知、维护和停用的区别；
- 累计读数与区间读数的区别，是否存在总表/分表重复计量；
- 分页、排序、过滤、聚合和历史查询上限；
- 状态延迟、最终一致性和控制后预计可见时间。

### 5. 事件与告警

- 事件产生方式：推送、Webhook、消息队列、轮询或历史接口；
- 事件 ID、发生时间、接收时间、设备身份和事件版本；
- 重复事件、乱序、恢复事件、持续事件和关闭事件语义；
- 严重等级、责任人、区域范围、确认/指派/处置/关闭接口；
- 是否支持演练事件和故障注入；
- 去重、限流、升级、静默和通知渠道要求。

### 6. 控制与处置

- 动作白名单、参数 schema、范围、单位、步长和互斥关系；
- 控制接口的幂等键、重复提交、超时、取消和未知结果语义；
- 返回“已受理”还是“物理完成”，两者必须区分；
- 控制后状态/事件回读接口和最大等待窗口；
- 部分成功、批量动作、失败重试和人工接管规则；
- 高风险动作的二次确认、角色限制、急停和审计要求。

### 7. 测试与验收材料

- OpenAPI/Swagger、字段字典和真实请求/响应样例；
- 测试环境地址、测试账号、租户、Token 获取方式和合法域名；
- 至少一台可重复开关或可模拟事件的设备；
- 正常、空结果、无权限、过期、离线、超时、重复和部分失败样例；
- 控制前状态、平台受理结果、设备最终状态或事件回执的完整链路；
- 期望的 Agent 对话、富交互组件、通知和审计验收截图/案例。

## 当前设备成熟度判断

| 设备/能力 | 当前证据 | 等级 | 结论与客户补充 |
|---|---|---:|---|
| 照明 | Office 用户范围、控制接口、草案确认、真实执行和回读记录 | E5 | 已有控制闭环；仍需持续补齐不同机型状态证据、异常和策略边界 |
| 中央空调 | Office 用户范围、参数控制、真实执行和状态回读；温度已冻结为整数 | E5 | 可继续扩展状态和场景；后台自动化仍需单独授权策略 |
| 门禁 | Office 用户范围、一次开门控制和确认执行；控制结果不是门磁状态 | E5（一次性控制） | 不应包装成门状态闭环；自动开门、访客和道闸需独立风险政策 |
| 视频 | Office 用户范围/底层目录线索 | E3 | 可继续做设备发现和权限调查；缺实时流、回放、鉴权、播放和审计闭环 |
| 电表/能源 | 认证账号读到能源目录和样本读数 | E2 | 不能直接做能耗业务；需用户范围、计量层级、历史口径、新鲜度和报表契约 |
| 水表/燃气计量 | Swagger 有水气路径，未形成用户范围和真实样本闭环 | E1 | 需真实设备、单位、采样、历史和权限证明 |
| 烟感/消防/燃气/水浸 | 感知服务有设备、告警和处置路径线索 | E1/E2 | 不能直接接入告警；需事件生命周期、责任人、演练和通知安全契约 |
| 环境/温湿度 | 环境接口声明和底层线索 | E1/E2 | 需确认具体传感器、区域映射、读数新鲜度和权限 |
| 人数/密度 | 合同和业务设想，未确认稳定统计接口 | E0/E1 | 不能从普通视频目录推导人数；需客户提供统计接口和隐私规则 |
| 道闸/停车 | 合同和场景提及，当前无稳定业务契约 | E0 | 需设备、动作、状态、车辆/访客身份和安全审批契约 |
| 显示屏/投影/窗帘/新风 | 下沉业务候选，无现场接口证据 | E0 | 先确认设备清单、客户价值和接口，再决定是否调查 |

## 现有接口能否顺利接入 Runtime

### 可以沿用现有适配器闭环的部分

照明、空调和门禁已经证明了当前 Runtime 的核心接入模式：

- 以 Office/工作区用户范围接口作为 Authorized Device Scope；
- Provider 映射只补充控制对象和状态来源，不扩大用户设备范围；
- 先检索和能力核验，再生成不可执行草案；
- 用户确认后执行，再通过状态或回执如实收口；
- 生产控制不把“平台受理”冒充为“物理完成”。

新增设备若能提供同等级的用户范围、统一 ID、状态/事件和控制契约，原则上可以复用这一适配器边界。不能仅通过添加 `DeviceKind` 枚举接入。

### 目前不能直接接入的部分

- `api-iot-center`、`api-perception`、`api-energy` 的底层目录不能替代 Office 用户范围；
- 能源接口名称包含 `realTime` 不等于数据实时，现有样本的 `readTime` 曾明显滞后；
- 感知空调状态接口曾返回记录但关键遥测字段为空；
- 视频目录不等于可播放视频流；
- 告警路径不等于告警生命周期和通知渠道；
- GET 形式的场景/状态切换接口不能未经确认当作无副作用查询或可安全执行动作；
- 事件、告警和自动化需要长期运行、责任人、通知和恢复语义，不能塞进六小时聊天会话。

## 建议客户提交的设备接入表

客户可以每种设备填写一行，缺失项明确标记“没有”而不是留空：

| 字段 | 示例 |
|---|---|
| 设备类型/业务名称 | 电表 / 分项能耗 |
| 目标业务闭环 | 查询、日报、异常告警、人工确认 |
| 用户范围接口 | 方法、路径、过滤字段、分页和权限 |
| 稳定身份 | 设备 ID、计量点 ID、区域 ID、父子关系 |
| 状态/读数接口 | 字段、单位、采集时间、空值和质量 |
| 事件/告警接口 | 事件 ID、等级、恢复、确认、指派、关闭 |
| 控制接口 | 动作、参数、幂等、受理/完成和回读 |
| 权限与风险 | 角色、审批、急停、不可执行动作 |
| 测试条件 | 测试账号、租户、设备、沙箱、故障注入 |
| 验收证据 | 请求响应、日志、截图、预期业务文案 |
| 客户负责人 | 接口、业务、运维和验收联系人 |

## 当前决策

- **已确定**：设备扩展按“用户范围 + 统一身份 + 状态/事件/控制 + 业务验收”判断，不按枚举或 Swagger 数量判断。
- **已确定**：现有照明、空调、门禁继续作为 E5 基线；视频、能源和安全设备不能被概括成同一成熟度。
- **已确定**：客户支持包必须按设备类型提交，至少包含测试账号、样本、权限、失败和验收资料。
- **待客户确认**：下一批真实优先设备类型、目标业务闭环、用户范围接口、数据新鲜度和安全责任人。
- **未进入实现**：本轮不新增设备枚举、不修改 Authorized Device Scope、不把底层 Provider 目录回填成用户设备范围。
