# 物联系统 Agent 合同设备与能力审查

首次审查：2026-09-11；补充核验：2026-09-14  
审查对象：《2026.8.28物联系统Agent开发合同-修改建议》  
性质：技术范围与交付现状审查，不构成法律意见。

## 一、结论

合同正文承诺的是一个包含设备控制、能耗、视频与消防安全联动、自动化策略、权限审计和急停的完整物联系统 Agent，不只是门禁、空调、照明三类设备的对话控制。结合 2026-09-14 对客户权限模型的澄清，Agent 的设备范围应以办公室/工作区接口为准，云起只作为其背后的控制 provider。

当前代码已经形成可验证闭环的范围主要是：

- 门禁、中央空调、照明三类 `api-office` 设备的账号范围目录、模糊检索、能力核验、操作草案、用户确认、指令下发、受理回执、Agent 自然收尾和本地审计；
- 空调温度 16–30℃ 校验、模式、风速、电源控制；
- 门禁开门及 1–5 次、每次间隔 5 秒的本地草案语义；
- 原生微信小程序中的对话、设备卡片、草案确认和复杂设备参数编辑；
- 本地 Iotfake 中三类设备的账号隔离、控制校验、影子状态和故障注入。

合同中下列部分尚不能认定为完成：

- 道闸；
- 水表与完整能耗模块；
- 视频实时预览、历史回放；
- 人员统计与密度分析；
- 烟感、燃气报警和联动处置；
- 设备台账、定时/场景/条件策略及自动化联动；
- 按工具、设备类型或整体关闭控制能力的急停；
- 面向客户的审计查询、导出和留存管理；
- 集团 AI 门户应用地址、生产部署、培训和完整验收资料。

因此，若以合同正文 2.1–2.6 和 3.1 的字面范围验收，当前实现存在明显范围缺口。若项目实际约定只是先交付办公室范围内的三类设备控制闭环，则需要通过附件一、书面设备基线或补充协议把一期范围重新锁定，不能仅依赖“预留接口”表述。

### 3.1 “设备可见”不等于“设备已接入”

当前测试账号已能跨 `api-office`、`api-iot-center`、`api-perception` 和 `api-energy` 读取较广目录，但 Runtime 的领域类型仍只有：

```text
lighting | ac | access
```

模型可调用的控制工具也只覆盖这三类。其余 333 台通用设备中的监控、能源、消防和环境设备目前没有进入 Agent 的正式发现、能力核验和草案模型。

### 3.2 空调与照明存在多目录口径

客户系统对同一类设备提供了 office 关联记录、物联中心底层设备、感知设备和照明回路等多层对象。它们不是天然一一对应：

- 空调：office 53 条，而底层空调/控制器约 66 个；
- 照明：office 159 条、底层开关 136 个、感知设备 132 个、回路 129 个。

合同中的“设备台账”要求先冻结统一设备标识、父子关系和控制对象。否则搜索得到的是“区域关联记录”，状态查询返回“控制器/回路”，审计记录又引用另一种 ID，无法形成真正的全链路追溯。

### 3.3 办公室范围接口族与云起面板的边界

2026-09-14 从客户小程序实际加载的 owner 子应用 `pages/office/index` 核验到：“我的办公室”先查询当前用户办公室，再按办公室标识查询空调、照明、门禁和监控。空调使用专用办公室分页；其他三类使用统一办公室设备分页并按类型/子类筛选。

当前测试账号从“我的办公室”页面来源观察到 1 个办公室和 7 台设备：2 台中央空调、3 台照明、2 台门禁、0 台监控。这 7 台设备只是该页面来源样本，不是 Agent 的地点隔离边界。Agent 使用客户小程序当前登录用户对应的用户设备接口集合，客户上游负责设备授权过滤；管理端 137 条注册记录和云起 333 台底层设备仍只作为管理/provider 诊断证据。

“智慧空调”“智慧照明”“智慧门禁”“智慧监控”等入口直接进入云起面板，不是 Agent 范围来源，也不需要 Agent 复刻。办公室层同级接口需要建立来源清单并聚合；此前根据这些页面或无完整上下文的 `myAreaList` 204 推断“我的办公室分配为空”的结论已经撤回。

## 五、已实现部分的验证结果

## 六、合同内部的范围与验收风险

### 6.1 “预留”与“本期完整交付”同时存在

合同 3.1（2）说对视频、消防、道闸、水电表“预留扩展设备接口”；但 3.1（3）至（5）又把完整能耗模块、自动化控制、视频和安全联动列为本期纳入范围。

这两种表述的工作量和验收结果完全不同。必须书面明确：

- “预留”是否只要求 adapter/类型扩展点；
- 还是必须接入真实设备并通过功能验收；
- 若接口或设备未提供，相关模块如何验收或顺延。

### 6.2 开放式设备范围与变更收费冲突

2.2 和 3.1（6）使用“包含但不限于”“其他物联设备接入”；5.2 又规定新增设备类型、接口、自动化联动需要变更单。

应以签约时的书面基线表列清：设备类型、接口版本、动作、数据字段、数量和园区。未列入基线的才属于新增，否则“包含但不限于”会使范围无法冻结。

### 6.3 状态能力一方面被排除，一方面又是其他模块前提

3.2（2）和 7.3 排除了接口未证明的实时温度、开关状态、在线状态和物理执行结果；但 2.3、2.4、2.5 又要求实时监测、异常告警和基于设备状态的自动联动。

需要把验收分成：

1. 指令是否被客户平台受理；
2. 平台是否提供当前状态；
3. 是否能证明物理设备达到目标；
4. 状态数据的最大允许延迟。

否则自动化和能耗模块没有可靠触发依据。

### 6.4 “急停”“审计”“回退”没有可执行定义

正文只写了目标，没有定义：

- 急停由谁触发，停哪些工具，是否影响已下发命令，如何恢复；
- 审计保留多久、谁能查询、是否导出、如何关联客户平台日志；
- 回退针对软件版本、配置、草案还是已执行设备动作。

这些都是验收项，必须转成具体测试用例。

### 6.5 工期与报价同范围不匹配

合同写明 6 周、38 人天、4 万元，且包含控制、视频、安全联动、完整能耗、自动化、权限、审计、急停、小程序、部署、培训和验收。以当前接口成熟度看，这一范围无法仅靠“接接口”完成：能源指标模型、视频播放、安全事件状态机、调度器和生产权限都属于独立业务闭环。

从技术交付风险看，应拆阶段、锁基线和设置客户依赖条件；否则任何一个上游接口不完整都会直接挤压开发和验收时间。

## 七、建议立即向客户索取和确认

### 7.1 首要材料

1. 完整附件一《物联系统 Agent 技术方案及报价 v2.1》，尤其是接口清单、交付物和验收标准。
2. 签约基线设备表，至少包含：设备类型、业务名称、设备/区域 ID、数量、位置、查询接口、状态接口、控制接口、可执行命令、风险级别、责任人。
3. 用户—角色—设备范围的正式权限矩阵和稳定用户主体 ID；Bearer Token 获取与刷新流程不能代替用户身份定义。
4. 每类接口的业务码字典、超时语义、幂等键、请求 ID、最终结果查询/回调和限流说明。

### 7.2 三类现有控制设备

1. 门禁 `devicePage` 对全部区域返回 204 的原因；该接口是否废弃，是否应统一使用 `accessAreaDevice/page`。
2. 空调 11 条运行状态记录为何所有核心字段为 `null`；53 条 office 空调与 66 个底层空调/控制器如何映射。
3. 照明 159 条 office 记录、136 个底层开关、132 个感知设备和 129 个回路的对应关系。
4. 控制接口返回成功究竟表示“请求已受理”“平台已下发”还是“设备已完成”；是否存在结果查询或回调。

### 7.3 能耗

1. 43 台设备是否全部为电表；水表数量和接口在哪里。
2. `realTimeRead` 样本时间停留在 2024-09-10 的原因、正常刷新频率和历史查询范围。
3. 电量、功率、分时电量、同比环比、单位面积能耗的正式指标定义。
4. 园区/楼栋/楼层/区域层级和建筑面积数据来源。
5. 报表模板、导出格式、最大查询跨度、数据补录和修正机制。

### 7.4 视频与安全

1. 视频设备目录、实时流、历史回放、抓图接口及可供小程序播放的协议和鉴权方式。
2. 人员统计接口、区域映射、更新频率、密度阈值和隐私要求。
3. 烟感、燃气报警事件接口或消息订阅、事件生命周期、处置动作和演练数据。
4. 消防联动允许控制哪些设备，谁确认，谁急停，异常时如何人工接管。

### 7.5 自动化与平台能力

1. 一期必须验收的场景/定时/条件规则清单，不接受仅以“支持自动化”概括。
2. 调度执行环境、失败重试、重复触发、冲突优先级、节假日和停用规则。
3. 急停的权限、粒度、恢复流程和审计要求。
4. 日志保留周期、查询/导出权限、敏感字段脱敏和数据出域规则。
5. 最终小程序归属、生产 AppID、发布主体、集团 AI 门户收录地址与上线流程。

## 八、建议的落地分期

若合同尚可调整，建议按可验收业务闭环拆分：

### 第一期：三类设备安全控制闭环

- 门禁、空调、照明；
- 统一身份与账号设备范围；
- 设备搜索、歧义澄清、草案、确认、执行回执；
- 审计查询和控制急停；
- 原物联小程序生产集成；
- 真实设备小范围验收。

当前实现最接近这一阶段，但仍需生产身份、状态/结果语义、急停、审计交付和正式部署。

### 第二期：只读台账与能耗查询闭环

- 统一底层设备与业务关联记录；
- 电表/水表数据接入和数据新鲜度治理；
- 指标语义层、自然语言查询、基础告警和报表；
- 暂不自动控制设备。

### 第三期：视频、安全事件与自动化

- 视频预览/回放；
- 人员统计；
- 烟感、燃气事件和人工处置；
- 定时、场景、条件策略；
- 在状态和能耗数据可靠后，再做自动联动和消防联动。

如果合同不调整，则上述第二、三期都属于当前合同未完成项，需要纳入剩余工期、客户依赖和验收计划，不能作为普通“扩展设备适配”处理。
