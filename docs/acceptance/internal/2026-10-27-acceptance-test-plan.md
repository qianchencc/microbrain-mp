### 2.4 明确不予验收的内容（附件一 §三 3.2、§八 验收说明、合同 7.3）

- 现有平台、设备固件、网关、通信协议、硬件、网络与既有业务规则的建设、改造、修复；
- 接口未返回的实时温度、开关/在线状态、能耗指标、视频或人员统计结果、报警状态、策略执行状态、指令最终到达与物理执行结果；

- 第三方接口耗时与设备响应时间（单独记录，不计入我方服务处理耗时）；
- 底层算法准确率、平台内部计算过程、指令物理执行效果。

## 4 验收准入条件

### 4.1 通用准入（三个节点均适用）

1. 当次验收基线版本已部署，版本标识、发布时间、回退锚已书面记录；
2. 我方自动化回归全绿，并附当次测试记录（编制时基线：Runtime 426/426、小程序 177/177；验收时以当次运行结果为准，不得引用历史数字代替）；
3. 验收环境、账号、设备、网络可用，且与生产同一配置口径；验收数据不写入生产审计的业务语义之外；
4. 上轮缺陷已关闭或有书面处置，遗留清单已确认；
5. 验收申请、证据包、缺陷清单已提前 3 个工作日提交。

### 4.2 G1 试点版本验收

- 准入：阶段 0 的《接口与工具矩阵》《设备/数据/权限清单》已双方书面确认；试点区域、试点用户、试点设备清单已确认；
- 完成条件：至少一条查询链路与一条控制链路端到端打通（附件一 §七 阶段 1/2 完成条件）；
- **控制类真实执行前提**：客户书面授权具体设备与时间窗口；门禁开门需现场人员与应急措施到位。

### 4.3 G2 生产验收

- 准入：G1 缺陷 A/B 级清零；生产环境、真实身份、真实设备就绪；微信真机可用；报告附件在线下载可用；
- 完成条件：全量用例执行一轮（GB/T 15532 第 9 章、JR/T 0175 准出口径），证据等级达到 E4（见 §6.3）。

### 4.4 G3 试点结束移交

- 准入：G2 通过；建议试运行 ≥30 个自然日并出具《试运行报告》（周期需双方确认；GB 50339-2013 3.3.9 要求规定周期连续试运行并留记录）；
- 完成条件：§11 交付物全部移交并签收，源代码可编译、可运行、可维护（合同 3.4）。

## 5 验收方法

### 5.1 双轨：验收测试 + 验收审查

依 HJ 728-2014 4.2.4 的通行做法：

- **验收测试**：按 §8 用例执行，覆盖功能、调用正确性、权限、安全、稳定性；
- **验收审查**：文档审查（接口、部署、运维、培训）、配置审查（工具白名单、参数范围、凭证管理）、一致性审查（三处设备标识口径、报表值与平台响应）。

### 5.2 环境与身份

| 项 | 要求 |
| --- | --- |
| 生产环境 | 客户可访问域名 + 真实身份；不得以 `local-development`/`local-test`/`LOCAL` 租户作为验收身份 |
| 测试账号 | 至少 3 个不同权限的用户身份（含一个越权场景身份），用于权限正反向 |
| 设备 | 每类受控设备至少 1 台真实设备；批量/策略场景按书面清单 |
| 网络 | 小程序真机 4G/5G 与 Wi-Fi 各一次（附件一 §十一「模型与网络」） |
| 故障注入 | 超时、鉴权失败、资源不存在、上游 5xx 各 1 次（可在我方隔离环境模拟，但需说明注入点） |

### 5.3 证据分级（贯穿全部用例）

| 等级 | 含义 | 可否作为验收证据 |
| --- | --- | --- |
| E1 | 源码与单元/集成测试 | 否，仅支撑 |
| E2 | 隔离环境/夹具/模拟上游 | 否，仅支撑 |
| E3 | 生产服务 + 真实上游接口（只读或真实身份） | 是（查询类、展示类） |
| E4 | 生产服务 + 微信真机/真实受控设备 + 现场见证 | 是（控制类、视频类、交付类） |

**控制类用例必须达到 E4。** 只到 E3 的控制类用例记为「未验收」，不得以「接口已受理」替代物理结果（附件一 §三 3.2、§八 验收说明）。

### 5.4 性能的处理

附件一未约定量化性能指标，本方案**不设通过性阈值**，只做记录：分别记录①我方服务处理耗时（不含第三方）、②第三方接口耗时、③端到端耗时。记录值进入验收报告「性能记录」表，供双方后续优化决策；我方处理耗时单独归因，不因第三方慢判为不合格。若双方希望设阈值，需在 G1 启动会书面补充。

判定准则来源标注：**【原】**＝附件一 §八 原文要求；**【细】**＝本方案细化，需双方书面确认。

> 口径说明：合同 7.1 概括为「七类验收项」（功能、控制正确性、权限、安全、稳定性、审计、回退）；附件一 §八 表另有 3 行能力域验收项（能耗与报表、视频与人员统计、报警与自动化），合计 10 项。本方案按 10 项执行，与合同 7.1 的七类为包含关系，不新增范围。

| # | 验收项 | 判定准则 | 来源 | 用例组 |
| --- | --- | --- | --- | --- |
| A1 | 功能 | 范围基线 V0 内场景**全部**正确路由；歧义时**不擅自调用**控制工具 | 【原】 | AT-FN |
| A2 | 调用正确性 | 平台、对象、动作、查询维度、参数符合白名单与接口约定；**写操作 100% 经草案+独立确认**；非法/缺失/越界参数**调用前拒绝** | 【原】 | AT-CL |
| A3 | 权限 | 不同用户仅能访问其授权设备、能耗数据、视频通道、报警与策略；**越权请求 0 放行**，且留拒绝记录 | 【原】 | AT-PM |
| A4 | 安全 | 门禁、批量、自动化等高风险操作按确认规则执行；提示注入、重放、并发不能绕过限制；**凭证明文 0 例**（抽查 ≥20 条日志） | 【原】 | AT-SC |

| A7 | 回退 | 可按工具/能力域/整体关闭 Agent 查询与控制，且不影响各现有平台独立使用 | 【原】 | AT-RB |
| A8 | 能耗与报表 | 按授权范围与确认口径调用现有平台，返回值、指标、文件与平台响应一致 | 【原】 | AT-EN |
| A9 | 视频与人员统计 | 授权通道可打开现有平台预览/回放资源；人数/密度结果与来源接口一致 | 【原】（人员统计未交付，见 2.3） | AT-VD |
| A10 | 报警与自动化 | 报警可查询/接收；处置、批量、策略操作完成预览、确认、调用、结果反馈与急停 | 【原】（处置与急停未交付，见 2.3） | AT-AL |

### 6.1 主控项目与一般项目

- **主控项目**（任一项不合格即当次验收不合格）：A2 调用正确性、A3 权限、A4 安全、A6 审计、A8 数据一致性（能耗/报表与平台响应一致）。
- **一般项目**（两项及以上不合格即不合格）：A1 功能交互细节、A5 稳定性（非崩溃类）、A7 回退、A9 视频呈现、A10 报警与自动化呈现。
- 依据 GB 50339-2013 3.4.4 的主控/一般判定制；分级映射为本方案细化【细】。

### 6.2 抽样与回归

- 每个用例组至少执行 1 条主路径 + 1 条反向路径；权限组按权限矩阵全量执行，不抽样；
- 批量与集合类场景按书面清单抽样，抽样数不少于 3 且覆盖多楼层/多区域；
- 缺陷修复后须回归该用例及其所属组的调用正确性用例（防「修一个坏一片」）；
- 复测时抽检数量加倍（GB 50339-2013 3.4.4 同口径）。

## 7 缺陷分级与准出

| 等级 | 定义 | 示例 | 处置时限（建议） |
| --- | --- | --- | --- |
| A 致命 | 越权放行、未确认即下发控制、数据错报导致业务决策错误、密钥泄漏、服务不可用 | 越权用户成功控制他区设备；确认前已下发 | G1 立即停止验收并整改 |
| B 严重 | 主控项不满足；受控场景无法完成；错误反馈缺失导致误判 | 门禁确认后无回执或回执与实际相反 | 5 个工作日内 |
| C 一般 | 一般项不满足；可绕过但不影响安全与数据正确性的交互缺陷 | 歧义候选排序不合理 | 10 个工作日内 |
| D 轻微 | 文案、样式、提示措辞、日志字段顺序 | 提示语句不通顺 | 记录，可延至质保期 |

**准出条件**【细】：A、B 级缺陷为 0；C 级修复率 ≥90% 且其余有书面替代措施与期限；D 级全部登记；主控用例执行率 100%、通过率 100%；一般用例通过率 ≥95%；需求/用例覆盖率 100%（对 V0 范围基线）。缺陷分级采用「致命/严重/一般/轻微」四级，与 HJ 728-2014 附录 A.4、JR/T 0175 附录 F 的行业分类一致。

**不通过的处理**：乙方在约定时限内整改并重新申请复验；复验只跑失败用例 + 回归组 + 抽检加倍。连续两轮仍不通过，触发合同 7.2(3) 与 11.2 流程。

## 8 验收程序与进度

```text
G0 验收准备（T-10）
  └─ 确认 V0 范围基线、未纳入项处置(顺延/变更/豁免)、试点清册、验收人员
G1 试点版本验收（阶段 2–3 完成后，3 个工作日）
  ├─ 提交申请与证据包 → 资料审核 → 现场执行 AT-FN/CL/PM/SC/AU 主路径
  ├─ 缺陷清单确认 → 整改 → 复验 → 签署《试点版本验收记录》
  └─ 付款节点 2（合同 5.3：30%）
G2 生产验收（G1 通过后，5 个工作日）
  ├─ 全量用例（含 E4 控制类、真机、视频、报表下载）
  ├─ 验收审查（文档/配置/一致性）
  ├─ 缺陷处置 → 复验 → 签署《验收报告》
  └─ 付款节点 3（30%）
G3 试运行与移交（建议 ≥30 天）
  ├─ 试运行记录与报告 → 培训与运维交接
  ├─ 源代码与技术资料移交（合同 3.4：终验通过后 5 个工作日内）
  └─ 付款节点 4（10%）
```

时限与视为通过：甲方应在收到验收申请后 **__ 个工作日**内组织验收（合同 7.2(2) 空白待填）；甲方无正当理由逾期不组织验收或未提出书面异议的，视为验收通过（合同 6.1(5)、7.2(4)）。项目验收结果公告义务仅适用于政府采购公共服务项目，本项目不适用。

## 9 风险与依赖（与验收直接相关）

| 风险 | 对验收的影响 | 处理 |
| --- | --- | --- |
| 真实设备/现场窗口不到位 | C4 门禁等控制类无法达到 E4，主控项无法判定 | G1 启动会锁定设备、时间、现场责任人；否则该项记「未执行」，不计通过 |

| 上游数据滞后/停报 | A8 一致性判定失去基准 | 以「与平台响应一致」判定，不以数新鲜度判定；停报期单独记录 |
| 上游接口变更 | 用例执行受阻 | 冻结版本与接口样例；变更走变更单 |
| 模型服务不可用 | A5 稳定性与 A1 功能受影响 | 记录为环境事件，重跑；不计入乙方处理耗时 |
