# Agent Page Notes

- 会话相位（2026-09-16 定稿，零滞留）：待确认草案期间可以继续发消息，但下一条消息会把旧草案退役为已取消（跨轮 `action.resolved` 即时转只读），模型总是重新起草；只有执行中/运行中会被服务端 409（`CONVERSATION_AWAITING_CONFIRMATION`，前端撤回乐观轮次并 toast）。不要按"有待确认草案就禁用输入栏"，也不要复活非末轮的过期草案。
- 微信分块事件的 `data` 是 `ArrayBuffer`，中文 UTF-8 字节可能跨 chunk；所有 NDJSON 解析继续复用 `apis/agent/ndjson.mjs`。
- Android 优先消费 `onChunkReceived`，其他平台保留完整 response 回退，两条路径必须产生相同业务事件。
- 开发凭据和生产登录态只在 `apis/agent/index.js` 组装，页面与组件不接触 header。
- `ACCEPTED` 表示上游受理，界面保留“暂无物理状态回执”说明；只有待确认卡片可发起真实控制。
- 恢复会话时以服务端 `draft/result` 为准；历史事件只恢复轨迹和正文，不能把已执行草案重放成待确认。
- 选项更新和确认携带最新 revision；执行结果的 summary 由服务端生成，重试回答不得重发设备控制。
- 设备卡徽标状态合并两个来源：`GET /device-states` 的最后已知值兜底，`result.observedStates`（confirm 回读时刻的权威读数）覆盖胜出且只取非空项（`device-card-state.js` 的 `mergeObservedStates`）。两处消费者（`ActionDraftCard`、`DraftSheetLayer`）都必须在 `result` 落地时先同步合入再异步补查，禁止只等下一次 GET——否则回执已出而徽标仍按指令前快照渲染（2026-09-17「确认后仍显示已开启再翻已关闭」根因）。
- 草案「还原」（全部设备面板右上角，仅在有改动时出现）：服务端 `POST /action-drafts/:id/restore` 原子恢复发布时刻的勾选+指令+summary/question（`original_json` 快照，提案落库时写入，旧库迁移回填当前态为基线）；客户端 `draftBaselines` 快照只做按钮显隐的 dirty 判定（`action-draft-presentation.js` 的 `createDraftBaseline`/`draftBaselineChanged`），权威还原始终于服务端；还原可逆故不加二次确认。
- 独立项目构建和验收边界见项目根目录 `README.md`；H5 预览不是小程序验收。
- 输入栏切换语音会卸载 textarea，键盘收起不能只依赖 textarea 的事件；页面监听键盘高度并在卸载时移除监听。
- WechatSI 只能在用户开始录音时延迟加载；测试号未注册插件时保留文字输入。授权前松手、切后台和触摸取消都必须丢弃已取消的识别结果。
- 编辑/重试只作用于最后一条未产生草案的失败回合：先用服务端 `turnId` 丢弃失败记录，再复用同一个前端 turn 原位启动；禁止保留失败轮后追加一条重复消息。
- `AgentReplySurface.vue` 是身份、轨迹、正文、草案和执行收尾的唯一编排层；不要再把这些区域直接拼回页面，也不要恢复按会话随机生成头像。
- 设备卡片：选择走原生 `@tap`；touch 流驱动长按进度环（360ms，进度 ≥90° 才渲染），原生 `@longpress` 作为微信 `scroll-view` 内的可靠完成信号；二者统一进入幂等 `completeHold`。一旦进入 `committed`，后续 `touchcancel/touchend` 只能清理视觉状态，禁止撤销 configure（2026-09-16「长按后环闪一下、筛选消失但编辑器未进入」根因是完成后 24ms 定时器被 touchcancel 清除）。监听一律**不带 .stop**，位移 >14px 在提交前视为滚动并取消，随行 tap 用一次性 `holdDone` 屏蔽。禁止 catch 触摸事件、禁止 suppress 时间戳。
- 设备卡片高度统一 180px，不因设备类型加高；当前状态未知时正文不渲染"状态未知 →"起点（只保留图上角标一处），避免与指令目标（如"开启 · 25°C"）并列造成误读。
- 草案手轨的边缘渐隐必须用 alpha mask（`.rail` 上的 `-webkit-mask-image`/`mask-image` 线性渐变，两端各 20px），让卡片内容连同描边整体透明渐隐；禁止用 `::before/::after` 色带覆盖层（半透明底色叠在卡片上会透出描边/图片残留细线，且与 overflow 裁切叠加产生脏边）。
- `DeviceSheet.vue` 使用官方 `@dcloudio/uni-ui` 的 `uni-popup` 作为底部面板底座，统一接管遮罩、层级、外部点击和进退场；横杆下拉只保留 WXS 渲染层手势适配。每次 `configure`/`browse` 必须递增并透传独立的 `openRequest`，`draftId/open` 只表达面板归属与期望状态：同一草案二次点击仍要重新驱动 `ensureOpen`，并先清除可能失真的 `visible` 反馈，让 350ms 重试跨过 uni-popup 的 300ms 关闭窗口；回归契约见 `test/agent-sheet-reopen.test.mjs`，编译保真见 `test/compiled-bottom-sheet.test.mjs`。若新增 uni-ui 组件，必须同步维护 `pages.json` 的 Easycom 映射并在微信构建产物中确认其内部依赖已编译。
- 面板内容统一由页面根部的 `DraftSheetLayer.vue` 渲染（在 composer 之后），`ActionDraftCard` 只通过 `configure`/`browse` 事件请求打开；打开面板要求草案 PENDING_CONFIRMATION，但打开后面板跟随轮次上的草案对象本身——过期不再踢掉面板，转为只读 + 面板内"重新核验"提示（核验成功原地恢复可编辑）；仅当草案被新提案取代（draftId 消失）或轮次清理时自动关闭。
- 面板的关闭操作（遮罩点击、横杆下拉）永远允许，不受 busy 限制——busy 卡死时用户必须始终能退出。**面板不设 × 按钮**（2026-09-16 统一底部面板）：横杆是唯一拖拽抓取区，标题、筛选和搜索控件不再参与拖拽；遮罩+横杆两条关闭路径已够（对齐 Kitze Bottom Drawer 的独立 backdrop / popup 结构），禁止再加回。
- 原生 input/textarea 一律非受控写法：`@input` 只向上同步文本，禁止把回流值直接写回 `:value`——bindinput 在拼音组合中态也触发且 `detail.value` 携带原始拼音，写回等同于向 IME 强制提交组合中文字（2026-09-17「打字中拼音直接上屏、发送时拼音与字一起进消息」根因）。程序性改写（发送清空、恢复草稿）经 `field-echo-guard.mjs` 的 `createFieldEchoGuard` 判定后才写 `:value`；`@confirm` 先以 `detail.value` 同步再提交。`UserMessage` 编辑器同规则（`draft` 仅进入编辑/取消重置时写，`fieldText` 跟踪实况供禁用态与提交）。
- 输入栏 textarea 常驻（v-show 切换语音胶囊），避免原生组件重挂载闪烁；**全项目 textarea 统一走系统 `adjust-position` 上推**（composer 含 `cursor-spacing` 控制胶囊与键盘间隙）。禁止回退到 `keyboardheightchange` + 手动压短页面高度 + CSS 过渡的补偿方案——该事件是事后回调、不与键盘动画逐帧同步（iOS/Android 时机还不同），真机上永远"追键盘"（2026-09-17 真机反馈根因）；也禁止挂全局 `uni.onKeyboardHeightChange`，会与系统上推叠加把页面压短留出黑洞。
- 折叠面板（处理记录）不要用 `grid-template-rows: 0fr/1fr` 过渡（小程序内核不动画），也不要用"selectorQuery 实测高度驱动 + height:auto 切换"——多轮同构组件下类名选择可能选错实例、且测量与内容增长有时间差，切换瞬间会凭空多出空白；用 `max-height: 0 ↔ 640px` 过渡（overflow:hidden，盒子高度恒贴合内容），折叠箭头用单图标 rotate(180deg)，禁止 up/down 字形互换（会引发布局跳动）。
- 底部面板（DeviceSheet）结构铁律（2026-09-16 统一成熟弹层底座）：① 官方 `uni-popup` 负责遮罩、层级、外部点击与 300ms 底部进退场；② WXS 只负责 handle-zone 的下拉跟随、向上阻尼、flick/阈值判定和 300ms 回弹，关闭通过组件方法回到逻辑层；③ 关闭=遮罩 tap + 横杆下拉，永远不被 busy 门控；④ 拖拽只认 handle-zone 全宽 44px 条带，标题、槽位内容、交互控件都在拖拽区之外；⑤ 面板内 scroll-view 禁用 `enhanced`，避免原生滚动层抢占周边触摸。
- 卡片单击选中的链路本身可靠；历史上"点不动"的三个真因：①草案已过期（服务端拒绝后静默回滚）——selectDraft 现在有过期预检 + toast + restore 重同步；②busy 锁（mutating/执行中/僵死 running）期间全部禁用；③服务端 conversation.running 在客户端断流后可能长时间不回收——stopRun 对无本地请求的僵死状态做本地解锁（staleRunSince 5 分钟内忽略）。
- 只有存在两个或以上同类动作时才显示“应用到全部同类设备”开关；单设备配置不显示一个不可用的伪控件。
- 全部设备面板由一份设备列表面与一个参数编辑面组成；搜索只是列表面的内部状态，禁止复制第二份列表。两面保持挂载并以 `transform` 做 240ms 可逆横向过渡，编辑页返回记忆来源页 `editorBack`；`.pages` 必须 `isolation:isolate`，设备面/编辑面必须各自拥有不透明 `#fcfdfc` 画布并固定 z-index 0/1，禁止透明 surface 让筛选、卡片与浮动按钮穿透编辑器。**禁止在面板内使用 swiper**：swiper 是原生手势组件，其手势识别会在原生层抢占整个面板的触摸流——横杆拖拽在含 swiper 的面板完全失效，而不含 swiper 的单设备面板正常（2026-09-17 用户三次实测「两者横杆交互完全不同」的真因；Taro #7677 为同类案例）。**禁止再引入控件行内原位展开搜索**（两层绝对定位交叉溶解方案已废——曾致真机图标 320×240 缺省尺寸撑爆面板）。头部固定「标题行 + 胶囊行」（2026-09-16 拟物重塑）：标题行=大标题 + `meta` 小字（标题下方，副标题仅单设备配置用）+ 右上「全选/取消全选」胶囊（`#header-right` 槽，无关闭钮——遮罩/横杆是出口）；胶囊行=区域/类型/选择三枚分组胶囊靠左排布（选中态实底绿）+ 尾随 32px 搜索圆钮（14px 图标），放在设备列表面正常 flex 流内，禁止再经跨组件 `#header` slot 反撑高度；搜索展开仍走 `header-viewport` 变形动效，进入编辑面时随列表整体左移，返回普通列表即清搜索词。浏览列表不放假期/取消状态条（toast 类播报多余，状态由卡片相位表达）。面板高度 `tall`=**78vh**（顶边须让出小程序胶囊区，92vh 会重叠；且必须保持 `:class` 绑定——只写 CSS 不绑类 = 高度链断裂、列表塌陷）。底部操作区为悬浮式拟物主动作（2026-09-16）：`.confirm-float` 绝对定位浮于列表底（透明→面板色渐隐过渡带防文字撞钮，`pointer-events` 只放行按钮），胶囊 `确认草案 · N`（min-width 216/高 52/暖纸白渐变 + 双层软阴影 + 顶部内高光，按压 scale(.965) 阴影收敛）+ 下方「已选择 N 台设备」小字；禁用逻辑不变（`busy || !pending || !selected.length`）；scroll-view 末尾 `.list-tail` 108px 留白防遮挡；不再有底栏「关闭」钮（出口=遮罩+横杆）。浏览网格按视口动态计算居中轨道：卡片规格永远为 119×180px、gap 12px、内容边距 20px，`columns=floor((available+gap)/(119+gap))`，轨道宽=`columns*119+(columns-1)*gap`；320/375px 为 2 列，430px 为 3 列。所有分组共享轨道宽，末行与单卡从轨道左槽开始；浏览卡禁止传 `fluid` 或用百分比拉伸，聊天手轨同样保持 119px。`.device-list` 用 `::-webkit-scrollbar{display:none}` 隐藏滚动条——DevTools 桌面滚动条会吃掉右侧 ~15px 可见边距。
- 全部设备列表的滚动提示为「浮标 + 底缘渐隐」双通道（2026-09-17 用户实测"没发现下面还有"）：`.cue-float` 胶囊浮于确认钮上方（bottom:104px，磨砂小胶囊对实心主动作，层级刻意压低于确认区），文案「还有 N 台设备」中的 N 由 `remainingBelowFold(groups, columns, scrollTop, viewportH)` 纯几何计算——行距 192、组标题 29（`.group-title` 必须保持 `line-height:17px`）、组间距 20，行顶仍完整位于视口底缘之下才计数；N=0 淡出、回滚重新出现。scrollTop 只由 `@scroll` 回传（`scrollY` 跟踪态），程序化滚动走独立的 `scrollCtrl` 绑 `scroll-top` + `scroll-with-animation`，点击浮标把首个隐藏行顶滚到顶缘下 8px——**禁止把 scrollTop 回写进 scroll-top 绑定**（动画中逐帧回写会打断动画）。视口高只在面板打开/窗口 resize 时用一次 `SelectorQuery` 量 `.device-list`，禁止在 scroll 回调里查 DOM（桥接昂贵）。浮标与渐隐显隐走 class 切换 + transition（常驻挂载），入场 bob 只在挂载时播两次；reduced-motion 下全部禁用。
- 面板（DeviceSheet/DraftSheetLayer）内一律用项目 SVG 图标（`static/search.svg`、`static/close.svg` 等），uni-icons 字体图标在真机不渲染（2026-09-17 全部设备面板放大镜空圈、头部 ✕ 缺失根因）；`image` 引用 SVG 必须显式写尺寸类（mp 的 image 缺省 320×240，缺尺寸即巨型图标撑爆布局——同日"点搜索页面崩坏"根因）；新图标按 `back.svg` 规格自绘（24 viewBox / stroke 1.7 / 圆角端点）。改面板后必须 `build:weixin` 重建并在产物 wxml 核对类绑定与图标资源——开发者工具读 dist，不读源码。
- `UserMessage` 消息操作行对齐 spectrum `message-actions` Ghost 变体：纯图标（项目 SVG：compose/refresh，uni-icons 字体图标在此不渲染）、28px 按钮 14px 图标、中性灰 opacity .45、按压 scale(.92)+黑 4% 底；禁止退回文字按钮。过渡四段缺一不可：普通→编辑先播气泡 `message-out`（140ms）再挂编辑器，`editor-in` 从气泡绿底过渡到纸白（textarea 文字白→墨绿同步过渡）；编辑→普通先播 `editor-out` 再挂气泡（`message-in`）。三条收起路径（取消/提交/recoverable 翻转）统一走 `closeEditor()`。编辑器主按钮为实底绿（对齐 error-state retry 规格），取消为安静文字。
- 空调温度步长以 runtime `acParameters`（0.5°C，产品约定 2026-09-16）为准，前端编辑粒度**下限 0.5**（`Math.max(0.5, 设备step)`——旧草案 parameters 残留 0.1 时仍按 0.5 编辑，invalid 网格校验同用有效步长）；步进与显示按 `1/step` 量化对齐网格，禁止再引入无证据的 0.1。温度滑块必须同时绑 `@changing`（拖动中实时更新）与 `@change`（松手定值）——只绑 `@change` 松手前数字不动（2026-09-17 用户点名）。模式/风速用 `SlidingSegments`：点击走原生 @tap，滑动用不带 .stop 的 touchstart/end 位移判定（滑动后 350ms 内屏蔽 tap 防双触发）；禁止再加 catch 触摸劫持（会吞滚动+误吞点击）。温度步进器为对称三段布局（按钮 | 数字 flex:1 居中 | 按钮），数字与单位垂直居中不混用 baseline；模式与风速共用同一组件。**卡内/编辑器内横向分段切换统一用 `SlidingSegments`，禁止自绘胶囊 tab**（2026-09-17：以空调面板为标准统一——kitze.io 研究结论只落地一处等于没落地）。唯一例外：全部设备面板头部的三枚分组胶囊是 2026-09-16 拟物重塑的既定设计（纯 @tap 切换 `groupIndex`，无滑动判定、无下拉菜单），不要再改成 SlidingSegments 或加回下拉。
- scroll-view 禁止直接 `flex:1; height:0` 撑高：微信 webview 会盒子 0 高、内容被 enhanced 层画出但命中盒全灭——"看得见点不中"（2026-09-17 预览整页失联终审根因；AX 表现=scroll-view 内全部子元素 bounds 塌缩 h=1px 而外层元素几何正常）。确定性高度链：外包一层 `flex:1; min-height:0; overflow:hidden` 的 view，内层 scroll-view `height:100%`（会话列表 `.conversation-shell`、参数编辑 `.content-shell`、面板列表 `.device-scroll-shell` 均按此）。
- `UserMessage` 编辑态必须有确定宽度（wrap 在编辑态为 `calc(100vw - 32px)`、上限 320px，恰好等于正文区内宽）：textarea 是原生组件，`width:100%` 撑不开 fit-content 父级，否则整卡塌缩；禁止用 `88vw` 之类视口单位定宽，窄屏上会溢出内容区、右对齐布局下向左贴边。消息动作按钮必须 `white-space:nowrap`（min-width 小于 CJK 文案固有宽度时会断行）。
- 终态事件四类：`run.completed`/`run.failed`/`run.aborted`/`run.awaiting_confirmation`——`run.aborted` 是显式停止终态（runs/cancel 触发，服务端已把该轮 user+半截正文+工具结果记入模型上下文），渲染为「本次回答已停止」、running/searching 活动归 skipped；`conversation.mjs`、`presentation.mjs`、`stream-errors.mjs` 三处的终态名单必须同步维护。
- 流式 `streamMessage` 必须带空闲看门狗（`apis/agent/idle-watchdog.mjs`，60s 无分块 → abort 并以"回答流超时"reject）：enableChunked 请求挂起时 wx.request 的 success/fail 永不回调，`isRunning` 永久为真，且 `schedule()` 轮询被 activeRequest 抑制，服务端恢复也无法自愈——整页 busy 冻结（2026-09-17 预览环境"面板打开后无法任何操作、主页面卡片全死"的根因；顶部与输入栏仍可点是因为它们不吃 busy 禁用：Header 按钮无 disabled 属性、composer 只被 mutating/hasExecution 禁用）。「清除会话」同样不得被 busy 门控（Header 的 disabled 只表示无会话，运行中能否清除由服务端 409 权威决定）——busy 卡死时这是用户唯一自救口。更正旧注：stopRun 的 staleRunSince 本地解锁已随"相位服务端权威"移除，勿按旧注复活。
- 面板轻扫收起必须带位移门槛（DeviceSheet WXS：`|位移|>8px` 才允许 flick 判定）：鼠标/模拟器一次点击会合成 1~3px 的高"速度" touchmove，无门槛时"点横杠"即被误判为轻扫收起。
- `UserMessage` 气泡布局**禁止依赖嵌套 fit-content/intrinsic 测量**（宿主 flex item → wrap → text 的反推链会塌到 min-content，短消息每行一字，2026-09-16 两次返工实证）：宿主经 `.um-host{width:100%}` 定宽、wrap 块级 `width:100%; text-align:right; font-size:0`（消行盒基线空隙）、气泡 `display:inline-block; max-width:88%` 收缩包裹；编辑态 `margin-left:auto` 保持右对齐。消息动作按钮必须 `white-space:nowrap`（min-width 小于 CJK 文案固有宽度时会断行）。编辑/重试入口按"最后一轮纯问答（无草案无结果）"显示（`canRecoverTurn`），带设备操作事实的轮次前后端都保持只读；runtime 侧提案判定查 `action_drafts.turn_id`（比事件流判定严，覆盖草案已插入但 action.proposed 未落库的崩溃窗口），丢弃轮会同步把该轮追加的会话条目标记出模型上下文（`discarded_session_entries` 表）。
