# Agent Page Notes

- 组件必须对宿主全局样式中立（2026-09-23 根因）：组件代码会被原样迁入客户小程序，而客户 `app.wxss` 继承 uni-app 模板 `view{font-size:28rpx;line-height:1.8}` 与 `input,text{font-size:30rpx}`——元素自身命中的规则优先于继承，会把组件内所有不带字号类的 `text`/`input` 撑成 15px；每个组件 scoped 样式首行固定 `view, text, input { font-size: inherit; line-height: inherit; }`，禁止删除。scroll-view 隐藏滚动条必须用 `enhanced :show-scrollbar="false"`，非 enhanced 时该属性不生效——本壳靠全局 `::-webkit-scrollbar{display:none}` 掩盖，客户壳没有这条全局规则会露滚动条。
- 会话相位（2026-09-16 定稿，零滞留）：待确认草案期间可以继续发消息，但下一条消息会把旧草案退役为已取消（跨轮 `action.resolved` 即时转只读），模型总是重新起草；只有执行中/运行中会被服务端 409（`CONVERSATION_AWAITING_CONFIRMATION`，前端撤回乐观轮次并 toast）。不要按"有待确认草案就禁用输入栏"，也不要复活非末轮的过期草案。
- 微信分块事件的 `data` 是 `ArrayBuffer`，中文 UTF-8 字节可能跨 chunk；所有 NDJSON 解析继续复用 `apis/agent/ndjson.mjs`。
- Android 优先消费 `onChunkReceived`，其他平台保留完整 response 回退，两条路径必须产生相同业务事件。
- 独立壳的开发身份只通过 `config/index.js`/`getAgentHeaders()` 提供，页面与组件不接触 header；本项目不承载生产登录态。
- `ACCEPTED` 表示上游受理，界面保留“暂无物理状态回执”说明；只有待确认卡片可发起真实控制。
- 恢复会话时以服务端 `draft/result` 为准；历史事件只恢复轨迹和正文，不能把已执行草案重放成待确认。
- 选项更新和确认携带最新 revision；执行结果的 summary 由服务端生成，重试回答不得重发设备控制。
- 设备卡徽标状态合并两个来源：`GET /device-states` 的最后已知值兜底，`result.observedStates`（confirm 回读时刻的权威读数）覆盖胜出且只取非空项（`device-card-state.js` 的 `mergeObservedStates`）。两处消费者（`ActionDraftCard`、`DraftSheetLayer`）都必须在 `result` 落地时先同步合入再异步补查，禁止只等下一次 GET——否则回执已出而徽标仍按指令前快照渲染（2026-09-17「确认后仍显示已开启再翻已关闭」根因）。
- 草案「还原」（全部设备面板右上角，仅在有改动时出现）：服务端 `POST /action-drafts/:id/restore` 原子恢复发布时刻的勾选+指令+summary/question（`original_json` 快照，提案落库时写入，旧库迁移回填当前态为基线）；客户端 `draftBaselines` 快照只做按钮显隐的 dirty 判定（`action-draft-presentation.js` 的 `createDraftBaseline`/`draftBaselineChanged`），权威还原始终于服务端；还原可逆故不加二次确认。
- 独立项目构建和验收边界见项目根目录 `README.md`；H5 预览不是小程序验收。
- 输入栏切换语音会卸载 textarea，键盘收起不能只依赖 textarea 的事件；页面监听键盘高度并在卸载时移除监听。
- WechatSI 只能在用户开始录音时延迟加载；测试号未注册插件时保留文字输入。授权前松手、切后台和触摸取消都必须丢弃已取消的识别结果。
- 编辑/重试只作用于最后一条未产生草案的失败回合：先用服务端 `turnId` 丢弃失败记录，再复用同一个前端 turn 原位启动；禁止保留失败轮后追加一条重复消息。
- `AgentReplySurface.vue` 是身份、轨迹、正文、草案和执行收尾的唯一编排层；不要再把这些区域直接拼回页面，也不要恢复按会话随机生成头像。
- 设备卡片：选择走原生 `@tap`；touch 流驱动长按进度环（360ms，进度 ≥90° 才渲染），原生 `@longpress` 作为微信 `scroll-view` 内的可靠完成信号；二者统一进入幂等 `completeHold`。`completeHold` **只能把状态推进到 `committed`，不得当场 emit configure**；须等原卡片的 terminal `touchend/touchcancel` 将状态推进到 `released` 后才打开 popup——在手指仍压住旧卡片时挂载 uni-transition，会让其 `$nextTick + 80ms` 入场提交与旧触摸序列竞争，真机可能卡在中间帧、下次 tap 才刷新（2026-09-17 外部空调卡片长按偶发半高）。已提交后的 cancel 必须进入 released 兑现配置，禁止撤销（2026-09-16「长按后环闪一下、筛选消失但编辑器未进入」根因是完成后 24ms 定时器被 touchcancel 清除）。监听一律**不带 .stop**，位移 >14px 在提交前视为滚动并取消，随行 tap 用一次性 `holdDone` 屏蔽。禁止 catch 触摸事件、禁止 suppress 时间戳。**长按配置只服务空调**（2026-09-17 门禁面板移除）：门禁一次执行即开一次门、无参数可配，`cardConfigurable`（device-card-state.js）限定 `kind==='ac'` 且 pending/非只读/非禁用——门禁卡长按不起进度环、不 emit configure，只保留普通点选；`openSheetEditor`（index.vue）与 `DraftSheetLayer.configure` 再设 ac 门禁兜底。曾有的门禁"开门次数/间隔/时间线"编辑器已整体删除——服务端 PATCH /parameters 只接受 ac 修改、access 指令严格 `{controlType:2}`，该编辑器是全链路死代码，且其步进器曾复用空调温度步长（次数按 0.5 步进）；禁止以"给门禁一个独立步长"方式复活，参数编辑面就是空调专属。
- 设备卡片高度统一 180px，不因设备类型加高；当前状态未知时正文不渲染"状态未知 →"起点（只保留图上角标一处），避免与指令目标（如"开启 · 25°C"）并列造成误读。卡内 `before→after`（`.change`）为**纵向两行制**：现状行（浅灰 `.from`）+ 目标行（绿 `.to`，文本 `→` 引导，不用字体图标），各自 `display:block; nowrap; ellipsis`——acSummary 复合串在 103px 内宽里单行容纳不下两段，横向 flex-wrap 硬排只会产生逐字竖排/箭头孤儿/断尾三种破相（2026-09-17 真机根因）。**通用禁令：承载文本的 flex item 要么 `flex-shrink:0` 要么 `nowrap+ellipsis`**，`flex:1;min-width:0` 的文本项会在窄空间里塌成逐字竖排列（CJK 任意字间断行），与 UserMessage 的 fit-content 塌缩同族。
- 操作面板（`ActionPanel.vue`，2026-09-18 定稿）：概览与草案合并为一张一体卡，`AgentReplySurface` 在 `turn.draft` 存在时只挂这一个组件。结构=头部（页提示+`[概览|草案]`分段控件）+共享速览条（共找到/拟执行/不动，数字走活 join）+**固定 300px 体高**+常驻底栏。切页签只 `v-show`（uni-app 编译为 `data-c-h`/`hidden` 保活），**禁止 `v-if`/重建**——会丢草案卡 states 缓存与概览滚动位；body 固定高、两页各自内部滚动，外卡高度不随页签或内容变化。底栏是唯一动作区：PENDING=已选 N+取消+执行操作、EXPIRED=重新核验、EXECUTING/result=回执行（卡的 `.receipt` 随 `embedded` 一并上移），CANCELLED/INTERRUPTED 等只读相位无底栏（说明在草案页 historyNote）。提案到达默认落草案页；**无 roster 的旧持久化轮次整体降级**为原独立 `ActionDraftCard`（分段/速览/底栏不渲染）。`ActionDraftCard` 加 `embedded` prop：藏自有 heading/actions/EXPIRED 按钮/receipt 并剥掉 `.draft` 外卡 chrome，勾选/调参/状态合并/还原等全部行为不变。
- 设备清单（`DeviceRoster.vue` + `device-roster.js`，2026-09-18 改为活视图）：`action.proposed` 事件的 `inventory` 落在 `turn.roster`，runtime schema 不变——inventory 仍是提案时刻原始事实，`disposition` 快照字段保留作恢复兜底；**「活」发生在前端 join**：`rosterLiveView(entry, draft, observed)` 处置槽由活草案推导（草案内已勾选→`→ ${operationLabel(活指令)}`，空调调温实时回流；草案内未勾选→未选择；不在草案→快照 disposition 给已排除/不动），`rosterLiveStats` 速览数随勾选即时变化；状态槽 `observed[deviceId] ?? entry.state`——confirm 回读覆盖提案时观测，执行后清单自然成为对账表。行模型=迁移链 `[标记] 短名 …… ●现状 → 意图`：**行首标记优先 `resolveDeviceArtwork().src` 裸图**（24px 高、宽自适应 ≤38px、drop-shadow、无框无底色），无图（generic）退回 code 徽章；短名 `deviceDisplayName`；**位置第一分组**（缺位置归「其他位置」），组内保持发现顺序。文案单一来源禁止另造措辞：照明=色点+已点亮/已关闭、空调=`acSummary` 去「开启 · 」前缀、门禁=「—」、未读到=状态未知；意图槽 `→ 打开/关闭`、`→ 制冷 · 26° · 低风`（°C 压成 °）、`→ 开门一次`。列表是面板固定体高内的 `scroll-view`：边缘渐隐只用自身 `mask-image`（禁色带覆盖层）；底部 v 游标沿用 `cue-float` 浮动胶囊视觉、图标化，`hasMore` 单布尔=「scrollTop+视口 < 内容高-4」，**只判到底、不做剩余台数计算**，点击下翻一屏；隐藏页 `display:none` 时 selectorQuery 测得 0，恢复可见需重测（`active` prop 驱动）。三槽布局铁律与 `.change` 同源：名槽 `flex:1;min-width:0;nowrap;ellipsis`，状态/处置槽 `flex-shrink:0;max-width;nowrap;ellipsis`，行禁止 flex-wrap；编译契约见 `test/compiled-roster.test.mjs`。runtime 侧 schema 与边界（只收触及设备、state 只来自观测）见其 `src/AGENTS.md`。
- 草案手轨的边缘渐隐必须用 alpha mask（`.rail` 上的 `-webkit-mask-image`/`mask-image` 线性渐变，两端各 20px），让卡片内容连同描边整体透明渐隐；禁止用 `::before/::after` 色带覆盖层（半透明底色叠在卡片上会透出描边/图片残留细线，且与 overflow 裁切叠加产生脏边）。
- `DeviceSheet.vue` 使用官方 `@dcloudio/uni-ui` 的 `uni-popup` 作为底部面板底座，统一接管遮罩、层级、外部点击和进退场；横杆下拉只保留 WXS 渲染层手势适配。每次 `configure`/`browse` 必须递增并透传独立的 `openRequest`，`draftId/open` 只表达面板归属与期望状态：同一草案二次点击仍要重新驱动 `ensureOpen`，并先清除可能失真的 `visible` 反馈，让 350ms 重试跨过 uni-popup 的 300ms 关闭窗口；回归契约见 `test/agent-sheet-reopen.test.mjs`，编译保真见 `test/compiled-bottom-sheet.test.mjs`。横杆拖拽收起时**禁止在松手帧把 `.sheet` 位移写回 `translateY(0)`**——内层 300ms 回弹与外层 slide-bottom 叠加成「先上窜再收起」的反向运动（2026-09-17 真机根因）；收起路径保留松手位移交给 popup 外层动画续滑；**不可假设位移会随 popup 子树卸载消失**——uni-popup 会复用槽位节点，WXS `setStyle` 的 inline transform 不受 Vue 虚拟 DOM 管理，若原节点复用，二次打开只显示遮罩而 `.sheet` 仍在屏外（2026-09-18 真机根因）。每次 `open/openRequest` 必须在 `popup.open()` 前递增 `surfaceReset` 并 await nextTick，通过 `.sheet` 的 `change:surface-reset="sheetGesture.resetSurface"` 让 WXS 同层清除位移；此外 `@dcloudio/uni-ui@1.5.12` 的 uni-transition 入场原实现依赖 nextTick 后 `setTimeout(80ms)`，微信真机调试会延迟该 timer，表现为面板卡在只露一点、点击后才闪到正常；`scripts/patch-uni-transition.mjs` 在 postinstall/build 时移除 timer，并在 `animation.run()` 提交后立即把声明式 transform 置于最终帧，禁止删除该可复现补丁（编译产物不得再含 transition setTimeout）；`resetHandle` 仍只用于未达阈值/触摸取消的回弹，禁止为了重开在松手帧复位。手势行为回归见 `test/agent-sheet-dismiss.test.mjs`。**`dismissFromHandle` 禁止用 `open`/`requestedClose` 早退**——横杆拖拽发生时面板必然可见，状态失配时早退会把 `.sheet` 连拖拽位移悬停在半空；此约束只处理横杆拖拽，不可用来解释外部卡片长按的 popup 入场问题；`popup.close()` 幂等，无条件执行 + `emit('close')`。`ensureOpen` 的 350ms 重试须按真实 `popup.value.showPopup && showTrans` 对账：两者皆真说明物理层仍在展示、`change{show:true}` 影子反馈失真，校正 `visible` 并停止空转（同时恢复后续 `open→false` 的关闭路径）；仅 `showPopup` 为真是 300ms 关闭动画未播完，继续重试等销毁后再打开。若新增 uni-ui 组件，必须同步维护 `pages.json` 的 Easycom 映射并在微信构建产物中确认其内部依赖已编译。
- 面板内容统一由页面根部的 `DraftSheetLayer.vue` 渲染（在 composer 之后），`ActionDraftCard` 只通过 `configure`/`browse` 事件请求打开；打开面板要求草案 PENDING_CONFIRMATION，但打开后面板跟随轮次上的草案对象本身——过期不再踢掉面板，转为只读 + 面板内"重新核验"提示（核验成功原地恢复可编辑）；仅当草案被新提案取代（draftId 消失）或轮次清理时自动关闭。**渲染与关闭信号解耦**（2026-09-17 真机「空调面板收起瞬间消失+一闪」根因）：`open` 由 `props.draft` 实时驱动保证收起立即触发，但 `emit('close')` 同帧 draftId 即空——所有渲染（标题/meta/subtitle、`current`、列表、回执相位、「还原」显隐）一律读 `renderDraft`/`renderResult`/`renderBaseline` 三份"最后非空"快照，模板禁止裸读 `draft.`；换草案时快照随新 props 同步覆盖防串稿。交互动作（toggle/configure/save）以 `open` 为门，收起动画 300ms 内不允许再发操作；页面态（page/search/groupIndex）只在显式打开或换新草案时重置，关闭中途不得重置防 surface 滑位。
- 面板的关闭操作（遮罩点击、横杆下拉）永远允许，不受 busy 限制——busy 卡死时用户必须始终能退出。**面板不设 × 按钮**（2026-09-16 统一底部面板）：横杆是唯一拖拽抓取区，标题、筛选和搜索控件不再参与拖拽；遮罩+横杆两条关闭路径已够（对齐 Kitze Bottom Drawer 的独立 backdrop / popup 结构），禁止再加回。
- 原生 input/textarea 一律非受控写法：`@input` 只向上同步文本，禁止把回流值直接写回 `:value`——bindinput 在拼音组合中态也触发且 `detail.value` 携带原始拼音，写回等同于向 IME 强制提交组合中文字（2026-09-17「打字中拼音直接上屏、发送时拼音与字一起进消息」根因）。程序性改写（发送清空、恢复草稿）经 `field-echo-guard.mjs` 的 `plan(target, written)` 取写回步骤：目标值恰等于已写入值时返回两步 `[显示值, 目标值]`——同值 prop Vue 不重渲染，必须先写当前显示值制造 diff 再 nextTick 写目标值，否则发送后清空进不了原生层（2026-09-17「发送后文字残留输入框」根因）；`@confirm` 先以 `detail.value` 同步再提交。
- 输入栏 textarea 常驻（v-show 切换语音胶囊），避免原生组件重挂载闪烁；**输入栏走键盘停靠而非整页上推**（2026-09-17 改判）：`adjust-position="false"`，textarea 组件级 `bindkeyboardheightchange` 经 `keyboard-dock.mjs` 归一化（duration 各端秒/毫秒不一，封顶 400ms）后由 index.vue 转为 `.composer-shell` 的 `padding-bottom`（键盘高 + 8px 缝，对齐事件返回的 duration 过渡）——头部不动、对话区 flex 收缩、弹起时 follow() 仅在底部锚定。`cursor-spacing`/`adjust-keyboard-to` 仅 adjust-position 生效，已删。禁止回退 `adjust-position="true"`（整页平移会让自绘 AgentHeader 撞上状态栏/胶囊、safe-area padding 变键盘死区）；也禁止全局 `uni.onKeyboardHeightChange` 事后回调；只许动 composer-shell 底部 inset，禁止压短页面高度。
- 折叠面板（处理记录）不要用 `grid-template-rows: 0fr/1fr` 过渡（小程序内核不动画），也不要用"selectorQuery 实测高度驱动 + height:auto 切换"——多轮同构组件下类名选择可能选错实例、且测量与内容增长有时间差，切换瞬间会凭空多出空白；用 `max-height: 0 ↔ 640px` 过渡（overflow:hidden，盒子高度恒贴合内容），折叠箭头用单图标 rotate(180deg)，禁止 up/down 字形互换（会引发布局跳动）。
- 底部面板（DeviceSheet）结构铁律（2026-09-16 统一成熟弹层底座）：① 官方 `uni-popup` 负责遮罩、层级、外部点击与 300ms 底部进退场；② WXS 只负责 handle-zone 的向下跟随、flick/阈值判定和 300ms 回弹，关闭通过组件方法回到逻辑层；**横杆上拉必须保持 `translateY(0)`，完全不动**——面板底部锚定屏底，任何负位移都会把底缘抬离屏底漏出遮罩背景（2026-09-17 真机根因），禁止用同色裙边掩盖本不该发生的位移；③ 关闭=遮罩 tap + 横杆下拉，永远不被 busy 门控；④ 拖拽只认 handle-zone 全宽 44px 条带，标题、槽位内容、交互控件都在拖拽区之外；⑤ 面板内 scroll-view 禁用 `enhanced`，避免原生滚动层抢占周边触摸。
- 卡片单击选中的链路本身可靠；历史上"点不动"的三个真因：①草案已过期（服务端拒绝后静默回滚）——selectDraft 现在有过期预检 + toast + restore 重同步；②busy 锁（mutating/执行中/僵死 running）期间全部禁用；③服务端 conversation.running 在客户端断流后可能长时间不回收——stopRun 对无本地请求的僵死状态做本地解锁（staleRunSince 5 分钟内忽略）。
