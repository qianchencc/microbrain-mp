## 原型要回答的问题

验证用户能否明确分辨“周期计划、未来发生、实际 Task”和“固定区间、自由检查点”，并顺畅完成仅本次/整个周期编辑。逻辑和导航采用一个方案，沿现有区域工作台设计语言，不重新探索 B6 几何或多个装饰风格。

必须有可操作路径：

1. Agent 提案展示重复摘要、下一次发生、独立区间及多个检查点，确认后进入计划列表。
2. 工作台在 14:00–16:00 的完整区间内展示 14:10、14:45、15:30 三个检查点；最后一个检查点完成，区间仍不缩短。
3. 从未来发生进入编辑，清楚选择仅本次或整个周期，确认前展示改动；其他日期及历史结果保持可核对。
4. 计划停用只阻止未来发生，当前发生继续；本次取消是独立命令，已发生动作不回滚。
5. 到点后对应未来投影被实际 Task 替代，结果与历史只有一份；Task 结束展示成功、部分完成、失败、未核验或错过的真实语义样例。
6. 创建者从结束通知返回同一 Task 详情；订阅不足/投递失败不阻断执行，任务结果和投递结果分别显示，并提供重新订阅入口。

边界走查：跨午夜按开始日期归属、截止日不截断已开始区间；结束后旧检查点不补执行、终点正常调度、进行中调用收口；本次与整个周期均可编辑未来检查点和目标。删除全部检查点、调整区间导致检查点落在外部等尚未收口的操作，标记为待验证场景，不静默生成规则。用可控演示时间推进，不需要真实等待。

## UI 补充与协调（建议，待原型验证）

本轮用 `better-layout` 与 `emil-design-eng` 核对信息结构和现有组件，没有做浏览器/微信视觉验收。实现以现有 `DeviceSheet` 和 pane 导航为底座，新增计划列表、计划详情和编辑内容；不为每个内容页重新创建抽屉。

| 位置 | Before | After | Why |
|---|---|---|---|
| [工作台](../pages/agent/region.vue:28) | 底部设备/新建任务入口，无长期计划入口 | 推荐补“周期”入口，打开计划列表；新建继续回 Agent | 停用计划仍可管理，不依赖某天是否有任务卡 |
| [提案卡](../pages/agent/components/TaskProposalCard.vue:1) | 只展示阶段和一次性创建 | 补重复摘要、独立区间、下一次发生、检查点摘要；创建/编辑的确认对象与范围明确 | 用户确认完整的未来行为，避免把编辑当成新建 |
| 计划列表/详情（新增） | 无长期计划视图 | 列表显示名称、重复规则、区间/时刻、下一次、创建者与启停；详情复用现有材质和抽屉 | 计划启用不等于本次正在执行 |
| [时间轴投影](../pages/agent/region-timeline.mjs:9) | 首末 phase 决定区间，单 phase 为点 | 使用独立区间，未来发生与实际记录可辨识；多个检查点按真实时刻呈现 | 单个检查点也能属于完整区间，替换投影不产生重复卡 |
| [任务详情](../pages/agent/components/TaskDetailContent.vue:5) / [文案投影](../pages/agent/task-detail-view.mjs:60) | 非首阶段统一叫结束，第二节点固定为结束环 | 本次日期/区间、所属周期入口、报告摘要、检查点列表；节点按语义区分，设备组按现有方式展开 | 任意检查点不能冒充区间终点；历史只读与未来编辑清晰 |
| 编辑 pane（新增） | 无本次/整个周期编辑 | 先选择作用范围，再编辑区间、检查点和目标；保存前展示影响，按钮明确“保存本次修改”/“更新周期计划” | 防止将单次调整误应用到全部周期 |
| 通知与返回 | 已有 region/date/taskId 跳转入口，无投递状态 | 结束通知直达同一 Task 报告；详情低优先级展示投递状态、失败原因及重新订阅 | Task 完成与通知发送分开；历史/无权限/任务不存在要有明确结果 |

推荐导航：工作台 → 周期列表 → 计划详情 → 编辑；时间轴/设备记录/通知 → 本次详情 → 所属计划。返回保留原区域、日期和滚动位置；编辑有未保存改动时先处理退出。复用单个抽屉的 pane 返回，不叠开多个 Sheet。

需共同维护的规则：

- 创建者显示完整启停开关；其他有停用权限的成员显示当前状态和明确的停用动作，不给可以重新启用的双向开关。具体能力由服务端返回，客户端不根据头像、姓名或来源字段猜权限。
- 明确“停用周期”“取消本次”“删除周期计划”的作用范围；删除计划保留历史，取消不回滚设备动作，停用不停止当前发生。
- 跨区域计划在编辑、停用或删除前展示全部受影响区域；当前关注区域只是入口上下文，不把整项计划操作误表达为只影响当前区域。
- 计划状态、本次 Task 状态、检查点结果和通知投递状态分开。检查点都完成但区间未结束，显示任务仍在区间内，不持续显示设备执行 spinner。未核验、失败、错过有不同文案，通知成功不能充当执行成功。
- 订阅入口放在创建/确认任务的用户操作处，详情提供重新订阅；拒绝不阻断 Task，不在每次打开列表时反复打断。投递文案依据真实回执，受理不写成已送达/已读，也不显示未经核验的剩余订阅次数。
- 一处保存后，同步刷新提案收据、计划列表/详情、未来时间轴、日历与本次详情；保持当前选区和阅读位置。版本冲突保留编辑内容，展示最新事实供核对，不静默覆盖。
- 所有入口使用同一计划/发生/Task 标识；移动时刻不能仅凭新的显示日期生成另一条发生。具体标识与查询形状留给规格，不在客户端各自推导。
- 长检查点列表使用单一滚动域，摘要有明确展开入口；区间端点与检查点拥挤时处理标签，不移动真实时间坐标。编辑键盘、底部操作栏与安全区沿现有 Sheet 规则核对；展开、返回与保存反馈遵守 reduced-motion。

需与[业务场景模拟](../docs/research/2026-09-30-agent-business-scenario-simulation.md)协调：报告可组合事实、提案和执行记录，复用现有观察块；一期仍为照明/空调的时间动作，纯观察任务、条件控制和传感器检查不因 UI 留出展示位置就变成已支持能力。图像/设备 artwork 复用本地目录，字段来源与采样新鲜度保持原有语义。
