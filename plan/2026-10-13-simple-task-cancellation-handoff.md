# 双 Agent 任务取消收口

2026-10-13。用户明确：周期任务只需要“取消本次”“取消全部”，移除只有引用作用的“管理整个周期”，不增加管理页面。Company 与 Office 共用交互、各自传 source。

## 行为

- 未落实际 Task 的发生：取消本次 = 跳过该发生；后续周期继续。
- 已落 Task：取消本次 = 现有任务取消，取消尚未执行的阶段，保留已执行与在途结果；后续周期继续。
- 取消全部 = 删除周期未来调度，并在同一事务取消已落实际 Task 中尚未执行的阶段。已下发指令不撤回，已执行结果及历史报告保留。
- 周期详情的“取消本次”指下一次安排；某次发生的详情则指选中的那一次。取消操作均明确弹窗确认，失败停留现场；成功返回列表/上层并刷新。
- 普通任务仍为“取消任务”。引用仍只负责询问，不承担取消。

## 实现与验证

Runtime 增加 POST `/api/agent/task-plans/:id/cancel?source=office|company`，请求 `version`、`scope=occurrence|all`，occurrence 另带上海发生日期 `date`。复用计划 skip/delete 与任务结果收口；校验来源、创建者、完整当前设备范围及版本。

HTTP 夹具分别覆盖 Office 照明和 Company 只读简报：取消一次、后续仍执行、取消所有剩余阶段、保留第一阶段结果、错来源/非创建者/旧版本拒绝。未操作任何真实设备或真实周期计划。
