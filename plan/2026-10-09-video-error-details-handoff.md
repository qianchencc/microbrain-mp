## 原始调用采集的实际报错

原始调用成功取得短时效播放地址，但SDK将+08:00时间直接传给媒体平台后，被拒绝且没有首帧。将SDK参数换为北京时间钟面+Z后，同一设备和窗口显示正确录像。以下记录用于追溯此次格式问题，不能将此错误码在其他场景中一律解释为相同原因。

| 项目 | 实际值 |
|---|---|
| 设备 | 监控-27楼茶水间 |
| 我方来源 | Company智慧监控目录 |
| 上游设备hubDeviceId | `0e5a0ec8ce1e6c882363eb167e12c072` |
| 目录设备ID | `65f748e2265a18ab30c57d75517cc58b` |

| SDK错误码 | `0x01730ec1` |
| SDK响应状态 | `statusCode=1`, `statusString=ERROR`, `subStatusCode=server` |
| SDK原始错误说明 | `errPlatformIp=;errPlatformName=sb68tg==` |
| 失败位置 | SDK开始播放的上游请求返回错误；解码/首帧未开始 |

录像查询动作：

```text
POST /micro-api/api/iot-center/interactive/0e5a0ec8ce1e6c882363eb167e12c072/bec190c9819348e08b203a95b7629ad8/down
```

```json
{
  "beginTime": "2026-10-09T13:09:00.000+08:00",
  "endTime": "2026-10-09T13:39:00.000+08:00"
}
```

SDK调用使用官方客户资源包：

```js
JS_Play(freshUrl, { playURL: freshUrl, mode: 1 }, 0,
  '2026-10-09T13:09:00+08:00', '2026-10-09T13:39:00+08:00')
```

`freshUrl`不附在这份材料中，避免保存短期会话地址；长期认证凭据也不附。SDK的mode参数与播放/回放语义分别处理，录像由时间参数和已取得的回放地址确定。

如果其他设备或窗口仍失败，按以下项目核对：

1. 对应媒体服务日志中`0x01730ec1`的具体原因与关联请求，优先看开始播放请求返回错误的位置。
2. 该hub绑定的录像通道是否正确，该时间窗口是否有可用录像。
3. 上游回放地址与SDK时间参数所需格式、时区和会话认证契约是否一致。
4. 若客户自己的播放器可播同一设备/窗口，提供该次回放的调用参数和脱敏日志用于对照。

`errPlatformIp`为空只是返回字段，不能单凭它断言平台IP配置错误。当前也没有证据确定录像不存在、超出保留期、摄像头离线或浏览器解码不支持。错误码来自SDK收到的媒体服务响应，不能用录像查询HTTP 200证明开播正常。

## 页面报错内容

主卡给出明确标题和下一步；“查看错误详情”展示失败阶段、可公开错误码、取流HTTP状态、SDK状态、设备、来源、模式、上海时间窗口与发生时间。字段通过白名单生成，原始SDK消息、token、WSS地址不会渲染或进入普通日志。

| 可确认条件 | 页面标题 | 用户可采取的动作 |
|---|---|---|
| 身份或范围核验失败 | 会话或设备范围无法核验 | 返回原页面后重新进入 |
| 期间不合法或超过三天 | 录像期间无效 | 返回调整期间 |
| SDK脚本/初始化失败 | 播放器组件未加载／播放器初始化失败 | 检查网络、重试或返回 |
| 取流请求未完成 | 无法连接取流服务 | 检查网络、重试或返回 |
| 取流响应无法识别 | 取流服务响应异常 | 稍后重试 |
| 上游暂不发流 | 上游取流暂不可用 | 稍后重试；不直接断言并发已满 |
| 当前窗口没有返回播放地址 | 未取得可播放录像 | 调整期间或稍后重试，录像存在性仍需核实 |
| 返回窗口与所选期间不一致 | 录像窗口核验未通过 | 已阻止播放，返回重新选择 |
| SDK收到server类开播错误 | 上游录像服务未能开始播放 | 重试；持续失败提供详情排查 |
| SDK报告播放连接失败/超时 | 视频播放通道未能建立 | 重试或返回 |
| 已验证SDK编码/解码类错误 | 播放器无法处理视频流 | 重试；持续失败提供错误码排查 |
| 本地等待超时 | 取流请求超时／等待视频画面超时 | 根据阶段说明20秒等待，重试或返回 |
| 播放开始后的服务端错误 | 上游视频服务中断了播放 | 重新连接或返回 |
| 未知SDK失败 | 播放未能开始／播放已中断 | 保留错误码，重试或返回，不猜测根因 |

## 实施与验收

沿用播放器脚本、现有错误卡和原生details控件，无新依赖。SDK字符串拒绝值和pluginErrorHandler均可捕获；播放中错误也会结束当前会话并显示错误。失败立即反馈，重试仍等待旧SDK释放，旧回调不能覆盖新画面。

播放器公开行为回归10/10，前端全量39/39，脚本语法和git diff --check通过。SDK码分类依据客户托管SDK源码中的枚举，未知码保留码值不擅自解释。版本hash随player.js更新，index.html与脚本同批部署；9415开发服务自动读取源文件，HTTPS页面重新进入即可获取新文案，不需要重启Runtime。

真实HTTPS页面复验显示“上游录像服务未能开始播放”，可展开详情包含0x01730ec1、HTTP 200和ERROR/server；390×844画面已检查，返回后SDK画布归零。截图见[错误详情](../docs/research/video-error-acceptance/error-details.png)。微信真机仍独立验收。建议技能：diagnosing-bugs、tdd、emil-design-eng、ego-browser。业务边界见[事件复盘交接](2026-10-09-safety-camera-review-handoff.md)。
