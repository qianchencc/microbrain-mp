## 已实现的业务

用户通过 Agent 提出工作日关灯，卡片展示重复规则、首次安排和完整设备目标。点击“创建周期计划”才保存长期计划及加密执行身份；未确认、放弃、读取未来安排均零下发。

`propose_task` 新增可选 `repeat`：`{ frequency: 'daily' | 'weekdays' | 'weekly', weekdays?: number[], until?: 'YYYY-MM-DD' }`。指定周几采用 ISO 1=周一、7=周日；工作日为周一至周五，不识别法定节假日。沿用照明/空调与已有命令范围；不接门禁或 Company。

未来发生由模板按上海日期平移，不提前写多日 Task。虚拟发生带 `occurrence: { planId, date, virtual: true }`，ID 为 `occurrence:<planId>:<开始日期>`。起点已过则顺延；跨午夜按开始日重复和截止，已开始区间照常跑到结束。

扫描时在同一事务中落独立实际 Task、复制已确认快照与加密凭据、推进下一次；`(source_plan_id, occurrence_date)` 唯一。执行、授权重核、回读、逐设备回执沿既有执行器。实际 Task 用独立 ID，带 `virtual:false`；区域/设备时间轴与日历以它替换同一发生的虚拟卡。旧发生链接可解析到实际 Task。

实际发生结束后保留一次报告。长期计划继续存活并展示下一次；最后一次凭据先复制给实际 Task，再清除耗尽计划上的密文。`GET /api/agent/task-plans/:id` 返回下一次及当前授权裁剪的最近实际任务/报告，不返回凭据。

小程序复用现有提案卡、纸面/玉绿材质、单层 Sheet、B6 图形。确认后提供“查看下一次安排”，有实际结果后提供“查看最近一次报告”；仍在执行时入口称“查看本次任务”。恢复卡片带真实 nextAt，立即刷新计划数据；刷新不改写原提案动作快照。

Task/提案/创建者标记使用已核验账户的稳定主体键。旧记录只在原凭据的账户核验成功后绑定；不能用另一份新 Token 猜测旧归属。区域 seen 同样使用稳定主体，因此测试中的两位同事必须有不同 account/me.id。

- 最终检查通过：Runtime 69/69、typecheck/build，小程序 22/22、HBuilderX 微信编译，两仓 `git diff --check`。微信编译仍有既有鸿蒙 UA 等告警，不属于本轮修改。
- 两轴审查修正：启动旧发生补下发、耗尽凭据未清理、投影无界枚举；另外统一原始时间时区校验，防止顺延时把非法时间洗成有效输入。查询超过 500 计划/发生或 4096 日期推算步骤显式 HTTP 422，不静默漏卡，也不增加区间业务跨度限制。
- 微信原生走查使用内存 `wx.request` 夹具：已点击创建、查看未来安排、从 B6 卡打开未来详情；发现 occurrence 编码链接未解码并修复。最终编译后复验下一次安排直接打开未来详情，最近报告入口打开实际发生及执行报告。已恢复原 `wx.request`、移除夹具并返回客户首页。夹具数据不代表 Runtime 实际执行，也不落真实数据库。
- 启动不补跑已经过去的周期起点；已落账且过时的待执行周期点记 missed/not_dispatched，执行中残留保持 interrupted/unknown。未落账且已跳过的旧发生链接返回 404，不能显示成未来安排。仅保留不重放安全，没有实现停机补执行、恢复追赶或新迟延窗口。
