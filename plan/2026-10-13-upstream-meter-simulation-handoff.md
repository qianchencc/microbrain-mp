# 上游电表临时模拟策略核验与本地演示退役

日期：2026-10-13，约 09:20–09:30（上海时间）。

## 用户确认的范围

客户负责 43 台电表的临时模拟补数：从每台最后采样时间续接，每天 08:00、20:00 两条，相邻累计电量随机增加 0–3 度。我方沿现有客户接口读取，不再自行 mock。该策略属于上游模拟，不能称为现场持续实测。

## 只读核验结果

使用既有开发身份直连客户网关 `/micro-api/api/energy`，不重新登录、不打印凭据、不写设备或上游数据库。

| 核验项 | 实测 |
| --- | --- |
| `equipment/page` | 返回 43 台电表 |
| 每台近期历史，最多 16 条 | 共返回 688 条；时间均为 08:00 或 20:00，无设备串号或重复时间 |
| 相邻 `epf` 差值 | 共 645 对，范围 0.00–2.99，样本内无回退或超限 |
| 历史最新时间 | 43 台全部停在 `2026-10-10 08:00:00`；尚未续到核验当天应有的 `2026-10-13 08:00:00` |
| `realTimeRead/page` | 返回 43 行，约 22.4 秒；只有 2 台与对应历史最新时间一致，41 台不一致 |
| 日期过滤 | 运营部电表不带日期查询可读到 10-09 记录；指定 10-09 当天却返回 code 204；指定 10-10 至 10-13 返回了早于起点的记录 |

运营部示例：历史最新 `2026-10-10 08:00:00 / epf=4450.22`，上一条 `2026-10-09 20:00:00 / epf=4448.50`，差值 1.72；最新快照却为 `2026-06-04 08:00:00`。单查 10-13 当天也返回空。

这些结果支持“补数已存在、近期样本符合固定时刻和增量规则”，不能证明定时生成持续运行、每台首次模拟与原始数据的接续完整，或所有历史均正确。历史时间过滤的现象与按写入时间过滤相符，但具体原因需客户核查，未认定其实现根因。

## 本轮修改与页面验证

- Runtime 本来沿 `equipment/page`、`realTimeRead/page`、`electricData/page` 读取上游；没有本地电表补数代码，本轮未改 Runtime 或重启服务。
- 移除仪表盘固定小时曲线、虚构日用电与峰值、演示/真实切换及其独占数据生成函数。
- 保留接口功率、采样时间、计量点历史入口；功率为空时明确显示未取得有效功率，不能把累计电量转换为功率。
- 仪表盘与历史报告注明上游目前采用临时模拟补数。保留按真实 `readTime` 判定陈旧的机制。
- Agent 测试 40/40；HBuilderX 微信编译成功；`git diff --check` 通过。
- 在实际客户微信编译包中，确认演示切换与曲线均不存在。打开计量历史，从当天空窗点击“查看最近采样日 2026-10-10”，页面展示运营部 4450.22 的原始累计示数和模拟补数说明。
- 本轮概览未取得有效功率，未用样例填充；历史请求可用。上游最新接口约 22.4 秒，超过当前适配器每次 5 秒的读取预算，构成概览读取失败的风险；未擅自扩大超时预算。
- 自动化导航曾超时，重连后完成页面检查；校验后返回原 Agent 页面，未修改草稿或发送模型消息。手机真机未验。

## 客户待修项与下一步

1. 检查定时任务是否持续执行，补齐 10-10 晚间至当前应产生的记录，并避免重复补数。
2. 最新快照按每台最大 `readTime` 选择，保证与历史一致；优化最新快照批量查询耗时。
3. 日期窗口按采样 `readTime` 筛选，使同一天的记录能被日期查询读到。

客户修正后继续通过相同接口复核；我方不补造缺失记录。完整电量统计、倍率/汇总集合和真实采集恢复仍按既有历史观察规格推进，不在本轮冒充完成。
