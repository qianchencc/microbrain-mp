## 目标与建议

完成一条真实微信闭环：按住说话 → 显示录音反馈 → 松手识别 → 发送一条消息 → Agent 正常响应；上滑取消、离页及失败不能误发，并能再次录音。

建议保留当前自动发送方式，增加实时识别文字和临近 60 秒的结束提示。录音反馈沿用现有纸面/玉绿输入框，设备执行仍经原草案确认流程。此建议尚待用户选择。

## 已做的最小检查与待验证风险

直接对客户主线 createVoiceInput 注入模拟 manager 并驱动公开回调：

- 启动前松手、随后 onStart/onStop：只返回一次最终文字；重复 onStop 不重复返回。
- release(true) 后 onStop：不返回文字。
- dispose 后延迟 onStart/onStop：不返回文字。
- onError 后再次 start，再送入上一段迟到的 onStop：现有封装返回了旧文字。这说明封装不能辨别这个回调序列；尚未证明插件会实际产生这种序列。

以上是模拟回调证据，不是真机识别验收。新段绑定处理器会覆盖旧处理器；若插件全局回调不带段标识，单加本地序号不能证明已解决旧事件误归属，需核实真实回调次序/释放契约。

另需验证：上滑取消意图目前只在松手时交给封装；若手指处于取消区时插件自动结束，现有 onStop 可能先发送。到上限时究竟自动发送还是等待松手，也须冻结产品语义。

## 实施与验收顺序

1. **冻结交互**：确定自动发送还是填入草稿；确定上限结束与取消优先级。建议自动发送，取消优先；首次权限弹窗结束后引导重新按住，避免录入不完整句子。
2. **确认平台可用**：用当前客户 AppID 的真机包验证插件加载、麦克风授权、拒绝及重新授权。仅确认失败时才补后台配置。
3. **收口可靠性**：在客户主仓库从 createVoiceInput 公共接口补关键回归，核实回调归属、连续重录、空语音、识别失败、离页及上限取消。明确失败时退出忙态并允许重试；恢复时不提交旧段。
4. **补可见反馈**：若用户选择增强范围，绑定 onRecognize，仅用于显示临时文字；最终发送仍使用 onStop 的结果。倒计时从实际 onStart 起算，隐藏/取消/结束时清理。实时回调缺失时保持基本反馈，不阻塞最终识别。
5. **客户端验收**：npm run test:agent、HBuilderX 微信编译；实际检查两个 Agent 的模式切换、草稿保留、取消、重复录音及窄屏。真机验证权限、上限、断网、切后台和来电中断，分别记录 iOS/Android 与微信版本。
6. **交付**：每次成功只增加一条用户消息，取消/失败/离页增加零条；旧草稿不丢、下一次录音可用。验收结果与未验边界记录到 plan/，只提交本切片文件。

首轮识别语料建议用只读请求：“26 楼现在温度多少”“查看运营部电表读数”“后者”“查看上个任务报告”。涉及控制仅检查到提案，物理执行另行授权。

## 改动边界与规模

预计主要涉及 voice-input.mjs、AgentComposer.vue、一份公开行为测试和交接文档；页面生命周期确有缺口时才修改 index.vue。预计新增生产代码约 80–150 行，实施前按冻结范围调整。

真实音量波形必须先取得与同一录音段对应的可靠音量数据，不能用随机动画冒充。回复播报、其他 ASR 服务和后端语音接口作为后续独立需求。本轮不需要新增组件库或依赖。
