# 任务展示复核：先看结果，点开再看原因

状态：展示逻辑审查与改动建议；尚未修改产品代码、编译或发布。用户要求以不熟悉技术的管理者为读者，错误默认简短中性，点击“未完成”等状态再完整查看。

基线：MP `b965399`，Runtime 参考上一轮已核验的发布源码 `d1f39fc`。检查截图及实际模板、视图函数、接口投影和导出生成器；没有读取客户凭据或新增设备控制。源码审查足以确认以下问题，不代表微信原生交互已经验收。

## 1. 这次要解决什么

用户打开任务，先能回答：做什么、什么时候做、现在怎么样。想追查时，再看到哪次、哪台、为什么。

内部的Task、Plan、Occurrence、Phase、Checkpoint及状态码继续用于执行和审计；面向用户不要求理解“发生、区间、检查点、受理、回读、绑定、让行、口径”等术语。不要为了换词改执行状态、权限或历史结果。

“不往坏了展示”落实为准确、中性、少重复：读取超时不能断言设备坏了或一定没有执行；明确没完成也不能改成成功。没有后台继续核验时，不写“正在确认”“稍后自动完成”。

## 4. 用户能看到的词

这是一套展示规则，不替换后台状态码。颜色和可点击性也应共用；不要再按Company/Office各写一份近义词。

| 事实 | 用户看到 | 点开后说明 |
| --- | --- | --- |
| 尚未确认的安排 | 待确认 | 时间、设备、动作；按钮仍是“创建任务” |
| 已确认、还没到时间 | 未开始 | 计划开始时间 |
| 当前任务仍在有效时间内，包括两次检查之间 | 进行中 | 下一次检查/操作时间；不能暗示一直在发控制 |
| 此刻确实正在调用设备 | 进行中 | “正在调整空调”或“正在检查设备” |
| 有事实证明目标完成 | 已完成 | 实际完成的动作、时间与设备 |
| 一部分完成，一部分没完成或结果未确认 | 部分完成 | 完成项和其他项分开；未知不改成失败 |
| 明确失败、错过时间、执行中断 | 未完成 | 保留三种不同原因；错过不补发，中断不声称全部没做 |
| 仅受理/读取不足，不能确认目标 | 结果待确认 | 已发送的指令、已知结果、缺少什么；不声称还会自动核验 |
| 已取消 | 已取消 | 取消的是后续安排，已做的操作仍保留 |
| 草案过期/用户放弃 | 已过期／已放弃 | 没有创建任务；不能显示成已取消已执行任务 |
| 重复安排开启/暂停/自然结束 | 已开启／已暂停／已结束 | 这是重复规则状态，旁边另显示最近一次结果 |
| 当前无查看/管理权限 | 无法查看／只能查看 | 说明需要有权限的账号操作，不把设备称为故障 |
| 未识别状态、接口字段不足 | 状态待更新 | 允许刷新；不直接露英文，也不默认已结束/已完成 |

设备行比任务总状态更具体：

| 原词/事实 | 建议 |
| --- | --- |
| 不必执行、无需执行、satisfied | 按已知目标写“原本已关闭”“原本已是26℃”；不足以具体化时“无需调整” |
| 已核验、verified | 按事实写“已关闭”“已调到26℃”或“已完成”；不能把设定26℃写成室温26℃ |
| 已受理、ACCEPTED但未证明目标 | “指令已发送”，结果显示“结果待确认” |
| 回读失败、unknown | “结果待确认”；详情说明“暂时没读到操作后的状态” |
| 目标未核验，但回读已有明确不同值 | “结果待确认”；详情写“暂未确认达到目标”，同时给出实际读到的值 |
| 未下发、not_dispatched | “这次未调整”；点开说明停止、时间结束、状态变化或无法判断；不算故障 |
| observed、只读读取成功 | “已检查”；只表示读到信息，不代表符合目标或已调整 |
| 设备现态 | “现在状态”，与“本次操作结果”分栏；刷新不修改历史结果 |
| 有限条件调温 | “空调温度调整”，条件用一句话：“只把开着、正在制冷且低于26℃的空调调到26℃” |
| 检查点、阶段 | 巡检用“第1次检查”；控制用“开灯”“关闭空调”等实际动作；混合操作用“第1次操作” |
| 本次发生、未来发生、周期计划 | “本次任务”“以后的安排”“重复安排” |

原始原因与编号不要靠正则删掉后丢失。前台保留完整原文；分类优先用code、outcome、receipt等结构化事实。无法可靠分类，就显示“这次未完成，点此查看原因”，不猜网络、离线或设备故障。

## 6. 点“未完成”后看到什么

1. 标题用可定位的日常话，例如“00:30这次检查未完成”。
2. 一句说明：“暂时没读到空调状态。”只在已知属于读取问题时使用。
3. 已知影响：“这次未取得检查结果”；如果控制可能已发送，就明确“指令已发送，是否完成还没确认”，不能说完全没执行。
4. 涉及设备：只列当前有权查看的设备；整体读取失败没有逐台结论时，不编“49台均失败”。
5. 完整原始原因、错误编号、发生时间全部保留，可滚动、可复制。短内容可沿现有弹窗；长内容用现有Sheet内的详情页，不用截断toast或只看得到开头的弹窗。
6. 操作只给真实存在的能力：“刷新结果”“重新登录”“知道了”等。刷新是读取历史/当前事实，不触发重新控制；没有重试能力不放“重新执行”。

“未完成”做成按钮，带箭头与可读标签，完整点击区域至少44px；“部分完成”“结果待确认”和加载错误的“查看原因”也走同一规则，避免只有failed能看到详情。弹层关闭回到原任务、原记录与滚动位置；换任务或账号后清除上一条详情，不沿用旧原因。

默认文字、图标采用现有中性灰/柔和提示色，移除每行重复的大段黄字和红叉。颜色表达结果差别，不能只靠颜色传意，也不能用一片绿色暗示待确认已成功。登录失效、没有权限、取消范围等影响用户下一步的信息仍在主界面说清楚，技术原文另点开。

## 7. 怎样实施，怎样验收
