## 业务归属与共用方式

| 能力 | 公司仪表盘 | 公司 Agent | 办公室 Agent |
|---|---|---|---|
| 环境历史 | 环境模块进入趋势详情 | 时间窗口查询、趋势解释、继续追问 | 当前无本办公室历史环境绑定，不合并账号级数据 |
| 电量历史/统计 | 计量模块进入真实历史电量详情 | 指定计量点/时间段查询、统计与比较 | 当前无本办公室计量点映射，不由同名位置推导授权 |
| 安全历史 | 三类筛选、分页、单条详情与引用 | 查台账、解释同一事件、找候选监控 | 保持既有办公室范围；不自动共享公司消防目录 |
| 视频直播/回放 | 可提供进入公司监控列表的轻量入口 | 公司“智慧监控”目录内选摄像头 | 本办公室目录内选摄像头 |

摄像头共用视频详情、播放卡、Runtime 取流服务和自建 H5 播放器；两个来源分别解析可见设备和 hub 身份。相同 hubDeviceId 不表示两端互通授权，恢复、重试和重新取流均保留 source。Company 不导航到 Office 工作台取得监控，Office 不借公司目录补齐缺少的摄像头。

## 可体验的业务场景

以下均是待实现后的验收场景，不是当前可用功能清单。

| 场景与示例表达 | 用户操作与预期结果 | 关键事实/反例 |
|---|---|---|
| 公司环境趋势：“今天上午温度和 PM2.5 怎么变化？” | 仪表盘环境→趋势，或 Company 对话→趋势卡；显示温度/湿度/颗粒物分开的曲线、时间范围、采样数和最新采样；继续问“最高在几点”引用同一查询范围 | `tem/hum` 与实时 `temp/humidity` 分别映射。历史没有设备标识时写“站点环境记录”，不伪称某房间实测；缺点断线，未知值不填零 |
| 环境时段对比：“上午和下午哪个时段空气更差？” | 读取两个明确窗口，给出有样本支撑的均值/峰值/变化；样本不足直接说明 | 小时采样看不到分钟级变化；不无依据给“达标/危险”结论，也不从趋势推断空调导致变化 |
| 单计量点历史：“看这个电表 2025 年 5 月 26 日的电量” | 计量点→历史详情，或 Company 返回电量结果卡；展示采样累计值、可计算区间增量、覆盖情况和字段口径 | 日期为历史可用日期；累计示数不是一天用电，不能把 667.45 直接当作日耗电 |
| 当日无数据：“今天公司用了多少电？” | 如实提示当日没有有效采样、最近记录停在 2025-05-27；可切换到有数据日期；演示始终单独标识 | 不自动拿 2025 年数据替代今天，不把当前功率 kW 累加成 kWh，也不把无数据写成零用电 |
| 用电比较：“比较这两天，哪里用电最多？” | 在已确认计量范围内计算同期增量和差异，展示计量点覆盖/缺失及排名；样本不足或基期为零时不给虚假增长率 | 总表/分表可能覆盖重叠；未冻结不重叠统计集合前，只给逐表结果，不将全部 43 台简单相加为公司总电量 |
| 三类安全台账：“烟感、燃气、水浸最近各有哪些记录？” | 仪表盘→常规筛选列表，最近记录先显示，分页查看更多；各类显示可核实记录与覆盖范围；点单条详情→引用 Company→用户决定发送 | 水浸原始 298 条不作为真实水浸总数；烟感最新仍在 2024 年，不能包装为实时预警。平台上报标记不代表恢复 |
| 告警复盘：“查看这条燃气记录附近的监控，前后各十分钟” | 事件详情→候选监控；Company 根据地点查本端目录，有歧义让用户选；选中后生成明确设备/录像窗口的回放卡 | 使用平台记录时间并显示该口径；地点同名只是候选依据。旧事件超录像保存范围时显示不可用，不伪造精确绑定或录像存在 |
| 两端直播：“看看运营走廊现在的画面” | 各端在自己的目录检索；视频详情→实时画面；点击立即进入播放页，再取流、接入 SDK；返回恢复原对话/列表 | 不等取流成功才切页；取流失败可立即返回/重试，失败不等于摄像头离线 |
| 两端回放：“看昨天 14:00–14:20 茶水间录像” | 明确日期、摄像头和窗口→回放卡→同一 H5 的回放模式；显示录像时间而非 LIVE；范围过大提示缩小或明确分段 | 实时离线不证明历史录像不存在。首次取流成功不证明历史模式、进度/暂停/拖动能用；重试固定原范围/source |
| 后续人数分析：“昨天 14:00–15:00 茶水间人数情况” | 独立分析任务读取可解码片段，按已确认口径返回分析报告、覆盖率和不确定性；结果可追问 | 属我方后端分析，已有责任决定不再向客户索取海康人数接口。但 WSS 地址不是视频文件；提取、解码和准确率均未证明，当前不能承诺此场景已具备 |

“趋势/统计继续追问”首期复用同轮持久化观察证据和确定的设备/时间范围。前台主动“引用这份分析”可在该业务切片上按需要增加类型化引用；不把大而全的通用分析平台作为所有接口接入前置。

## 接线位置与建议接口

本节为候选公开契约，名称和字段尚未冻结，不应当被当作已经存在的端点。

1. Runtime 的 `apps/runtime/src/iot/observation.ts` 复用现有身份、分页和错误约定，增加环境历史、电量历史和回放查询。物联适配器先按来源确定设备，再绑定上游设备 ID；模型不拼客户 URL、actionId 或租户参数。历史聚合先放在对应业务模块，不预建通用数据仓库。
2. 环境/电量为 Company 公开查询路由和 Agent 工具共用同一读取/统计函数；例如环境历史 `source + from/to + page/limit`，电量历史额外携计量点 ID 集合。返回 `requestedRange / actualCoverage / observedAt / rows或series / metrics / warnings / pageInfo`；已授权范围、单位及统计字段由后端确定。可分别增加 `query_environment_history`、`query_energy_history`，沿 `observation.reported` 扩展历史结果块，恢复即重放。
3. 视频复用 `/api/agent/devices/:id/video-stream` 服务边界，支持明确的 `source + mode(live/playback)`；回放携 `beginTime/endTime`，直播不携录像窗口。首次返回短时效流地址和本次模式/范围；不保存流地址到会话卡、任务库或通知。Company 现有直播走智慧监控 `monitor/down`，回放则用已授权设备绑定出的 hubDeviceId 调新动作；Office 同样先核验自己的摄像头。
4. 安全查询扩展 `SafetyLedger`、引用校验和详情到 `smoke`；查询类型选择在上游读取前生效。新汇总使用独立烟感记录和目录核实后的水浸记录。旧 `flooding` 烟感引用仍按原 ledger/eventId/deviceId 查历史来源，不静默改写身份或清理历史卡片。
5. mp 的 `apis/agent/index.js` 增加上述读取封装；`dashboard.vue` 原有环境/计量/安全入口进入对应详情，`ObservationCard.vue` 呈现结构化结果；趋势按指标切换，安全用常规列表，监控用共用视频详情/播放器。参数选择、返回与结果刷新保持现有单层 Sheet 和状态恢复规则。
6. 自建 H5 复用既有官方 SDK 资产，核验实际回放 API/模式后接入；不因 WSS 形状与直播相同而复用直播调用参数。原生小程序不承担 WSS 解码。

客户 Swagger 的实际参数：环境含 `startDate/endDate`（yyyy-MM-dd）、`startTime/endTime`、租户和分页，无明确设备过滤参数；电量含 `equipmentId/equipmentIdList/areaId/startTime/endTime`；三台账含 `deviceId/elementId` 和分页，本轮 Swagger 未声明告警时间过滤。参数存在仍需用有效/空窗口、指定/不存在设备以及分页重复边界验证语义。

## 当前问题及处理方向

| 问题 | 接入影响 | 处理方向 |
|---|---|---|
| 现有 PM 标签反了 | `observation-view.mjs` 将 pm10 显示 PM10、pm101 显示 PM1.0；与本轮物联中心 Swagger 矛盾 | 规范化为语义字段并校验实时/历史两条来源。官方定义 `pm101=PM10`、`pm10=PM1.0`，`pm25=PM2.5`；数字大小关系只能辅助，不能替代字段定义。温湿度有单位，颗粒物浓度单位仍需原文核对 |
| 电量字段存在正反向冲突 | 旧约定为正向有功总电量，交接称客户指定 epf，Swagger 则标 epf 反向、epz 正向；样本相等只证明数值关系 | 先支持原始历史；统计按客户指定字段记录口径，物理方向、单位/倍率与表计用途在统计切片冻结。未核实前不把 epf 结果直接命名为“公司正向总用电” |
| 电量当前采集中断 | 今日/近月统计无采样，历史仍有大量记录 | 可用历史期间真实验收；今日明确无数据，维修演示与真实历史独立。采集修复后补近期验收，不阻止开发历史功能 |
| 统计边界、负增量和计量重叠 | 缺少窗口边界采样、表计清零/更换/回绕或上级与分表重叠会产生错误 | 差值计算必须保留边界采样/覆盖；负值标异常，不取绝对值/补零；默认不插值、不以首末区间内采样冒充完整日。跨表汇总需明确不重叠集合 |
| 环境历史 deviceCode 为空 | 无法证明特定房间/设备的历史归属，多设备扩展受限 | 当前先做 Company 站点趋势；同租户只有一台设备也不自动证明每条历史属于这台。按现有站点口径查询；具体设备历史进入时再补标识契约 |
| 烟感、水浸混表 | 新烟感接口与旧水浸记录可能重叠，简单相加会重复统计 | 根据当前安全目录设备子类和端点来源识别；无法归类的记录单独说明。分别验新列表统计与旧引用兼容，不凭原始数量直接相减得水浸数 |
| 旧台账分页上限且前端只拿少量摘要 | 现有读取最多五页，Agent 只输出前八条；扩大历史范围后会漏数 | 详情/历史列表按需翻页，明确 total 是上游原始总量、授权分类总量还是已读取数量。无法完成全窗口统计时输出不完整覆盖，禁止用截断样本称全量 |
| 回放尚未进入生产代码 | Runtime 只有直播端点；播放器目前只使用直播 JS_Play 模式 | 核验官方 SDK 回放模式和真实录像，逐步开放已验证控件；拖动/倍速不得仅凭原型外观开放。摄像头当前实时离线时也允许尝试回放 |
| Company 播放被前端禁用 | `AgentReplySurface.vue` 给 Company 观察卡强制 readOnly；ObservationCard 因此只显示播放未接入 | 按独立“可查看视频”能力开放；观看与设备控制分开，不能为开放播放放宽其他控制范围 |
| H5 重试来源/身份参数不一致 | 当前首播 source 只用于原生取流；H5 再取流不传 source；H5 读 tenant，现有 webView 注入 tenantCode | 首播、重连都显式带原 source 和一致身份/租户。Company 重试不能缺省成 Office。标题与返回维持原模式/窗口 |
| 播放页未配置且存在凭据日志 | videoPlayerUrl 返回空；旧 webView 将含 token 的完整 URL 打到控制台，H5 又需从 HTTPS 调本地 HTTP API | 确定播放页部署/微信业务域名及可达 HTTPS Runtime 代理；核验 CORS、混合内容和真机网络。接视频切片时移除敏感 URL 日志并收口身份传递，优先桥接/短期票据，不能把旧注释当已安全完成 |
| code 207、会话释放与录像保留未知 | 已知直播孤儿会话/并发可能使多摄像头取流暂不可用；回放是否同样受限未证 | 用户主动重试，避免无限自动取流；退出/换流可靠等待 JS_Stop 收口；询问保留时长与会话限制，同时用近期真实录像验证。取流失败不改成离线 |
| 告警与监控关联没有唯一绑定 | 同名地点可给候选，但无法证明画面覆盖报警点 | 复用智慧区域/安装地址；有歧义让用户选，不重新索取整套权限机制或强制要求新关联接口 |
| 人数分析输入链尚未证明 | 浏览器能播不等于后端可以截帧、解码或正确计数 | 独立技术样例证明获取/解码，再定义同时在场人数或去重通行人次、采样与准确率；两者不可混称，失败不输出零人 |

## 前端预期质量与等待策略

- 沿用纸面浅色材质、玉绿主动作、克制的描边/圆角和既有文字层级；保留底部安全区与原生返回。趋势是常规图表，安全是常规列表，摄像头是视频详情；不将它们强行做成任务时间轴。
- 页面/Sheet 外壳先显示且返回立即可用，再独立请求当前所需指标/记录。直播/回放先导航，加载在播放器内进行；不能沿用当前 `openVideoPlayer` 先 await 取流再 navigate 的等待顺序。
- 首屏只读所需摘要和小窗口；查看详情才拉相应历史。用户切日期/设备后丢弃旧请求结果并允许退出，不把 176,179 条全部拉到手机，不逐台串行扫全部电表。
- 给出采样时间、请求范围和实际覆盖；无数据、身份失效、上游故障、部分覆盖分别显示。已有结果可以带时间保留用于浏览，但不能把长期“核验中/已保留数据”作为新查询的完成结果。
- 分别记录点击→可见反馈、点击→页面可操作、请求→首屏数据、取流→真实首帧。建议体验目标：按下反馈约 100ms 内，已有页面的详情壳约 300ms 内可操作；属待真机测量目标，不能据本轮 HTTP 耗时声称已达标。

## 按业务闭环推进

不按“先建所有后端、再建所有前端”推进。每个切片都包含查询、前端呈现、继续对话、失败/返回、实际证据和交接。

| 顺序 | 单个闭环 | 完成条件与前置 |
|---|---|---|
| 1 | 独立烟感/水浸列表→详情→引用 | 接 smoke；水浸污染处理；新旧引用兼容；真实窗口/分页/多类型对话证明，无设备写操作 |
| 2 | 公司环境历史→趋势→追问 | 修正 PM 映射；站点历史口径；窗口/缺失呈现；仪表盘与 Company 共享结果。无 H5 部署依赖 |
| 3 | 两端摄像头→直播/近期回放→返回/重试 | 共用源敏感取流、Company 观看入口、H5 回放模式及身份参数；开发期验证 SDK 真实首帧，生产验收依赖部署路径/HTTPS与微信域名 |
| 4 | 单计量点真实历史→区间电量→Company 解释 | 先冻结累计字段/单位/倍率和边界；用 2025 年可用样本证明计算及无今日数据；同一统计供仪表盘和 Agent 使用 |
| 5 | 非重叠计量集合→对比/排名/日报 | 依赖单表闭环和汇总集合，不以“43 台求和”绕过；报告载明范围/覆盖/异常，随后按需复用已有 Task 与收件箱做定时报告 |
| 6 | 回放片段→后端人数分析报告 | 在回放可播之外先证明可提取可解码；冻结计数口径和准确率后成为单独闭环，不扩展人脸识别 |

这是建议顺序；第 3 项部署协调可在第 1/2 项期间准备。各切片开始前才预估实际新增代码和最小公共接口，避免本轮先建无消费者的大量基础层。无人值守消防联动、告警处置写入、PTZ/对讲/录制和新外部推送均不由此次历史接口自动扩大范围。

## 验收方式

| 切片 | 公开行为回归 | 真实网关/前端证据 |
|---|---|---|
| 安全 | 新 smoke 详情/引用；错误来源/设备不可读；混表不重复算水浸；旧 flooding 烟感引用可追溯；失败不显示已恢复 | 两类筛选、翻页、点详情、保留草稿引用、Company 发问和返回；清楚区分 2024 历史与当前记录 |
| 环境 | 时间过滤/空窗口；tem/hum/PM 三种正确映射；null 标识不生成房间归属；缺失采样不补零；恢复不重查写入 | 仪表盘进入趋势、Company 同范围读数一致、峰值追问、切日期与返回、窄屏/真机 |
| 视频 | 两 source 授权独立；回放模式/三天限制/窗口合法；错误身份不可取流；重试不丢 source/窗口；持久化卡无流 URL | 两端分别检索与打开；实际近期录像首帧和 OSD；已验证的暂停/定位；返回释放后再次打开；故障可立即退出 |
| 电量 | 累计差值；完整/部分覆盖；空当日；清零负值；跨页同时间点；单位/倍率；基期零；跨表重叠拒绝总汇 | 历史真实计算与原始边界读数对照，前端同一结果，今日无数据，演示/真实切换与解释 |
| 人数 | 有输入证据才出结果；无片段/解码失败与零人区分；结果身份/时间窗一致 | 独立录像人工标注与后端报告比较；未定义口径/准确率前不写“已完成” |

验收必须包含实际微信页面点击、加载可退出、重连、返回状态；协议夹具、截图或取流 HTTP 200 不能替代真实画面/手机验证。此次准备阶段不需要为文档新增测试，业务实现时从公开路由/对话流进入必要回归。
