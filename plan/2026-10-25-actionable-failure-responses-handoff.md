# 失败答复与操作建议交接

2026-10-25。用户要求改进 prompt：失败任务应承接原目标并给操作建议，避免生硬统一的失败收尾。通过 ask-matt 进入小切片实施；提示词按 langfuse 的失败观察→最小修改→真实模型验证流程迭代。范围见[票11](../.scratch/agent-error-recovery/issues/11-actionable-failure-responses.md)。

## 实施

Runtime 仓库 `../iot-agent-runtime`，基线 `67d2a09`，提交 `6232607`、`1f113de`、`f0ddd33`。只修改 `apps/runtime/src/agent/pi-runner.ts`、原有公开回归及模块说明；没有新增依赖、API、恢复框架或前端入口。

- Office/Company 共享失败沟通规则：先按现有权限与预算恢复；仍未完成时说明阻碍、保留成果及一两项实际可行的下一步。只追问缺少的业务信息，参数构造问题由助手承担。
- 读取故障沿原范围/期间恢复，不推断数据存在或消失，不建议靠改日期绕过。授权不足先恢复相应访问权限。
- 确认回包丢失或执行结果未知，先按原对象读任务/回执；列表缺项与详情503均不证明未创建。重新准备、改时间/范围和设备控制仍受原授权/确认边界约束。
- 失败有模型答复和确定性收据两个出口。原提案失败收据“本轮已结束，未安排后续处理”已替换为重新读取/沿原要求继续准备的建议；报告解读失败则引导打开或追问已保存的原报告。
- 专用任务准备失败后的模型正文也由同一收据谓词抑制，防止正文先流出没有依据的后台承诺；能耗仍准备中/暂不可用的收据同样保留原范围、期间及已保存附件。
