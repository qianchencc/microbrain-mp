# 安全事件台账缓存诊断与后续修复入口

2026-10-26。状态：诊断完成，产品代码未修改，未编译或发布。本轮用户通过 `/ask-matt` 要求判断如何处理类型切换重复读取问题；此前空调回读会话是背景，不属于本轮范围。

## 已证实的原因

`apis/agent/index.js` 的 `listSafetyHistory` 直接调用 `request`，没有进入 `companyRead`。首页的告警概览已进入统一缓存，概览成功复用不代表独立台账列表也复用。

`pages/agent/components/SafetyHistoryList.vue` 切换类型执行 `reset()` 后 `load()`，重新激活也会 `load()`。当前没有 API 缓存承接这些读取，因此相同类型和日期短时切回仍发送网络请求。此处的 reset 清的是组件状态，不是统一缓存；仅删除 reset 会有显示上一类型数据的风险。

## 可重复证据

隔离夹具运行真实导出的 API 客户端，只替换配置、身份与 `uni.request` 网络边界，不连接客户或生产服务。

```sh
node /private/tmp/safety-cache-20261026/repro.mjs
node /private/tmp/safety-cache-20261026/probe.mjs
```

- 第一条已实际失败：燃气→烟感→燃气，相同身份、日期、limit，实际 3 次网络请求，期望 2 次。
- 第二条已实际通过：概览调用 2 次，进入缓存 2 次，网络 1 次；台账调用 3 次，进入缓存 0 次，网络 3 次。排除了缓存键不同或响应被缓存淘汰作为本次 API 重复读取的原因。
- 夹具是本机临时证据，后续实施将场景转成仓库内公开客户端回归，不依赖临时目录长期存在。
- 尚未做真实微信点击和生产网络计数；本结论证明源码客户端缺接缓存，不宣称已完成现场验收。

## 冻结的修复范围与验收

按单个闭环推进：安全台账类型/日期切换→短时切回→显示对应列表→打开详情→返回。先修 API 接线，生产代码预估 10–30 行；仅在交互验证证明需要时调整组件。复用现有缓存，不建立第二套台账缓存或后端同步机制。

1. 在真实导出 `listSafetyHistory` 的测试接口复现上述失败。现有客户端别名加载方式可参考 `test/agent-stream.test.mjs`，缓存边界参考 `test/agent-company-cache.test.mjs`。
2. 将列表读取显式接入 `companyRead`，保留原先忽略 null/undefined/空字符串的查询语义，查询键固定参数顺序，包含类型、起止时间、limit 与 cursor。提供现有 `options.force` 绕过方式；沿用 60 秒、身份隔离、在途合并、失败不缓存及权限拒绝清理。
3. 验证同一类型首次读取、不同类型各自读取、60 秒内切回新增零请求；同参数并发只发送一次；过期/强制刷新重新请求；失败后可重试；换身份及迟到响应不串数据。
4. 验证分页、日期变更与三类台账不会串页；有 nextCursor 不应直接等同业务截断，需按真实响应确认缓存资格。超过一页后返回详情可能使用不同 limit，须实测请求数，不能仅凭首屏测试宣称全部返回路径零请求。
5. 在客户微信环境检查燃气→烟感→水浸→燃气、详情返回、关闭重开、快速连续切换；保留记录所属类型和已有迟到响应保护。按变更运行必要测试与微信编译后，记录证据、提交对应修复。

详情的权威重读、关联摄像头和视频短地址保持现有实时读取约定。API 缓存接线通过后再依据真实体验判断是否需要恢复各类型滚动位置或已加载多页状态，这些不属于本次必要修复。
