# 双 Agent、仪表盘与自动化核心规格

日期：2026-10-02。Status: accepted core specification — D01/D02 and 16-slice breakdown approved; remaining decisions scoped below。

用户认可上一轮明确提出的推荐边界及 16 条切片：D01 保留旧跨来源历史展示/审计并隔离后续 Office 规划；D02 各端默认查询本端任务，暂不接跨端共享。本规格的已定核心可按批准切片实施；条件/持续事件、治理、统计和客户契约仍按下表限制对应工作，不因整体认可自动补齐。

## Problem Statement

现有办公室 Agent 的即时控制及一次性任务无法覆盖客户新要求：物联助手需要高级仪表盘、微脑公司 Agent 和办公室 Agent 两套业务来源；用户希望两个 Agent 都支持自动化，并把复杂任务管理交给对话。当前周期/独立区间/编辑/后台只读报告和结束通知未完整落地，账号级观察来源曾越界进入办公室。原型能演示体验，不能证明真实设备、调度或正式小程序可用。

## Solution

物联助手首屏采用已认可的 A 园区运行总览方向，承载有明确数据质量的公司概况及两入口。公司 Agent 从微脑处理公司设备、能耗、告警和报告；办公室 Agent 使用 Office 授权设备。复用一套任务/周期/区间执行规则，各按本端真实能力执行或读取。

对话负责理解、澄清和管理提案，用户确认明确影响；前台保留查看、删除/取消、引用和确认。后台保存执行快照、按时运行、记录结果和报告。观察面沿用户指定的重要参考组织视频、环境、能耗和台账块。告警由客户渠道进入具体事件，结束通知由我方记录事件并与客户发送服务接线，点击返回同一次任务报告。

## User Stories

### 入口、来源和身份

1. 作为用户，我希望物联助手首先展示公司运行仪表盘，以便快速掌握设备、能耗、告警和自动化概况。
2. 作为用户，我希望数据注明范围、时间、单位及演示/陈旧/缺失状态，以便正确理解指标。
3. 作为公司 Agent 用户，我希望点击客服式按钮展开对话并正常返回，以便查询公司设备与报告。
4. 作为员工，我希望从仪表盘二级入口进入办公室 Agent，以便处理我的 Office 授权设备。
5. 作为员工，我希望客户“我的办公室”也能打开办公室 Agent，以便沿原有工作入口使用。
6. 作为用户，我希望两个入口分别恢复原会话和草稿，以免切换时串用设备或丢失输入。
7. 作为员工，我希望办公室无法读取尚未纳入 Office 权限的账号级环境/消防/能耗，以免业务越界。
8. 作为用户，我希望任务长期归属稳定主体，凭据变化不意外换人，以便持续管理安排。
9. 作为用户，我希望来源无法核验时明确失败，以免静默扩大设备范围。

### 自然语言提案和引用

10. 作为用户，我希望设备歧义、时间或编辑范围不清楚时先澄清，以便确认准确安排。
11. 作为用户，我希望完整提案显示设备、时间、重复规则、区间、检查点和目标，以便批准具体行为。
12. 作为用户，我希望未经确认不创建执行授权或下发控制，以便避免意外操作。
13. 作为用户，我希望从任务详情快速引用到原输入框，保留草稿且不自动发送，以便补充自己的意图。
14. 作为用户，我希望能移除引用而保留文字，以便改变提问对象。
15. 作为用户，我希望引用定位准确计划、本次发生或实际记录，以免按同名对象误操作。
16. 作为用户，我希望消息发送、编辑、重试固定该轮引用，以免后来选择的任务改变原消息语义。
17. 作为用户，我希望引用已结束报告问原因，而不是重新执行，以便复盘同一次事实。
18. 作为用户，我希望权限撤销、对象删除或版本变化时旧提案明确拒绝，以免覆盖新版本。

### 周期、区间与管理

19. 作为用户，我希望创建一次性或每天/工作日/指定周几的安排，以便覆盖常用重复业务。
20. 作为用户，我希望区间起止与检查点独立，以便自由安排执行点而不改变任务边界。
21. 作为用户，我希望时间轴显示推导的未来发生，并由实际 Task 替代已落账发生，以免重复显示。
22. 作为用户，我希望通过 Agent 仅修改本次或以后全部，以便不影响其他日期和历史。
23. 作为用户，我希望未来检查点/设备目标的变更重新校验并确认，以便控制实际影响。
24. 作为用户，我希望执行中快照和历史结果不被修改，以便追踪真实过程。
25. 作为创建者，我希望通过 Agent 启用、编辑计划，以便继续负责自己的安排。
26. 作为拥有全部目标操作权限的成员，我希望能委托停用计划并留下记录，以便停止未来影响。
27. 作为用户，我希望删除周期只停止未来，当前实际任务继续，以免误解操作范围。
28. 作为用户，我希望取消实际任务只停止未执行部分，历史不删除、设备动作不回滚，以便准确结束安排。
29. 作为用户，我希望跳过某个虚拟发生不影响其他日期且不产生实际结束通知，以便处理例外。
30. 作为用户，我希望跨午夜按开始日归属，截止日不截断已开始区间，以便理解同一次任务。

### 后台执行、只读与报告

31. 作为用户，我希望关闭小程序后后台仍按时执行，以便不必守在前台。
32. 作为用户，我希望重复扫描、重启及重复确认不重复下发，以便避免多次物理影响。
33. 作为用户，我希望执行前重新核对来源、授权和设备状态，以便不使用失效授权。
34. 作为用户，我希望已达到目标的设备无需再下发但保留结果，以便减少无用操作。
35. 作为用户，我希望全部检查点提前结束后区间仍显示进行中，到终点才汇总，以便任务语义一致。
36. 作为用户，我希望错过、失败、中断、部分完成、未核验能分别解释，以便采取后续行动。
37. 作为用户，我希望定时/周期读取本端有权设备并保留报告，以便实现两端只读自动化。
38. 作为用户，我希望观察块组合视频、环境、能耗、告警内容并注明各自证据，以便一次阅读所需信息。
39. 作为用户，我希望无房间覆盖、陈旧读数或缺态诚实表达，以免误认为现场状态已确认。
40. 作为用户，我希望依赖条件无法判断时不自动执行该动作，以便避免把未知当成满足。
41. 作为用户，我希望设备现态、执行回执与物理核验分开，以免现态刷新改写历史。

### 能耗、告警、视频和通知

42. 作为公司 Agent 用户，我希望电表维修时仍请求真实接口并明确展示演示覆盖，以便演示链路而不混淆真实采集。
43. 作为公司 Agent 用户，我希望能按已冻结范围/时间/口径查询统计和报表，以便理解公司用能。
44. 作为告警接收人，我希望客户推送经登录恢复定位原事件，以便查看该事件的建议和监控。
45. 作为告警接收人，我希望监控来自实际关联，以免查看模型猜测的“附近摄像头”。
46. 作为用户，我希望取流/播放失败不变成离线，返回时释放播放会话，以便可靠查看视频。
47. 作为任务创建者，我希望实际任务成功、异常或取消结束后得到通知，以便及时知晓结果。
48. 作为用户，我希望订阅不足/投递失败不改变任务执行结果，以便从应用内仍能查报告。
49. 作为用户，我希望通知打开同一实际 Task，重新订阅不静默重发旧通知，以免生成重复业务。

### 治理、真实验收与缓存

50. 作为运营者，我希望设备身份和审计贯穿提案、执行、报告和时间轴，以便追踪同一次业务。
51. 作为获授权的运营者，我希望确定性停控及恢复不依赖模型理解，以便明确阻止后续下发。
52. 作为获授权的用户，我希望查询/导出本期约定审计且保留演示标记，以便用于验收和复盘。
53. 作为用户，我希望真实小程序的 Sheet、输入、日历和 B6 时间轴在窄屏/连续操作时正常，以便顺畅使用。
54. 作为交付方，我希望正式后台、HTTPS/NDJSON、H5 与微信真机验收有证据，以便声明业务真正完成。
55. 作为交付方，我希望会话恢复和长会话压缩的真实缓存用量可解释，以便关闭已记录缓存问题。

## Implementation Decisions

### 已接受边界

- 物联助手模块入口改为仪表盘，不替换整个客户小程序首页。A 为视觉方向；观察响应面是重要设计参考，保留现有材质/头像/Sheet/B6。
- Agent 来源固定并由服务端按当前身份核验；不依客户端 source 值授予权限。同一主体的公司与办公室设备范围不合并。
- 复用当前会话/提案/确认/任务查询与执行模块；来源、稳定主体与旧归属兼容随真实闭环接入，不先横向重写所有模块。
- 公司目录/动作/回读依客户真实契约。空间未知可独立查询任务，不伪造 Office 区域；能力预留默认不开放。
- 引用是结构化对象身份及来源，展示名称/时间仅摘要；消息确认或执行时重新读取并核验，不把引用当授权。
- 管理是 Agent 提案→差异/影响→用户确认，查看界面不提供复杂管理控件；确认必须绑定对象、版本和明确内容，不靠模型任意执行。
- 周期计划保存模板，未来发生按规则推导；发生例外影响指定发生，到点使用持久化快照落 Task。历史与执行中快照不随计划编辑改变。
- 区间独立于阶段，无阶段数业务上限；可设置工程资源限制但不得伪装成“仅两阶段”领域规则。时间/设备/参数不合法时明确反馈。
- 执行器使用已确认步骤，不在后台持续调用模型重新规划。只读步骤与控制步骤按实际能力分开，条件未知不能放行依赖动作。
- 报告由持久化事实形成，现态不改写结果；缺权威回读保留未核验。通知意图/发送/投递与任务结果分开记录。
- mock 是维修演示覆盖，真实接口响应与覆盖值可区分，不切回全局模拟网关，不进入真实控制/安全依据。
- 客户负责设备告警发送；我方负责 Agent 落地、引用、建议/关联监控。Task 结束发送推荐接客户渠道，客户具体契约尚未确认。

## Testing Decisions

延续用户已认可的外部行为测试原则；测试以下完整行为，不镜像 SQL/组件实现。

1. **后端主入口**：消息→流事件/完整提案→公开确认→任务/计划查询→恢复会话，断言未确认无下发、绑定来源、对象/版本及报告事实。复用现有应用注入和生产协议网关夹具，不要求真实模型随机生成同一句话。
2. **后台时刻入口**：应用公开的到期扫描配合可控时钟，查询同一任务结果；关闭/重建应用复用临时存储验证恢复，观察网关接收次数验证幂等。新行为尽量沿现有入口，不新增仅供测试的管理员执行 API。
3. **权限/源边界**：通过公共 HTTP 发送越界引用、确认前撤权、变更源/身份、目录不可用；核对拒绝结果和网关零写入。旧会话恢复还核对后续模型收到的边界，不仅 UI 隐藏。
4. **前端主入口**：浏览器/微信实际点任务→引用→保留草稿→发送→差异确认→更新同一对象；同时走返回、移除、重试/编辑原轮和单层 Sheet 滚动。源码 regex 不替代用户操作验收。
5. **读取/事件证据**：观察采样时间/来源/缺态、陈旧/mock 标记贯穿报告；通知断言同一 task/幂等意图与独立投递状态，视频验证真实取流/播放/返回释放，不把三者混称成功。
6. **真实验收**：协议夹具证明本地规则；正式客户数据/HTTPS/NDJSON/真机及已明确授权的真实操作另留证据。mock 和本地样例不关闭真实业务票。
7. **缓存支线**：复用原始请求/usage 对照，核对恢复、工具回填和压缩后的前缀，不以字段存在证明命中。

公开接口优先复用现有消息、确认、详情、时间轴/日历与扫描入口；新计划/例外/查询接口按业务所需最小新增，具体命名在票内实施时确定。此处未要求搭通用测试平台。

## Out of Scope

- 新领导角色/RBAC、合并微脑与 Office 权限、Office 未授权观察接入。
- 前台规则/检查点编辑器、手动管理后台、多对象引用系统、任意组件注册或通用工作流引擎。
- 复制双份自动化、用范围选择或提示词授予权限、由位置文本伪造设备权威区域。
- 周期一期门禁/消防无人值守控制、PTZ/对讲/录制、模型执行中自主新增步骤、默认冲突裁决。
- 自动将记忆/偏好/会议等候选业务升级成本期；将历史合同其余项静默删除或当成已实现。
- 所有外部事件触发、回放、人员/道闸等是否本期由 D03 及范围核对决定；未决不等于正式排除。

## Further Notes

本规格已获用户认可的核心及 16 条切片，按本地 tracker 一票一文件发布。未决/外部项保持阻塞，每票只实施其获认可的完整闭环。原型的固定措辞、模拟设备/告警/计量数据和简化调度不作为生产实现复制来源。已认可的 UI 方向和领域规则不重复询问，局部客户依赖不阻塞不相关业务。
