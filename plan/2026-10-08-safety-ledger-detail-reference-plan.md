# 安全台账详情与对话引用实施计划

2026-10-08。状态：已实施并完成公开回归、真实网关只读与微信模拟器验收；效果、证据和真机未验边界见[闭环交接](2026-10-08-safety-ledger-detail-reference-handoff.md)。下文保留冻结规格。

## 本轮交付

一个完整切片：公司安全台账列表 → 点击单条记录 → 查看详情 → 引用到公司 Agent → 用户主动发送 → 后端读取同一记录并回答。仪表盘与对话观察卡共用详情及引用行为。

列表仍展示当前查询得到的最近记录；全部历史分页、筛选与搜索另列后续。设备告警由客户产生与通知，我方任务收件箱仍只承接 Task 结束消息。

## 当前事实与实现入口

- mp 基线 `60c78c6`，Runtime 基线 `fbd1028`；两仓已跟踪文件干净，mp 六个既有历史探索文件保持未跟踪。
- `ObservationCard` 的告警行当前只有时间、设备、位置、平台标记，没有点击行为；仪表盘在一个 `DeviceSheet` 中展示最近 8 条。
- Runtime 上游读取已有事件 `id`、`deviceId`、类型、`createdAt`、`alarm/report`，但仪表盘响应与 Agent 告警观察事件丢失事件 ID。燃气与烟感/水浸来自两个独立台账接口。
- 当前 `customer_alert` 是客户自由文本引用，服务端明确标为未经核验的上下文。Task/Plan 已有按身份读取真实事实、原轮引用持久化及草稿保留机制，可沿用其接线方式。
- 现有上游能力是分页台账读取，尚未核验单条详情接口。台账读取每个接口最多 5 页、每页 100 条，未找到目标不能直接宣称事件已删除。
- 感知目录实际有 `installAddr`，当前映射只读 `installAddress`；本切片补兼容以展示真实位置，不从设备名猜房间。证据见[接口盘点](../docs/research/2026-10-08-interface-source-boundary-audit.md)。

## 已冻结的体验

1. 每条记录作为可点击行，补右箭头、按压反馈和至少 44px 的点击高度，时间/设备/平台标记保持可读。
2. 详情沿现有 Sheet 的单层导航：左侧返回列表并恢复滚动位置，右侧 X、遮罩和下拉关闭整层；原生返回先退详情，再关闭列表。
3. 点击立即展示本次读取的记录快照与读取时间，后台只在打开详情时核验对应记录。核验过程中页面可以返回；失败显示重试，旧快照明确标为此前读取。
4. 详情展示记录类型、设备、位置、记录时间、平台上报标记及读取时间。当前时间字段来自上游 `createdAt`，文案用“记录时间”，不冒充物理事件发生或恢复时间。
5. 沿用纸面底色、细描边和玉绿主按钮。主操作为“引用到对话”；待核验成功后可用。进入 Company 输入框，引用可移除，已有草稿保留，不自动发送。
6. 从对话观察卡打开同一详情，引用回当前 Company 输入框；从仪表盘进入 Company，返回时恢复原台账阅读位置。

## 事件身份与读取规则

- 结构化引用保存 Company 来源、台账来源、上游事件 ID 和设备 ID；事件身份按“台账来源＋事件 ID”区分，设备 ID 同时参与一致性校验。台账来源直接来自调用的燃气或烟感/水浸接口，不按设备名称推导。
- 新增独立的安全台账记录引用类型，保留原 `customer_alert` 自由文本桥的原意与兼容性；客户端名称和标记不能作为权威事实。
- 详情公开读取接口和消息发送前核验共用同一读取逻辑：读取当前 Company 授权目录，只在其安全设备中查找匹配记录。Office 拒绝此引用；换身份、越界设备、伪造或缺失身份均不能读取。
- 优先复用已验证的台账读路径；如没有已验证的单条上游接口，按来源在有限分页范围内查找，不增加告警数据库、通用缓存或新权限系统。未找到提示“当前查询范围内未找到这条记录”，上游失败与权限失败分别表达。
- 发送、重试、编辑原轮时按原事件身份重新核验；流事件与历史保留原引用身份及服务端展示摘要。新选引用不替换旧轮；后续普通追问可使用明确标为历史读取的上下文，不假定设备现态。
- `report` 只表达平台标记，语义延续当前边界；已上报不等于已恢复，未上报不等于仍在报警。未知位置、恢复、责任人、预案与监控关联不补造。

## 实施顺序与规模

按一张业务票完成，内部先后如下，单层 API/UI 的完成不单独计为业务交付：

1. 从公开 HTTP 写回归：稳定事件身份、Company 详情、跨来源/设备拒绝、引用消息及恢复、重试核验、上游不可用；复用生产协议网关夹具。
2. Runtime 补事件身份、位置兼容、详情读取与消息引用核验，同时让仪表盘和告警观察事件携带身份。
3. mp 接通可点击记录、共用详情与单层返回、Company 引用静带；沿用现有输入框和跨页面草稿保存。
4. 微信实际操作与真实只读联调完成后记录证据，运行对应检查，再分别提交两仓的同一闭环并回填交接。

预计新增/修改生产代码约 250–400 行，测试与文档另计；复用 DeviceSheet、输入框引用、现有目录与分页读取，不引入基础控件依赖。若必须新增上游接口或范围超出此切片，先记录明确阻断项。

## 验收关闭标准

- 同设备两条记录分别点击、引用，模型收到的事件身份和服务端事实准确；两个台账同 ID 不串记录。
- 真实微信完成首次打开、详情返回、连续开合、整层关闭、原生返回、引用、移除、保留草稿、用户发送、历史恢复及原轮重试；包括长名称和窄屏。
- 详情点击先出现快照与可返回的界面；核验等待单独展示，不阻塞切换。测量点击到详情可用、核验请求耗时及进入 Agent 的耗时，与现有页面性能基线比较。
- 详情关闭、切换记录、换身份之后的迟到响应不覆盖当前记录；首次懒挂载确实发起核验请求。
- 无权限、查找范围外、接口失败及缺失字段有明确反馈；缺失稳定事件 ID 时可读快照，但不能生成伪造的结构化引用。
- 公共 HTTP、前端行为测试、类型检查、构建、微信编译和 diff 检查通过；真实网关只读取得一条记录并核对详情和引用回答，完成一次完整 NDJSON 终态。
- 记录真实网关、夹具、模拟器与真机各自证据；仅做只读查询与用户主动模型追问，不触发设备控制、告警处置或通知发送。
