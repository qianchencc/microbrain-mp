## 本次纠正

“查询最近三个月公司用电，自行统计”首先要求统计结果。逐表切换的月度增量/环比图不能代替统计。请求时间也不应因旧组件只接受周数或月数而被改写。撤销“公司月报已经满足统计需求”的结论。

本次保留用户选中的 A 图表方向、纸面/玉绿材质和底部抽屉，重新设计三个业务结果。业务方向、计量范围、时间窗口是三个独立维度。日、周、月只用于结果分组，不决定能不能查询。

## 三类问题与组件

| 用户问题 | 工具建议 | 主组件 | 首要结果 |
| --- | --- | --- | --- |
| 这段时间用了多少？各处用了多少？ | `summarize_energy` | `EnergyStatisticsReport` | 区间总量、有效范围、分段/分组构成、逐表结果 |
| 与另一段时间相比变了多少？ | `compare_energy_periods` | `EnergyComparisonReport` | 两期值、绝对差额、相对变化、可比范围 |
| 数据/用电有什么需要核查？ | `inspect_energy` | `EnergyInspectionReport` | 检查规则、发现、未覆盖项、涉及电表和采样 |

统计无需基期；统计图不出现自动环比 chip。对比须明确双方；不以最高/最低柱子替代对比结论。检查不等同于对比或现场故障诊断。

## 共用输入和事实

建议三个工具复用同一套确定性读取/区间计算，分别返回业务结果。不要向模型暴露分页拼接、日期边界猜测、单位换算等内部维护工作。

```text
source: company
scope: 当前接入范围 | 已授权区域/电表集合 | 单台稳定电表 ID
window: { from, to, timezone: Asia/Shanghai }
bucket: none | day | week | month      // 统计/对比展示粒度
```

- `from/to` 为明确时刻，使用 `[from, to)`；边界差分仍读取终点时刻的累计示数。
- “最近两周”是请求时刻前推十四天，“最近三个月”是按当地日历前推三个月；不是自动改成两完整自然周或三个自然月。用户指定自然周/月时才按日历边界。
- 若接口只有每日 08:00 采样，保留请求时刻，另返回实际观测时刻；不能偷偷把 00:00 请求换成 08:00 后声称完整覆盖。
- 末段/当前时段可显示“截至 …”，不补齐未来，不把部分时段直接与整段比较。
- 日/周/月切换重新投影同一窗口，区间总量不改变。只有存在对应边界证据时才绘制细分柱；缺失处留空。
- 同一计量口径的有效边界差分乘已确认倍率得到区间电量。负增量、清零/换表、重复时间冲突、读取失败保留各自原因，不能取绝对值或补零。
- 支持任意有效起止窗口，并不承诺无限读取。服务端预算用尽返回已取得结果与剩余范围，不能静默截断或诱导改成月查询。

共用结果事实建议：`reportId / kind / source / requested / observedAt / basis / coverage / meters / issues`。`basis` 明确字段、方向、单位、倍率和计量集合版本；`coverage` 区分授权数量、读取完成数量、可计算数量、可汇总数量及实际时间覆盖。读取完成不等于可统计。

## 统计

### 输入与计算

默认处理本端全部已授权接入电表，不要求老板逐表选定。区域/指定集合/单表沿同一工具走；请求“全公司”时记录意图，并检查接入集合是否确实覆盖公司。

- 总量：对已确认无重叠、单位/方向一致、倍率明确、边界有效的集合计算。可配置的确认口径是事实来源，不由模型或用户一句“自行统计”补造。
- 部分总量：仅当一个可解释子集具备上述口径时才提供“小计”，明确缺失项；不是“公司总量”。
- 各表：逐表区间增量、起止证据、可计算状态。单位未确认仍可列原始示数差；不同未核验倍率的原始差值不作贡献排名。
- 构成：同一总量按有效时间桶或已确认计量映射分组。总表和分表不能共同累加。缺少分组映射时不从设备名字臆造部门统计。
- 日均：只对完整且明确的实际区间计算，并声明有效跨度；部分表的小计日均不冒充公司日均。

### 主卡层级

1. 固定业务名“用电统计”；对象、请求起止时间、实际观测差异。
2. 已核验总量用大数字 + kWh，下一层为日均/覆盖；不以单表选择器占据主位。
3. 分段柱状图：零基线、统一坐标、清晰单位，日/周/月为小型切换；桶不足时不强画。
4. 同口径电表/区域构成，全部明细进抽屉。
5. 口径未确认时主位显示“已完成 N 台区间统计”，接逐表结果；明确待确认项和自动读取范围，不显示虚构总量、伪 kWh、跨表排名。
6. 无结果时显示缺失边界/读取失败及范围；不出现正常绿色完成结论。

`summary` 建议分离 `total`、`subtotal`、`average`，每个指标带单位、有效集合、有效窗口和状态。不能只有 `usage:null` 加一堆提示，让客户端自己决定含义。

## 对比

```text
scope + periods: [{ from, to, label }, ...]
comparison: previous_equal_window | explicit
```

- 支持用户指定两段或多段时间，不再限制“2–6 个采样周”。未指定基期且要求环比时，选择上一个等长区间，并显示两段实际时刻。
- 先分别计算统计事实，再验证设备集合、单位、倍率、实际时长和边界覆盖一致。
- 缺失电表时，范围对比仅使用双方均有效的相同集合，展示裁剪项；不能每期各自用不同数量后直接算百分比。
- 绝对差与百分比分开；基期为零保留差额，比例显示不可计算原因。不同长度区间不自动称为可比，可应用户要求明确比较日均。
- 单台同一稳定计量口径的示数增量可比较；不能借此推导全公司 kWh。
- 主卡为两期数值 + 差额/比例，下面并列柱/连续多个期间柱。采样依据同时包含本期和基期，原始采样窗口包括双方。

## 检查（推荐设计，仍待确认）

首期包含数据质量与有证据的用电变化核查，不建立告警处置平台。

- 数据检查：最新采样时间、请求边界缺失、重复时间冲突、负增量/可能清零、读取失败、单位/倍率与聚合口径缺失。
- 用电检查：在可比区间发现增幅、指定时段持续消耗等线索。采用用户指定或已确认规则，返回规则来源和实际证据；没有阈值时不自行建立“正常/异常”标准。
- 有数据时能做趋势/差额观察，不需要先拿到全公司聚合口径；但不能称原始示数为 kWh 或跨表比较大小。
- 输出 `findings[]`、`notChecked[]`、`rules[]`，每项绑定稳定电表 ID、时段、实际采样/计算。没有发现与没有检查不能混为一谈。
- 主卡是“待核查项”而不是用电走势图，优先列具体问题及涉及范围；点击进入规则与证据。
- 不从电量曲线推断漏电、设备故障、原因或安全。规则检查通过不证明现场正常。

## 共用交互与组件边界

- 三个业务组件放在既有 `ObservationCard` 中，根据结构化 `kind` 渲染；用户自然语言决定业务，不要求对话里再选业务 tab。原型切换器仅用于评审。
- `EnergyReportFrame`（如确有三个重复宿主再提取）只负责标题/范围/状态/共用操作；统计、对比、检查保留独立主视图。
- `EnergyEvidenceSheet` 使用既有 `DeviceSheet` 单实例承载“范围明细 → 单表依据 → 原始采样”，有返回与关闭；不层叠新 Sheet。`MeterHistoryView` 复用分页/真实身份与窗口。
- 图表继续使用项目已有 SVG 图片承载方案；不直接导入 React 图表库到 uni-app。
- 宿主 flex 链、`height:0; flex:1; min-height:0` 保持，窄屏数据横向滚动；操作按钮始终明确居中。
- 无“继续追问”按钮，无强制“文字解读/重试解读”。结构化业务结果一旦可用即展示，采样/明细入口不被模型运行状态锁住。
- 用户明确要求解释/分析时，Agent 仍可根据保存的报告事实回答。不能用停止所有报告后的模型调用来取消分析能力。
- 报告引用携带 `reportId` 与来源，不把整份数据拼进用户文本；恢复/引用时复核授权。新问题若不是解释这份报告，不强制绑定旧报告。
- 读取中显示范围已固定、取得多少有效结果；停止/超时保留结果，保留未完成原因。读取失败、口径未确认、数据不足分别表达，不统一为“部分完成”。

成熟组件参考：[Animate UI Sheet](https://animate-ui.com/docs/components/radix/sheet)、[ReUI](https://reui.io/docs/)、[shadcn Chart](https://ui.shadcn.com/docs/components/base/chart)。借鉴交互层级、坐标/图例，原生宿主复用既有 DeviceSheet 和 SVG，不新增 React 依赖。
