# 现有 Agent 的设备发现与目标表达优化

日期：2026-10-09。Status: ready-for-agent。

用户已认可：保留现有业务底座，优化设备发现与目标表达，吸收完整集合、集合排除与按需浏览。用户已确认三票粒度、依赖与公开HTTP验收入口；本文为批准规格。认可方向不等于批准原位置分组方案的全部契约。

## Problem Statement

用户已经能通过双 Agent 查询、控制和安排任务，但宽范围查询会把真正需要的目标挡在展示窗口之外。当前主线把前50台明细当成候选集的全部可用成员，超过窗口就拒绝提案；整层操作又要求模型逐设备抄写，增加遗漏和多轮纠正的负担。

现有 Task、周期计划、确认、执行与报告已存在。需要解决的是同一委托中的目标取得、集合表达和意图保持。不能用工具改名、缩短提示词或局部测试通过代替业务改善。

## Solution

用户可以描述地点与设备，取得真实候选，选择、排除并调整时间；Agent 按必要程度补读事实，最终展示完整实际影响对象。明确要求整层时，Agent 可以表达一份已发现集合及其排除项，由 Runtime 展开成具体操作，交给既有确认与执行流程。

首条业务是照明委托：目标位于原展示窗口之外，用户从自然生成的两个选项中选择后者，只开灯带、格栅灯不动，并改到明确时刻；确认后到期执行，从同一 Task 报告继续追问。随后才扩展到整层即时操作及定时、周期集合目标。

## User Stories

1. 作为 Office 用户，我希望找到当前来源内的指定照明，即使它位于目录后部，以免反复换说法。
2. 作为 Company 用户，我希望使用智慧照明范围完成同一委托，以免员工与公司目录混用。
3. 作为用户，我希望名称命中的实际设备可被读取，以便辨别灯带与格栅灯。
4. 作为用户，我希望“后者”承接 Agent 刚才给出的两个选项，以免重新解释地点。
5. 作为用户，我希望没有明确两项时得到澄清，以免 Agent 猜选设备。
6. 作为用户，我希望“格栅灯不动”只排除格栅灯，以免系统额外执行相反动作。
7. 作为用户，我希望改时间后仍保留原地点、设备和开关目标，以免修改引起目标漂移。
8. 作为用户，我希望整层请求包含展示页之外的设备，以免把局部结果当成全部。
9. 作为用户，我希望“除了会议室”依据真实成员排除，以免未识别限制时误操作全部。
10. 作为用户，我希望确认前查看全部具体操作与排除数量，以便知道实际影响。
11. 作为用户，我希望只有确认当前提案版本后才执行，以免聊天中的选择被当成授权。
12. 作为用户，我希望未来任务保存完整目标，以免设备当前已满足就被永久遗漏。
13. 作为用户，我希望周期安排固定已批准的成员，以免新增设备悄悄进入计划。
14. 作为用户，我希望恢复后仍可讨论同一目标与任务，以免历史引用失效或扩大权限。
15. 作为用户，我希望报告说明受理、回读确认与未知，以免把总体结束误当成物理完成。
16. 作为用户，我希望原有计量历史、环境趋势、台账、录像和任务管理仍可用，以免定位优化牺牲已有业务。

## Implementation Decisions

- 从最新已提交生产主线做增量修改。隔离候选只提供可复用的局部思路，不整份覆盖业务实现。
- 沿用设备候选集与现有设备身份。查询集合是发现时固定的成员证据，引用属于当前用户、来源和会话；引用不授予执行权限。
- 区分服务器保存的实际匹配集合、模型可读明细窗口和查询覆盖事实。明细未全部展示不再单独决定提案资格；上游目录读取失败或实际覆盖未知仍不能宣称完整。
- 首票解决可读目标与必要补读。名称描述仍是调查线索，不因某个软词未命中就清空硬范围；也不把软命中自动升级成用户批准目标。
- 明确的地点条件按共同约束处理。条件分别有命中但无共同设备时，报告约束不能共同满足；回退建议供用户选择，不静默作为控制目标。
- 模型显示可以按需读取或展开已有分组。位置分组只作浏览投影；不新增规范地点数据库或第二套授权模型，不为本轮重建全部空间工具。
- 完整集合目标扩展在现有提案入口旁，兼容逐设备目标。表达明确包含集合、明确排除集合或设备以及结构化命令；Runtime 先确定实际成员，再核验并生成既有提案。
- 排除集合必须已被识别并限定在本次包含范围。未找到“会议室”不能当成已排除空集合而继续执行。实际匹配子集与所在空间全部设备必须分清。
- 首期集合命令只支持已接入照明的开/关，避免同时扩展异构空调参数和门禁语义。其他类型继续沿现有精确设备路径使用。
- 当前逐设备参数的50项上限与模型明细窗口分别处理。集合表达可展开超过50台的已知照明；不能只调大展示上限，或偷偷截断展开结果。保留已有执行资源边界；确实无法承载时明确拒绝完整请求，不假称已处理全部。
- 展开后的提案保存具体成员、动作、版本和时刻；确认及执行重新核验授权。新增设备不自动加入旧提案或周期模板；撤权对象按现有机制拒绝或记录不可用。
- 即时草案沿用当前状态过滤已满足操作的语义，排除项与未勾选项分开；未来任务保存完整目标，到期按需执行。
- 复用现有 Task、独立区间、检查点、周期计划、Occurrence、执行器、回读和报告，不改写这些生命周期。没有用户要求就不新增区间、重复规则或终点动作。
- 工具说明、提示词与守卫只随本票实际接口或已复现阻断调整。必要取证被次数规则阻断时，先以公开行为复现，再做必要修正；不先整体删除守卫。总时间、工具和运行预算保留。
- 报告追问只引用同一任务事实，不新建操作；用户时间按中国标准时间表达。受理未回读确认必须明确未知，不建议以重新操作证明历史结果。
- 已保存的旧候选、草案与任务继续可恢复。计量历史、录像准备和安全事件仍使用各自权威设备/事件身份，不强制迁移到位置分组。
- 前端复用现有草案卡、查看全部、任务提案与报告。只有公开流实际缺少必要范围信息时才补充字段与展示，不增加规则编辑器或重做界面。

## Testing Decisions

- 主验收入口是已有公开 HTTP 对话、恢复、提案确认及 Task/Plan 查询。设备实际调用通过生产协议网关夹具观察；时钟和模型应答使用已有注入能力。需要到期扫描时沿用应用现有扫描入口，不新增测试专用路由。
- 持久回归断言实际设备集合、动作、时间、来源、确认前零下发、执行后回执/回读和恢复结果。不得断言提示词字符串、内部 SQL、工具固定顺序或较少调用次数。
- 脚本模型证明确定性契约与边界；固定版本、模型、预算和目录的真实模型对照验证自然首轮、选择、排除、改时间和报告语义。两类证据分别报告，夹具控制不称为真实设备验收。
- 首票复用当前大目录轨迹与定时任务公开测试的模式，将目标放在原50台窗口之后，重排目录并更换名称；验收不依赖硬编码首轮候选文本。
- 正向情境之外，覆盖没有两项却说“后者”、仅匹配部分地点、排除项未知、来源混用、撤权、历史恢复与预算终止。反例不得产生越界提案或物理下发。
- 整层验收使用超过50台且可明确计算成员的夹具，比较包含、排除、已满足及实际操作集合；重复确认/扫描不重复控制。
- 定时/周期验收检查目标在改时间与恢复后保持，下一次发生复用批准快照；新增目录设备不自动进入旧计划。
- 公共协议改变时运行当前 Runtime 必需检查；前端改变时运行 Agent 回归与微信编译，并走查真实原生卡片。稳定业务切片完成才做一次规范/规格审查。
- 既有自然委托对照两版都通过，不能用它宣称新实现更优。交付必须展示原缺陷的改善，并检查原通过场景没有退步；失败保留，逐例报告。

## Out of Scope

重写位置分组方案全部工具、通用集合语言、目录去重/控制身份迁移、整个提示词重构、更换模型、通用评测平台、外部通知、调度补执行政策、新相对时间规则及新增业务能力。完整集合不改变授权来源、控制风险或任务编辑作用域。

真实设备控制与3200部署不是本轮规格准备动作。现场验收另需具体设备、动作及用户确认；原有H5和安全事件并行工作不混入本批。
