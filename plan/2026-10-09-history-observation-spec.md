# 历史观察与双 Agent 视频：业务规格

日期：2026-10-09。
Status: ready-for-agent — accepted direction; affected slices retain explicit decision and external gates.

用户已基本认可 [业务场景与接入方案](2026-10-09-history-interfaces-business-integration.md)，并要求按 ask-matt 具体准备。本规格固定现有方向，不宣称电量口径、SDK 回放或人数算法已获验证。本轮只发布规格与票据，不实施业务代码。

## Problem Statement

公司仪表盘和 Company Agent 目前以最新读数和少量安全摘要为主，用户无法查询环境趋势、真实历史电量及完整分类台账。两端视频尚未形成可用的共用观看链路，回放只有取流证据。新增接口已经可调用，但设备归属、字段映射、混表与播放状态仍可能造成错误解释和长时间等待。

## Solution

用户从仪表盘或 Company 对话查询同一范围的环境、计量和安全历史，得到带采样时间、统计覆盖和异常说明的结构化结果，能继续追问。视频在 Company 和 Office 中共用观看体验，各自从本端设备目录进入，先打开播放器，再取流。历史查询和观看本身不产生控制草案；告警处理仍由客户业务负责，涉及物理动作继续走既有显式确认。

## User Stories

1. 作为公司用户，我希望从环境概览查看今天的历史趋势，以了解一天中的变化。
2. 作为公司用户，我希望选择时间段和指标，以比较温度、湿度及颗粒物。
3. 作为公司用户，我希望看到实际采样时间与数量，以知道曲线的证据范围。
4. 作为公司用户，我希望缺失采样明确显示，以免把空数据当零值或连续观测。
5. 作为公司用户，我希望知道历史属于站点还是具体设备，以免误认某房间情况。
6. 作为 Company 对话用户，我希望查询同一环境窗口并追问峰值时刻，以减少反复选范围。
7. 作为公司用户，我希望查询指定计量点的历史累计示数，以检查真实原始数据。
8. 作为公司用户，我希望知道累计示数与区间电量的区别，以避免误读日用电。
9. 作为公司用户，我希望区间电量附实际边界读数和计量口径，以核对计算结果。
10. 作为公司用户，我希望今日无数据时明确显示无数据及最近采样时间，以避免看到旧数据冒充今日。
11. 作为公司用户，我希望显式切换到最近有数据的日期，以继续分析历史。
12. 作为公司用户，我希望对比同口径的期间并查看逐表排名，以找到变化大的计量点。
13. 作为公司用户，我希望公司汇总避免总表与分表重复计量，以得到可解释总量。
14. 作为公司用户，我希望报表说明缺失、负增量和覆盖不足，以判断能否据此决策。
15. 作为公司用户，我希望真实历史与维修演示始终区分，以免把样例当成事实。
16. 作为公司用户，我希望分别查看烟感、水浸和燃气记录，以获得正确分类。
17. 作为公司用户，我希望台账能够翻页并明确数量口径，以免把前几条误当全部。
18. 作为公司用户，我希望点单条详情并引用到 Company，以围绕同一记录讨论。
19. 作为已有会话用户，我希望旧水浸来源的烟感引用仍可追溯，以保留历史证据。
20. 作为用户，我希望上报标记与设备恢复区分，以免误以为隐患消失。
21. 作为两端 Agent 用户，我希望查看本端可见摄像头的实时画面，以完成现场观察。
22. 作为两端 Agent 用户，我希望指定日期和时间查看录像，以复盘历史情况。
23. 作为用户，我希望实时离线时仍可尝试回放，以查看已保存录像。
24. 作为用户，我希望播放页立即打开且始终能返回，以免取流等待看起来像故障。
25. 作为用户，我希望重试保留原摄像头、来源和录像窗口，以免跳到其他画面。
26. 作为用户，我希望退出或换流释放播放会话，以减少后续取流故障。
27. 作为公司用户，我希望由告警位置找到候选摄像头，以查看记录前后的画面。
28. 作为公司用户，我希望监控关联有歧义时自行选择，以免系统假装已经精确定位。
29. 作为用户，我希望返回后保留日期、筛选、滚动和原输入，以继续原来的工作。
30. 作为用户，我希望换身份、撤权或来源错误时停止读取，以保护数据边界。
31. 作为公司用户，我希望后续人数分析报告给出录像覆盖和计数口径，以判断可信程度。
32. 作为公司用户，我希望无法提取或解码画面时明确失败，以免被告知现场无人。

## Implementation Decisions

### 已固定的业务边界

- 仪表盘和 Company 使用公司环境/能源/安全历史；Office 不自动合并账号级环境、消防、能耗。双端摄像头共用技术能力，各自解析本端目录与 hub 身份，继续遵守现有来源 ADR。
- 不创建新权限平台、事件数据库或通用分析引擎。共用上游适配器、公开路由、Agent 工具、观察结果投影及现有会话恢复。
- 模型负责解释和选择必要查询，代码负责设备范围、时间合法性、字段映射、统计计算和结果覆盖；模型不拼客户接口或自由生成图表数据。
- 历史观察结果复用持久化观察事件，保存查询范围、采样证据和可解释指标；恢复重放原结果，新的查询独立核验当前范围。无必要不新建分析对象表。
- UI 复用既有单层 Sheet、返回边界、观察卡和筛选结构；安全是普通列表，趋势是普通图表，视频是观看页。保留原有纸面材质、玉绿动作与安全区，不引入时间轴式历史台账。
- 用户输入、旧轮引用与新结果分开；引用不覆盖草稿、不自动发送、不授予控制权限。新 smoke 引用可用；旧 flooding 烟感引用保留原身份和来源，不能静默改名或删除。

### 历史字段与统计

- 时间请求显式带时区；业务日为 Asia/Shanghai。上游无时区的日期按已有客户东八区契约解析。环境 createdAt 和台账 createdAt 是上游记录时间，不提升为精确物理发生时间。
- 环境历史 tem/hum 映射为温度/湿度；颗粒物按官方定义 pm25=PM2.5、pm101=PM10、pm10=PM1.0。实时与历史在适配边界转成同一语义，不就地改写旧事件中的原始值。颗粒物单位未核实时显示单位未知，不输出未经确认的达标结论。
- deviceCode 为空的环境历史先按站点呈现；只有实际可验证的标识才关联具体设备。设备名称或单设备目录不能补出历史归属。
- 烟感使用独立台账。水浸新列表依据当前目录子类识别混入的烟感；不能确认类别的记录说明未分类。保持端点来源与事件身份，不靠时间相近合并不同事件。
- 分页结果区分上游原始总量、已核实分类数量、已读取数量和是否完整；不足以证明完整分类数量时不返回一个看似精确的总数。翻页按固定窗口、稳定时间/记录身份去重；多台账游标须绑定身份、筛选和原查询窗口。
- 电量首条闭环可以先展示真实原始历史，字段名称忠实表达 epf/epz/totalElectric。统计使用的方向、单位/倍率及边界规则在 E01 收口；本规格不把 epf 默认命名为“公司正向总用电”。
- 统计结果附字段、单位、倍率、边界采样时间/值与统计覆盖；负增量、清零/换表、同时间冲突不能取绝对值或补零。没有完整请求边界证据时标实际观测区间，不能伪称完整日耗电。默认不插值；允许近邻边界或估算须另明确口径。
- 当前无数据返回无数据；用户显式选择最近有数据日期才改范围。累计示数不作为日用电，瞬时 kW 不替代历史 kWh。汇总集合未明确时只展示逐表结果。
- 比较范围必须同口径，并说明各期有效覆盖；基期为零或样本不足不计算误导性增长率。初期报表为可查看、可追问的期间分析，不自动新增导出/邮件/定时报告。

### 公共查询契约（实现票开工时固定 JSON 细节）

| 业务入口 | 建议公开端点/工具 | 必要输入与返回约束 |
|---|---|---|
| 分类安全历史 | GET `/api/agent/safety-events`、既有 query_alerts 的范围扩展 | source=company、类别、明确时间窗口和分页；返回稳定事件身份、记录时间、分类、平台标记与覆盖。不要求上游具备未声明的日期过滤 |
| 单条安全详情 | 既有 safety-events 单条 GET 和消息 reference | ledger 支持 gas/flooding/smoke；eventId/deviceId 均核验，保留旧引用 |
| 环境历史 | GET `/api/agent/environment-history`、query_environment_history | source=company、from/to 和分页；返回站点/可验证设备归属、指标序列、采样覆盖和已核实单位 |
| 电量原始历史 | GET `/api/agent/energy-history`、query_energy_history | source=company、已核验计量点、from/to 和分页；返回原始字段、采样身份/时间，不隐式生成区间统计 |
| 单表/集合统计 | GET `/api/agent/energy-summary`、同业务统计工具 | 指定集合/窗口与已冻口径；返回指标、边界证据、覆盖、异常；与仪表盘共用计算 |
| 实时/回放取流 | 扩展现有 video-stream GET 服务 | 两端明确 source、设备、mode；playback 必须携 beginTime/endTime，按提供资料验证最多三天。短期地址只在播放会话中返回，不落会话/任务/通知 |

以上是本轮准备的契约建议，尚非已实现端点。列表首屏建议 20 条、服务端 limit 最大 100；这是实现默认值，不是新的任务时序规则。统计读取预算在对应票据按真实采样规模定，预算耗尽必须报告覆盖不完整，不能静默截断或把全量读取放到首屏。任何已选窗口变化都重新绑定查询，客户端不能复用前一游标。

### 视频与等待策略

- 观看能力与控制能力分开；Company 观察卡可观看，不因来源而强制关闭全部视频动作。当前在线未知或离线状态与回放可用性分别表达。
- 先进入播放器再取流，标题在加载中已显示设备与实时/回放模式，返回始终可用。首播与重试统一 source、租户、摄像头和录像窗口；两个来源不能在重连时缺省混用。
- SDK 只开放真实验证过的控件；取得 WSS 地址不代表回放调用正确、录像存在或可拖动/倍速。暂无录像、过期、频控、认证失败和解码失败分别如实显示，不改写设备在线态。
- H5 保留既有视觉方向与官方播放 SDK；冻结身份注入/桥接契约，清除含凭据/短期流地址的调试日志，核验 HTTPS、跨域和微信业务域名，不扩大为一般 WebView 重构。
- 换流与退出释放会话；避免自动重复取流造成上游孤儿会话。开发验证与客户域真机验收分别记录，部署缺口只阻塞视频的对应关闭条件。
- 按下即时反馈，内容外壳先出现、请求可取消/丢弃旧响应，分区互不等待。约 100ms 反馈、约 300ms 已有页面详情可操作为测量目标，不是未经测量的达标宣称。不得用无限核验或“已保留数据”掩盖未完成查询。

## Testing Decisions

- 用户已要求只测试外部可观察行为；复用现有 buildApp + inject 公开 HTTP、公开消息 NDJSON 和会话恢复，不增加内部 adapter/SQL/函数调用次数断言。UI 点击、返回、滚动、首帧和等待不靠 Vue 源码正则证明。
- 各票先用生产协议夹具驱动一个窄红测试，再完成该业务路径。优先复用安全详情引用、Company 仪表盘分区、观察事件恢复、Company/Office 来源隔离的已有场景；测试 fixture 使用独立身份/库，不访问真实设备。
- 历史列表验证窗口/分页、重复时间/ID、空数据、范围外设备、身份失败、部分上游故障；统计重点验证实际边界、单位/倍率、负增量/缺失、重叠集合与零基期。
- 用户实际体验验收需客户微信包：点击→页面可操作与数据返回分别计时；切日期/筛选→返回→恢复；引用→发送→再进入；播放器首帧→换流→释放→再打开。默认公开行为回归之外不新建 QA 平台。
- 每票完成必要的 Runtime 类型/构建、mp Agent 回归、微信编译和差异检查；稳定切片按需两轴审查，不把重复测试次数当交付。真实凭据只从既有安全存放点读取，不重新 SSO 登录，不并起第二个 Runtime。
- 验收记录分“源码/夹具通过、真实接口通过、实际微信操作通过、真机通过”，未通过项留明原因。票据最终关闭必须满足本票所有适用证据，外部缺口保留为待验。

## Out of Scope

新增消防处置写入、设备告警通知中心/外推、无人值守安全联动、PTZ/对讲/录制、人脸识别、跨来源目录共享、Office 环境/能耗授权扩大、通用数据仓库/报表平台、全局导航重写。既有 Task/Plan/收件箱业务不重做；自动定时报表与导出在用户明确需要后复用现有业务另成切片。
