# Agent 目标优化：三条业务闭环

日期：2026-10-09。Status: ready-for-human。关联[规格](2026-10-09-agent-target-improvement-spec.md)。

方向已认可，以下拆分与公开 HTTP 验收入口待一次合并确认；确认后分别发布到本地 tracker，才标 ready-for-agent。三票是完整业务路径，按顺序每次只实现一票。每票中的必要回归、模型检查、前端走查、审查和交接随业务交付，不另立设施票。

## 01：页外照明目标完成多轮委托与报告追问

**What to build:** 在大目录中找到原窗口外的实际照明，让用户从自然生成的候选中选“后者”，只开灯带、格栅灯不动、修改时刻；形成可确认的具体 Task，到期执行后追问同一报告。

**Blocked by:** None。从最新主线增量实施，不先合并旧隔离分支。

**Status:** ready-for-human。

- [ ] 目标在原50台窗口之后，名称与目录顺序变化仍可取得必要明细；不能以临时夹具固定ID替代查询。
- [ ] 真正的两个候选可承接“后者”；没有两个明确对象则澄清，不能猜选。
- [ ] 提案只包含选定区域的灯带和用户新时刻；格栅灯无动作，不添加区间/重复规则。
- [ ] 硬范围与建议分开；不因无法共同满足的词静默扩大目标。
- [ ] 确认前、到期前零控制；显式确认后夹具执行正确目标，重复扫描不重复下发。
- [ ] 恢复或新会话引用同一Task可解释报告；受理但无权威回读不称为物理完成，时间使用明确时区，无新操作。
- [ ] 双来源隔离、撤权拒绝和已有计量/录像/安全事件能力保持；真实模型自然首轮走通，固定应答的HTTP回归与模型证据分别记录。
- [ ] 必要提示词/守卫修改由本票失败证据支持；完成检查、交接和语义提交。

预期新增或改写业务代码约100–250行，主要是命中可读、引用补读及接线；测试和文档另计。这是范围预警，不是硬性行数目标；若需要新的持久化模型或广泛循环重构，先缩小切片/复核，不把它藏进本票。

## 02：整层照明排除指定集合后形成完整即时草案

**What to build:** 用户说“26楼所有灯，除了会议室，都关掉”，Agent 表达完整已发现集合和明确排除，Runtime 展开成可查看全部的具体草案；用户确认后执行并看到实际收据。

**Blocked by:** 01。复用其必要取证与引用补读路径。

**Status:** ready-for-human。

- [ ] 超过50台的已知匹配集合可以完整参与目标表达；模型明细窗口不导致遗漏，也不要求模型抄写所有设备。
- [ ] 使用现有候选集证据表达包含与排除，区分匹配子集和空间全部成员；不同来源不能组合。
- [ ] 排除项未识别时不生成“已排除”的全范围草案；只有部分目录成功不能声称完整。
- [ ] Runtime展开后核验每台能力，草案及查看全部展示实际对象；明确排除与即时已满足、不勾选项语义保持可区分。
- [ ] 确认时不静默增加新增设备；撤权按既有机制处理，不借旧引用控制。
- [ ] 确认前零下发；确认后的实际调用集合等于批准的待操作集合，会议室零下发；重复确认不重复控制。
- [ ] 复用既有卡片与执行器；超资源边界明确失败，不能截断后称全部完成；通过公开HTTP、模型和原生卡片验收。
- [ ] 完成交接与语义提交，不混入目录去重、空调集合参数或门禁改造。

预期新增或改写业务代码约200–400行，集中在完整成员保留、集合目标展开和提案接线。前端仅补必要范围说明，预计0–50行；不新建集合引擎或第二份草案状态。

## 03：同一集合用于定时与周期照明安排

**What to build:** 用户安排“工作日18点关26楼办公区灯，走廊留着”，在改时间后确认；到期产生实际Task并保存报告，未来发生使用同一批准模板，能继续从任务/周期引用追问。

**Blocked by:** 02。复用已验证的完整集合与排除展开，不再单独实现目标解释。

**Status:** ready-for-human。

- [ ] 一次性和周期提案沿现有任务入口保存完整具体设备与命令；当前已满足设备仍在未来目标中。
- [ ] 修改尚未确认的时间不改变包含/排除；已有计划的修改、跳过、停用继续采用原权威对象及确认规则。
- [ ] 工作日沿周一至周五口径；不给用户额外添加重复规则、区间或终点动作。
- [ ] 到期按已确认快照执行，重复扫描不重复落账或下发；后来的新设备不进入旧周期模板。
- [ ] 授权变化依现有执行语义处理；Office/Company任务归属不混用。
- [ ] 任务/计划详情、未来投影及同一报告查询使用一致对象；只读追问不新建控制。
- [ ] 完成公开HTTP、真实模型、既有任务UI回归与交接提交；现场控制另行具体授权验收。

预期新增或改写业务代码约100–250行，复用第二票展开与既有Task/Plan创建路径。若发现必须重写scanner或Occurrence生命周期，登记新问题，不扩大本票。

## 收口与继续条件

首票开始前固定版本、失败样例、预期目标集合与模型预算。之后每票展示原问题的改善和原正常委托的保持，分别标明确定性回归、真实模型、微信/真机及真实设备证据。未发生的验收不填写通过。

五次无工具run.failed仍是单独待诊断问题。若复现为当前闭环阻断，只做本票必要诊断；若无关，不把它变成全局整改。报告问题只修本轮同一Task追问的明确误述，不顺带重写所有回复。
