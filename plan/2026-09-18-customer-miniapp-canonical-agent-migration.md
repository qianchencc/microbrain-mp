状态：本地客户开发闭环与唯一 `3200` 真实网关验收已完成（票 01-04，2026-09-23）；阶段 3 剩余清单与体验版 HTTPS 验收待执行  
前置调查：
[`客户小程序登录态与 Agent 接入调查`](../docs/research/2026-09-18-customer-miniapp-login-and-agent-integration.md)

> **2026-09-23 架构修订**：Iotfake 与 `3100`/`3201` 端口已永久退役。本机只保留单一 `3200` Runtime 实例，直连真实客户网关（`IOT_BASE_URL=https://ncim.577119.com`），不存在模拟数据源和隐式回落。下文中 2026-09-18 的 3200/3201 双端口验收记录保留为历史事实，其架构划分已被本决策取代。

## 决策

`apps/agent-miniapp` 不再作为生产交付入口。客户小程序源码成为 Agent 唯一的生产开发主线；独立 miniapp 保留为研发回归、视觉验收和脱离客户首页的演示壳，暂不删除，也不再在其中发展新的业务能力。

这不是简单替换 AppID 或复制一个页面。迁移已经按客户会话桥接、页面能力适配和客户 AppID 开发版验收推进；本地开发闭环已完成，唯一 `3200` 真实网关设备闭环和体验版 HTTPS 仍需单独验收。

## 第一条业务闭环

第一条闭环固定为：

```text
真实客户用户登录
  -> 等待客户会话和园区上下文就绪
  -> 进入客户小程序中的 Agent 页面
  -> 查询当前用户有权限的照明/空调/门禁设备
  -> 生成操作草案
  -> 用户明确确认
  -> Runtime 执行、回读并展示结果
```

首条闭环不新增设备类型、记忆、日程、自动化或告警。它的业务价值是证明 Agent 已经从独立测试壳变成客户用户可使用的受权设备入口。

## 阶段与范围

## Agent 地址决策

Runtime 继续作为独立后端服务运行，不放入小程序包，也不要求跟客户小程序部署在同一台机器。小程序只调用 Agent API；Runtime 再通过物联适配器访问客户物联网关。

地址按环境分层：

| 环境 | Agent 地址 | 用途 | 结论 |
|---|---|---|---|
| `develop`，开发者工具模拟器 | `http://127.0.0.1:3200/api` | 本机唯一 Runtime 实例，直连真实客户网关 | 可以继续本地运行 |
| `develop`，真机预览 | `http://<开发机局域网地址>:3200/api` | 手机访问开发机；Runtime 必须监听 `0.0.0.0` 且同网段 | 可以本地运行，但不能使用 `127.0.0.1` |
| `trial` | 客户可访问的 HTTPS 验收地址，优先走客户网关 `/micro-api/api/ai` | 真实客户登录、受控测试设备、体验版验收 | 不能放在本机 |
| `release` | 客户正式 HTTPS 网关 `/micro-api/api/ai` 或客户批准的独立生产域名 | 正式用户和正式授权设备 | 不能放在本机 |

客户配置已改为精确判断 `envVersion === 'develop'`：`develop` 使用本地 Runtime，`trial/release` 指向客户网关。体验版仍需验证 HTTPS、合法域名和 NDJSON 代理，不能仅凭配置宣称可用。

本地只保留单一 `3200` Runtime 实例，直连真实客户网关（`npm run start:local-real` 启动，缺配置 fail closed）；Iotfake 与 `3100`/`3201` 已于 2026-09-23 退役，不应再有进程监听。`3200` 既承担日常页面/对话开发，也承担受控的真实只读和经授权的低风险设备验收；它不是客户体验版或正式版的长期服务地址。

### 阶段 0：冻结迁移边界（已完成）

- 把客户小程序视为唯一生产源码；独立项目只接受回归修复和迁移前必要的验证修复。
- 为独立项目当前可迁移版本建立可追溯基线；不能直接把工作区未提交差异整体复制到客户仓库。
- 列出需要迁移的页面、组件、纯逻辑模块、资源、构建脚本和测试；明确哪些是独立项目专属配置。
- 暂不迁移独立项目的 App.vue、manifest、固定开发身份、独立环境配置和与客户工程冲突的依赖。

验收：能够明确回答每个文件是“迁移、适配、保留在壳、还是不迁移”，且没有把客户登录替换成独立项目的固定 Token。

### 阶段 1：客户会话桥接（开发版已完成）

先在客户仓库完成最小会话边界，再接入完整页面：

- 精确区分 `develop`、`trial`、`release`，禁止用“非 release 即开发”决定身份。
- 建立统一的 `sessionReady`/等价入口，Agent API 不再直接从页面读取 Token 或园区对象。
- 复用客户现有登录态；记录 Token 过期信息或接入客户提供的刷新/换票接口。
- 首次登录时等待用户、菜单、园区上下文准备完成；园区切换时使 Agent 上下文失效并重新加载设备范围。
- 401、退出、切换用户和流式请求分别处理；确认动作在结果未知时禁止盲目重试。
- `trial` 必须使用真实客户测试身份和 HTTPS 验收网关，不能出现 `local-development`、`LOCAL` 或 `127.0.0.1`。

验收：干净安装、有效 Token 重启、过期恢复、无园区缓存、切换园区、退出后重新登录、切换用户等场景均不会串用户、串园区或重复执行动作。

### 阶段 2：迁移当前 Agent 页面能力（已完成）

在会话契约稳定后，将独立项目已验证的行为移植到客户 `pages/agent`：

- 对话流、历史恢复、流式 NDJSON、错误收口和停止生成；
- 设备候选、设备清单、照明/空调/门禁卡片；
- 草案选择、参数编辑、取消、确认、回读和自然收尾；
- 原生底部面板、拖拽关闭、重开复位、语音入口及其权限边界；
- 仅迁移可观察行为测试，不把独立项目的编译细节当作客户业务契约。

迁移方式是逐模块适配，不是目录覆盖：客户入口、路由、组件注册、资源路径、uni_modules、配置和 API 基础地址必须以客户工程为准。

验收：客户项目在本地开发环境可编译，客户页面完成现有三类设备闭环；独立项目仍能作为回归壳启动，但不再承载新业务开发。

### 阶段 3：客户 AppID 真实验收（本地 3200 部分已完成，体验版待执行）

由客户 AppID 的开发/体验成员账号完成：

1. 首次登录后直接进入 Agent，不出现第二次登录；
2. 使用当前用户和园区查询设备；
3. 完成一条低风险照明或空调操作；
4. 检查 Runtime 的用户、租户、设备授权和审计记录；
5. 验证断线、超时、Token 过期、权限撤销和重复点击；
6. 更换普通测试用户，确认设备范围、历史和草案不泄漏；
7. 在体验版中确认请求域名、流式响应和网关不会缓冲 NDJSON。

阶段 3 完成前，只能称为“客户仓库已接入开发版”，不能称为生产集成完成。

### 阶段 4：独立项目退役管理（已迁出本仓库）

- 2026-09-24：`apps/agent-miniapp` 经 `git subtree split` 迁出为同级独立仓库 `agent-miniapp`，保留全部提交历史；本仓库不再保留其源码，`test/agent-source-parity.test.mjs` 同步移除。
- 独立仓库保留回归、演示和故障复现职能（test AppID、无客户登录生命周期、69 项源码测试 + 16 项编译契约测试）。
- 客户主线稳定后，将独立仓库标记为 archived/reference，停止功能分叉；只有客户主线修复无法复现的问题时，才回补最小回归用例。

## 任务分配

### 当前主线：客户小程序接入

阶段 0 至阶段 2 及开发者工具只读验收已经完成。阶段 3 的本地 `3200` 部分已于 2026-09-23 完成（票 03）：真实只读查询、低风险照明动作（草案→确认→受理→回读）、重复 confirm 只回放不重复执行。剩余阶段 3 清单为断线/超时/Token 过期/权限撤销、更换普通测试用户、以及体验版 HTTPS/NDJSON 代理验收。新设备、自动化、记忆和告警不混入这条验收。

### Runtime/网关

并行确认客户 Token 或短时 Agent session 的验签方式、`Tenantcode` 来源、HTTPS 网关、NDJSON 转发、超时和审计 actor。Runtime 不应因为客户端迁移而复制客户用户体系。

### 设备扩展

继续独立调查客户下一批真实设备和接口支持材料，等客户身份闭环完成后再选择一个设备业务切片，不提前做通用设备平台。

### 下沉业务

日程、会议、记忆、自动化、告警和富交互活组件按各自切片推进，不混入迁移验收。2026-09-30 账户来源 `account/me.id` 已核验，用户纠正频繁 Token 过期前提；不再以刷新契约或跨 Token 实验阻断自动化。周期任务、结束通知与缓存的现行进度见[任务总表](2026-09-30-agent-task-register.md)。

## 暂不做的事情

- 不在 Agent 页面内重新执行 `wx.login` 并建立第二套账号体系；
- 不把微信 `openid`、`session_key` 或前端 OAuth secret 传给 Runtime；
- 不把 Token 哈希直接升级为长期记忆、日程或自动化 owner；
- 不为了“迁移完整”同步实现更多设备、自动化、会议联动、告警通知；
- 不直接删除独立 miniapp；
- 不用测试 AppID 或固定 `local-development` 身份宣称客户生产可用。

## 进入真实网关和体验版前仍需确认

- 客户 Agent 网关接受现有客户 Token，还是需要短时 Agent session；
- 用户与园区的实际隔离；Token 刷新契约不作为当前前置要求，实际鉴权失败仍按已有错误处理收口；
- `tenantCode`/园区切换的权威来源和生效时机；
- `trial`、`release` 的 Agent HTTPS 地址、合法请求域名和流式代理策略；
- 可操作的非生产设备、授权动作和测试窗口；
- 客户 AppID 的 `WechatSI` 插件授权和语音验收责任。
