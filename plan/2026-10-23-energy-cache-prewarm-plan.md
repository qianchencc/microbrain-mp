# 电表历史与最新数据同步方案（请求驱动）

日期：2026-10-23

## 0. 规则

- **不要求稳定同步身份**；
- **历史数据**：每天半夜刷新一次；**最新数据**：每小时一次；
- **全部后端完成**：小程序/智能体不调用同步接口；
- **同步不阻塞前台**：报告只读本地数据，请求不等待同步；
- **租户级共享**：不按用户、不按 token 存历史数据。

## 1. 核心思路

没有长期服务账号，就不能保证“无人使用时 03:00 整点也能跑”。所以改成：

> 用**最近一次正常请求**携带的租户身份，在后台补同步；按租户去重、按租户共享。

```text
任意已鉴权请求（仪表盘/智能体/普通页面）
        │  只作为触发器和临时身份，不持久化
        ▼
ensureMeterSync(tenant, identity)   // fire-and-forget
        │
        ├── 历史到期（每天 03:00 后首次）→ 后台刷全部闭月
        └── 最新到期（每小时首次）      → 后台增量拉当前日
                    │
                    ▼
         本地 meter_history_samples（租户级）
                    │
                    ▼
         报告只读本地 → 按当前用户授权目录过滤
```

请求本身**不等待**同步；它读当前本地数据，后台任务完成后下一次请求看到新数据。

## 2. 触发与调度

### 2.1 身份来源

- 不保存长期 token；
- Runtime 在内存中保留最近一次成功鉴权请求的 `authorization + tenantCode`，仅用于后台同步，不落库、不写日志；
- 收到 401/403 立即丢弃该内存身份，等下一次请求；
- 同一租户只有一个内存身份，后到的请求覆盖先前的；
- 不用用户 token 做任何写操作或越权读，只做租户级只读采样同步。

### 2.2 到期规则

- 历史：`last_history_success_at` 不在当天 03:00 之后，即视为到期；
- 最新：`last_latest_success_at` 超过 1 小时即视为到期；
- 每个请求进入后端时检查一次到期状态：
  - 未到期：什么都不做；
  - 到期且无任务在跑：启动后台任务；
  - 到期但已有任务在跑：直接复用，不重复启动。

### 2.3 03:00 / 每小时的含义

- 有用户在 03:00 后使用系统：第一个请求触发历史刷新；
- 整夜无人使用：不会在 03:00 准点执行，而是在下一个请求到达时补跑；
- 最新数据同理：整点前后无请求，就在下一次请求时补拉。

这是没有稳定身份时唯一能保证“不阻塞、不要求用户操作”的模型。若必须严格 03:00/每整点、无人也执行，只能提供长期服务账号；两者不可兼得。

## 3. 数据模型

```sql
CREATE TABLE meter_history_samples (
  tenant      TEXT NOT NULL,
  equipment_id TEXT NOT NULL,
  read_time   TEXT NOT NULL,
  epf         REAL,
  total_power_factor REAL,
  source      TEXT NOT NULL DEFAULT 'electricData',
  ingested_at INTEGER NOT NULL,
  PRIMARY KEY (tenant, equipment_id, read_time, source)
);
CREATE INDEX meter_history_samples_tenant_time
  ON meter_history_samples (tenant, read_time);

CREATE TABLE meter_sync_state (
  tenant          TEXT NOT NULL,
  kind            TEXT NOT NULL,       -- history | latest
  last_success_at INTEGER,
  last_sample_time TEXT,
  cursor_page     INTEGER,
  error           TEXT,
  updated_at      INTEGER NOT NULL,
  PRIMARY KEY (tenant, kind)
);
```

- 租户级共享，不按用户/token；
- upsert 幂等；
- 独立连接、WAL、批量提交，前台读不等待写锁。

## 4. 同步任务

### 4.1 历史任务

- 触发：当天 03:00 后第一个请求，或上一次成功后已跨天；
- 范围：**全部可访问历史**，一直读到上游 `last=true` 或安全上限 2000 页；
  当前 `totalElements=236,377`，500 行/页，约 473 页；不再有 60 页截断；
- 方式：倒序翻页，500 行/页，30 秒/页；每批 4 页并发，避免把前台小请求挤超时；
- 预算：单次后台任务 30 分钟；超时或失败时保留已成功页，`cursor_page` 记录首个失败页，下一次从该页续跑；
- 写入：批量 upsert；
- 失败：保留已写入样本，记录错误；下一次请求继续。

### 4.2 最新任务

- 触发：上一次成功后超过 1 小时；
- 范围：当前日/未闭合月；
- 方式：从第 0 页倒序读，遇到 `read_time <= 本地最新样本` 停止；
- 通常 0–2 页。

### 4.3 首次启动

- 本地表为空时，第一个请求触发全量回填；
- 回填期间报告返回本地已有月份，并标注未覆盖月份；
- 不返回 202、不轮询、不阻塞。

### 4.4 并发与失败

- 每租户同时只允许一个 history、一个 latest；
- 任务在后台独立执行，请求返回不等待；
- 同步在请求的身份核验通过后**延迟 10 秒**启动，避免和该请求的 5 秒身份/目录读抢上游；
- 历史分页每批 4 页并发；单页失败重试一次，仍失败则保留其余页并记录 `cursor_page`；
- 401/403：丢弃内存身份，标记到期，下一次请求重试；
- 网络/超时：保留已写样本，记录错误，不删除旧数据。

## 5. 报告读取

- 只查 `meter_history_samples`，不再访问上游；
- 加载当前授权目录，按授权电表过滤；
- 无本地数据的月份：返回覆盖说明（缺少月份、最新本地样本时间），不返回 preparing；
- 报告快照可选，键为 `tenant + 权限范围哈希 + 查询`，不含 token；历史闭月不设短 TTL；
- 同步写入期间，前台读 WAL 快照，不等待。

## 6. 前端

- 不调用任何同步/预热接口；
- 正常请求即可触发后端到期检查；
- 移除 `energyDaily`/电表报告的前台 `readWhenReady` 轮询；
- 智能体 `summarize_energy` 直接读本地报告；缺月份时按普通覆盖说明展示。

## 7. 权限与数据完整性

- 内存身份来自某个用户，其可见范围可能小于全租户；
- 如果上游 `electricData` 是租户统一流（2026-10-14 实测），同步数据完整；
- 如果上游按用户权限过滤，则同步结果只覆盖该用户可见表：
  - 记录本次同步覆盖的设备集合；
  - 其他用户请求时，本地缺失的表显示覆盖缺口；
  - 后续不同用户请求可逐步补齐；
  - 不把缺失数据当成“零用电”。
- 报告始终只输出当前请求授权目录内的表，不泄露其他用户数据。

## 8. 迁移步骤

1. 建 `meter_history_samples`、`meter_sync_state`；
2. 在鉴权入口挂 `ensureMeterSync`（到期检查 + fire-and-forget）；
3. 第一个请求触发全量回填；
4. 报告读路径切到本地样本；
5. 删除报告路径的上游分页、202 preparing、按 token 快照；
6. 小程序移除能耗前台轮询；
7. 观测：任务页数/行数/耗时/错误、本地覆盖月份、最新样本时间。

## 9. 验收

- 正常请求不会等待同步；仪表盘/智能体响应时间不受同步影响；
- 4–5 月报告从本地返回（实测 5.1s；后续可继续优化目录/聚合，目标 <2 秒）；
- 同一租户不同用户/不同 token 共享同一份历史样本；
- 报告路径 0 次上游 `electricData` 请求；
- 03:00 后首个请求触发历史刷新；每小时首个请求触发最新增量；
- 同步中断可重试、幂等，旧数据不丢；
- 小程序无同步/预热请求，无 120 秒轮询。

## 11. 明确的取舍

- **不保证无人使用时准点执行**：03:00/整点仅在系统被使用时补跑；要严格准点必须长期服务账号；
- **身份是借用的**：用最近一次请求的内存 token，不落库、不长期保存；
- **权限范围可能不完整**：若上游流按用户过滤，需要逐步补齐并在报告里标注覆盖缺口。
