# 09 — 录像片段到人数分析报告

Date: 2026-10-09
Status: needs-info
Blocked by: 04
External/decision gates: E04：后端可提取可解码证明、同时在场人数/去重人次等计数口径与准确率，未满足前仅准备技术验证。

规格：[历史观察与双 Agent 视频](../2026-10-09-history-observation-spec.md)。状态是发布时快照，实施进展在本地 tracker 同编号票维护。

## What to build

用户为已授权摄像头和录像窗口委托人数分析，最终取得可追问的报告，能看到画面覆盖、计数定义、误差与失败原因。

## Frozen scope

我方后端分析，不再索取海康人数接口。先证明一小段真实录像的输入链，再选最小模型/算法；不做人员身份、人脸识别或跨镜头追踪。

## Expected code size

实现前先做隔离提取/解码验证；生产代码量待 E04 确认后估算，当前不预建算法/队列/任务平台。 估算只含新增/主要修改的生产逻辑，不含固定倍数的测试或文档，也不是报价。开工先核对现有实现；明显超出应说明原因并缩小本票，禁止顺手扩大为平台。

## Acceptance criteria

- [ ] 在隔离环境证明合法取流与可用帧，样例不打印凭据，不用浏览器可播冒充后端可解码。
- [ ] 冻结计数对象、采样覆盖、时间窗、人工标注对照和接受标准；无法定义时票保持 needs-info。
- [ ] 报告关联原摄像头/source/窗口，区分未获取、解码失败、低置信度和有证据的零人。
- [ ] 复用适用的既有 Task/报告/个人收件箱，不为分析另建第二套运行记录；接入前说明新增对象确有必要。
- [ ] 独立人工标注录像与分析报告比较，实际微信查看/追问/恢复完成，不能仅凭模型文字关闭。
- [ ] 局部门槛收口后才进入生产实现；必要测试/类型/构建、微信编译和本票实际操作证据通过；真实接口、模拟器、真机边界分别记录。
- [ ] 必要稳定切片审查、语义提交、plan 交接完成；外部验收未通过不得标整票完成。

## Testing decisions

冻结可解码输入后从公开分析请求/报告查询验证；精度用独立标注录像，不用实现生成的结果充当真值。

## Out of scope

不新增本票之外的控制、通知、权限或通用平台。未决项只阻塞这里列出的业务行为，不反向阻塞已可开始的历史查询。
